Já sabes programar e [medir o tempo de um programa](/cadeiras/ac/desempenho/); a pergunta desta página é: se cada acesso à memória pode esperar dezenas de ciclos pela resposta, como servir a maioria dos acessos perto do processador?

O processador pede um byte e a memória principal demora dezenas de ciclos a responder. Registos e SRAM, memória RAM estática, são rápidos, mas caros por bit. DRAM, memória RAM dinâmica, permite uma memória principal maior. SRAM e DRAM são voláteis, ou seja, perdem o conteúdo sem alimentação. O armazenamento conserva-o. Uma hierarquia tenta servir a maioria dos acessos perto do processador, transferindo **blocos**, também chamados linhas, entre níveis.

## Localidade e organização

**Localidade temporal:** voltar a usar um dado recente. **Localidade espacial:** usar endereços próximos. Um ciclo percorre um vetor contíguo e pode reutilizar a linha que contém vários elementos.

Uma cache guarda dados, etiqueta e bit de validade. A etiqueta identifica o bloco da memória; validade distingue uma entrada utilizável de dados antigos sem significado. Uma cache write-back guarda também um bit dirty, explicado em [Políticas de cache](/cadeiras/ac/politicas-cache/).

| Organização                           | Onde pode entrar um bloco?   | Escolha da vítima                       |
| ------------------------------------- | ---------------------------- | --------------------------------------- |
| Mapeamento direto                     | Uma única entrada            | Determinada pelo índice                 |
| Associativa por conjuntos de $A$ vias | Qualquer via do seu conjunto | Necessária quando o conjunto está cheio |
| Totalmente associativa                | Qualquer entrada             | Necessária quando a cache está cheia    |

Um acesso acerta, ou é um **hit**, quando encontra uma entrada válida com a etiqueta pedida; caso contrário há uma **falta**, ou miss. Numa cache de $A$ vias comparam-se as $A$ etiquetas do conjunto selecionado, não as de todos os conjuntos.

O número de conjuntos é $S=C/(B A)$, com capacidade de **dados** $C$, bytes por bloco $B$ e associatividade $A$. Distingue conjunto, via e bloco da memória.

## Decompor um endereço

Constrói primeiro por divisão inteira e só depois lê os bits. Para linha de 64 bytes e 32 conjuntos, com endereço $E$:

$$\text{bloco} = E // 64, \quad \text{offset} = E \bmod 64, \quad \text{índice} = \text{bloco} \bmod 32, \quad \text{etiqueta} = \text{bloco} // 32.$$

Para `0x12345678`, bloco `0x48D159`, offset 56, índice 25 e etiqueta `0x2468A`. O início da linha é `0x12345640`. Confere sempre que índice e offset cabem nos bits previstos antes de comparar etiquetas.

Exemplo fechado com organização declarada. Matriz `8x8` de palavras em ordem por linhas a partir do endereço de palavra 0, logo 64 palavras. Cache de dados diretamente mapeada com 2 linhas de 16 palavras (128 bytes no total), inicialmente vazia; palavra `w` usa a linha `(w // 16) \bmod 2`.

Por linhas, cada falta traz 16 palavras seguidas: faltas nos blocos 0, 1, 2 e 3, total 4 faltas para as 64 leituras. Por colunas, a primeira coluna lê as palavras 0, 8, 16, 24, 32, 40, 48 e 56, com 4 faltas, mas cada coluna seguinte volta a falhar porque os blocos foram expulsos: 4 faltas por coluna vezes 8 colunas, total 32 faltas. A ordem dos ciclos muda a taxa de faltas mesmo com o mesmo número de leituras.

Para endereços de $n$ bits, com $B=2^b$ bytes por bloco e $S=2^s$ conjuntos:

$$\underbrace{\text{etiqueta}}_{n-s-b}\quad\underbrace{\text{índice}}_s\quad\underbrace{\text{deslocamento}}_b.$$

As contas seguintes usam endereços de **byte**. Se um exercício fornece endereços de palavras de 4 B, converte primeiro para bytes, multiplicando por 4, ou expressa o tamanho da linha em palavras. Não mistures as duas unidades.

O deslocamento escolhe o byte **dentro da linha**, não uma linha. Para palavras de 4 bytes, os dois bits baixos escolhem um byte dentro da palavra; os restantes bits de deslocamento escolhem a palavra.

Uma cache direta de 2 KiB, com linhas de 64 B e endereços de 32 bits, tem 32 linhas, portanto 5 bits de índice, 6 de deslocamento e 21 de etiqueta.

## Seguir uma sequência de leituras

Modelo: cache direta, 4 linhas de 16 B, inicialmente inválida. Lê os endereços `0,4,64,0,16,20`:

| Acesso | Bloco da memória | Índice | Etiqueta | Resultado e alteração                     |
| ------ | ---------------- | ------ | -------- | ----------------------------------------- |
| 0      | 0                | 0      | 0        | Falta; carregar linha 0, etiqueta 0       |
| 4      | 0                | 0      | 0        | Acerto; mesma linha                       |
| 64     | 4                | 0      | 1        | Falta; substituir linha 0 pela etiqueta 1 |
| 0      | 0                | 0      | 0        | Falta; repor etiqueta 0 na linha 0        |
| 16     | 1                | 1      | 0        | Falta; carregar linha 1                   |
| 20     | 1                | 1      | 0        | Acerto; mesma linha                       |

São 4 leituras de blocos na memória principal e 2 acertos. Alterar só o deslocamento não provoca substituição.

Em uma cache de 2 vias com a mesma capacidade, há 2 conjuntos. Os blocos 0 e 4 continuam no mesmo conjunto, mas cabem simultaneamente, por isso a leitura posterior de 0 pode acertar. **Maior associatividade permite evitar conflitos**, mas não elimina faltas por capacidade nem garante melhor tempo de acesso.

Aumentar a linha também não garante melhoria. Com capacidade fixa, linhas maiores aproveitam vizinhos, mas deixam menos linhas disponíveis e transferem mais bytes em cada falta. Dados sem localidade espacial podem expulsar dados úteis sem compensar esse custo.

## Substituição e tipos de falta

Segue o estado completo do conjunto. Com 2 vias e sequência de blocos A, B, A, C: após A e B o conjunto fica `[A, B]`. O segundo A acerta e, em LRU, passa a `[B, A]` do mais antigo ao mais recente. O C substitui B. Em FIFO, o segundo A não altera a ordem e C substitui A. Escreve a ordem em cada passo, porque a política decide a vítima.

LRU substitui o bloco usado há mais tempo. FIFO substitui o carregado há mais tempo; um acerto altera LRU, mas não a ordem de chegada FIFO. Usa primeiro uma via inválida. O estado da política faz parte do traço.

Uma falta é compulsória na primeira referência a um bloco. É de capacidade se ocorreria mesmo em uma cache totalmente associativa de igual capacidade sob a política de referência. Uma falta adicional causada pelo mapeamento restrito é de conflito. Esta classificação exige comparar modelos, não adivinhar a partir de um único endereço.

A escolha da vítima em uma falta compulsória pode mudar **faltas futuras**. Em caches partilhadas, invalidações acrescentam faltas por coerência.

## Contar os bits físicos

Para 8 linhas diretas de 16 B e endereços 24 bits: $b=4,s=3,t=17$. Sem dirty ou outros metadados:

$$8\times(16\times8+17+1)=1168\ \text{bits}=146\ \text{bytes}.$$

A capacidade anunciada de dados é só 128 B. Para write-back, acrescenta 8 bits dirty; para uma política de substituição, considera também o seu estado, se pedido.

## Endereços de uma matriz

Em C, uma matriz contígua em ordem por linhas `A[R][K]` tem endereço `base + (iK+j)×tamanho`. Variar `j` percorre dados adjacentes; variar `i` salta uma linha inteira. Trocar a ordem dos ciclos pode melhorar localidade, desde que conserve dependências e significado. Processar pequenos blocos de uma matriz permite reutilizar dados antes de os expulsar, mas o bloco deve caber no nível relevante da cache.
