Já sabes acelerar instruções umas a seguir às outras com [pipeline e ILP](/cadeiras/ac/superescalar/); a pergunta desta página é: como executar a mesma operação sobre vários dados pequenos com uma única instrução de 32 bits?

Somar quatro bytes com quatro instruções desperdiça buscas e descodificações. Uma instrução SIMD, ou seja, uma instrução única aplicada a múltiplos dados, aplica a mesma operação a várias parcelas de dados. Neste modelo **empacotado de 32 bits**, as parcelas ocupam registos inteiros normais: quatro bytes ou duas meias palavras, ou seja, grupos de 16 bits. As instruções seguintes acrescentam operações a RV32; não usam o banco vetorial `v0…v31`.

## Vias e interpretação

`r.B[0]` é o byte baixo, bits 7 a 0; `r.B[3]` é o alto. `r.H[0]` é a meia palavra baixa, bits 15 a 0. A numeração das vias não depende da ordem em que escreves os dígitos hexadecimais.

Flynn distingue SISD, um fluxo de instruções/dados; SIMD, um fluxo de instruções para vários dados; MISD, vários fluxos de instruções sobre um de dados; MIMD, vários fluxos de ambos. Vários núcleos independentes são MIMD; cada núcleo pode também executar SIMD.

## Soma, subtração e overflow

`ADD8` soma separadamente quatro pares de bytes; `ADD16`, dois pares de 16 bits. `SUB8/SUB16` fazem a diferença. Cada via mantém os seus bits baixos, **sem transportar carry para a via vizinha**.

Com vias baixas `[250,2,3,4] + [10,20,30,40]`, ADD8 produz `[4,22,33,44]`. Uma soma escalar dos registos inteiros propagaria o carry do 250+10, dando 23 na segunda via.

Sem sinal, 4 é o resultado modular 260 mod 256. Com sinal, a mesma operação usa padrões em complemento para dois; ADD8 não satura no máximo 127. Saturação e descarte de bits são comportamentos diferentes.

## Operações diretas e cruzadas

| Instrução | Via alta H1 | Via baixa H0 |
| --------- | ----------- | ------------ |
| STAS16    | `a.H1+b.H1` | `a.H0−b.H0`  |
| STSA16    | `a.H1−b.H1` | `a.H0+b.H0`  |
| CRAS16    | `a.H1+b.H0` | `a.H0−b.H1`  |
| CRSA16    | `a.H1−b.H0` | `a.H0+b.H1`  |

Os resultados são reduzidos a 16 bits por via. Escreve as duas equações antes de calcular um valor hexadecimal, porque trocar H0/H1 muda a operação.

## Comparações e deslocamentos

CMPEQ8/16 testa igualdade. SCMPLT/SCMPLE interpreta operandos com sinal; UCMPLT/UCMPLE, sem sinal. Uma comparação verdadeira produz **todos os bits 1 da via**, isto é 0xFF ou 0xFFFF; falsa produz zero.

O padrão byte 0xF0 representa −16 com sinal e 240 sem sinal. Compará-lo com 10 dá verdadeiro em SCMPLT8 e falso em UCMPLT8.

Deslocamentos lógicos introduzem zeros; aritméticos replicam o sinal **em cada via**. O número de posições usa 3 bits para vias de 8 bits e 4 para vias de 16 bits neste modelo. Não uses um shift escalar do registo inteiro para imitar um shift por via: misturaria bits entre parcelas.

## Multiplicação e pares de registos

SMUL16 multiplica com sinal H0×H0 e H1×H1. Cada produto ocupa 32 bits, por isso dois produtos exigem um par de registos. SMULX16 cruza H0×H1 e H1×H0. UMUL16/UMULX16 interpreta sem sinal. O par físico é um registo de índice par e o seguinte; por exemplo `t3/t4` são `x28/x29`. Na notação de par `d`, os destinos são `x[2d]` e `x[2d+1]`.

Para `a=[−2,3]`, `b=[4,5]`, os produtos diretos são −8 e 15; os cruzados, −10 e 12. O resultado de 32 bits baixo não contém dois produtos de 16 bits. Se pretendes reconstruir vias de 16 bits, extrai/empacota a parte pretendida de **cada** produto, verificando se cabe.

SMUL8 produz quatro produtos de 16 bits em dois registos. KMDA soma os produtos das duas meias palavras com sinal para formar um produto interno parcial de 32 bits. Se ambos os operandos forem `0x80008000`, a soma matemática seria 2³¹: KMDA satura em `0x7FFFFFFF`. Essa saturação difere do descarte modular de ADD16. Confirma os limites antes de usar o parcial como uma soma exata.

## Empacotar, trocar e estender

| Instrução | Resultado `(H1,H0)` |
| --------- | ------------------- |
| PKBB16    | `(a.H0,b.H0)`       |
| PKTT16    | `(a.H1,b.H1)`       |
| PKBT16    | `(a.H0,b.H1)`       |
| PKTB16    | `(a.H1,b.H0)`       |
| SWAP16    | `(a.H0,a.H1)`       |

SWAP8 troca bytes adjacentes em cada meia palavra. SUNPKD estende bytes escolhidos com sinal para meias palavras; ZUNPKD preenche com zeros. O sufixo da variante identifica os bytes selecionados. Por exemplo, `SUNPKD820` coloca B2 em H1 e B0 em H0, estendendo cada sinal. Para `0x12FE34F0`, dá `0xFFFEFFF0`; `ZUNPKD820` dá `0x00FE00F0`. Não é um shift do registo inteiro, porque cada byte passa a ter 16 bits.
