Imagina uma pauta com as notas de uma turma e a tarefa de descobrir a nota mais alta. Percorres a lista do início ao fim, guardas a maior nota vista até agora e, no fim, anuncias esse valor. Essa sequência de passos que transforma uma entrada, a pauta, numa saída, a nota mais alta, é um **algoritmo**, ou seja, uma receita precisa para chegar a uma resposta.

Um algoritmo precisa de duas justificações: **calcula o resultado pedido** e **usa tempo e memória dentro dos limites disponíveis**. Um programa, ou seja, o algoritmo já escrito para o computador executar, que seja rápido mas falhe com notas repetidas continua errado. Um programa correto que faça mil milhões de operações pode não terminar dentro do limite. Se a sintaxe de vetores ou referências ainda te causa dúvidas, recorda os [fundamentos de C++](/cadeiras/aed/fundamentos-cpp/).

## Contrato e invariante

O **contrato** separa a pré-condição, que o chamador garante, da pós-condição, que o algoritmo garante. Para procurar o máximo, o vetor tem pelo menos um elemento, a resposta é um valor presente no vetor e nenhum elemento é maior. Se também pedires a posição, tens de decidir o que acontece num empate.

Considera este pseudocódigo, que devolve a primeira posição do máximo num vetor não vazio:

```text
melhor = 0
para i = 1, ..., n-1:
    se v[i] > v[melhor]: melhor = i
devolver melhor
```

À entrada de cada iteração, o **invariante** é: `melhor` é a primeira posição do máximo de `v[0..i)`. A notação `[0,i)` inclui 0 e exclui `i`.

1. **Inicialização:** antes da primeira iteração, `i=1`. O prefixo só contém `v[0]`, e `melhor=0` satisfaz a propriedade.
2. **Manutenção:** se `v[i]` for maior, a posição `i` é o novo máximo. Se for menor ou igual, manter a posição antiga conserva o máximo e o primeiro empate. Depois de aumentar `i`, a propriedade vale para o prefixo seguinte.
3. **Conclusão:** ao sair, `i=n`. O prefixo é o vetor inteiro, logo a propriedade implica a pós-condição.
4. **Terminação:** a quantidade inteira não negativa `n-i` diminui em cada passo. O ciclo não pode continuar indefinidamente.

As três primeiras etapas dão **correção parcial**: se terminar, o resultado é correto. Com a terminação, tens **correção total**. Uma propriedade como «o máximo ainda existe» é demasiado fraca para justificar a posição devolvida. E usar `>=` conserva o máximo, mas passa a escolher a última ocorrência.

## Contar operações

Escolhe uma operação representativa, como comparações de chaves, e conta-a em função do tamanho `n`. O máximo anterior faz exatamente `n-1` comparações. Não precisa de ordenar, porque isso acrescentaria trabalho sem melhorar uma única consulta.

| Fragmento de ciclo                       | Número de execuções do corpo         | Ordem apertada   |
| ---------------------------------------- | ------------------------------------ | ---------------- |
| `i=0..n-1`                               | $n$                                  | $\Theta(n)$      |
| dois ciclos independentes de tamanho `n` | $n^2$                                | $\Theta(n^2)$    |
| `i=1..n`, `j=1..i`                       | $n(n+1)/2$                           | $\Theta(n^2)$    |
| `i=1; i<n; i*=2`                         | $\lceil\log_2 n\rceil$, para $n\ge1$ | $\Theta(\log n)$ |
| ciclo linear seguido de ciclo quadrático | $n+n^2$                              | $\Theta(n^2)$    |

Não multipliques custos de ciclos consecutivos. E não classifiques todos os ciclos encaixados como quadráticos: se o exterior duplica `i` e o interior executa `i` vezes, a soma é $1+2+4+\cdots<2n$, ou seja, $\Theta(n)$. Um índice que apenas avança ao longo de todo o programa pode justificar uma soma linear, mesmo dentro de outro ciclo.

O modelo costuma tratar operações sobre inteiros de dimensão fixa e acesso a uma posição de array como constantes. Comparar duas strings com comprimento máximo `L` pode custar $O(L)$. Copiar um vetor de `n` posições custa $\Theta(n)$, mesmo que a chamada pareça uma única instrução.

## Limites assintóticos

Para funções não negativas a partir de certa dimensão:

- $T(n)\in O(f(n))$ se existem $c>0,n_0$ com $T(n)\le c f(n)$ para todo $n\ge n_0$.
- $T(n)\in\Omega(f(n))$ se existe um limite inferior análogo.
- $T(n)\in\Theta(f(n))$ se os dois limites valem.

Para $T(n)=3n^2+7n+4$, com $n\ge1$, temos $3n^2\le T(n)\le14n^2$. Logo $T(n)\in\Theta(n^2)$. Também pertence a $O(n^3)$, mas esse limite informa menos. E $O$ não significa «pior caso»: podes dar um limite superior para o melhor caso, o caso médio ou o pior caso, desde que indiques qual analisaste.

A notação $\sum$ indica uma soma dos termos nos limites escritos. Por exemplo, $\sum_{i=1}^{n}i=1+2+\cdots+n$. $\log_2 n$ é o expoente que dá `n` como potência de 2; conta aproximadamente quantas divisões por dois reduzem `n` até um. $n!$ é o produto $1\cdot2\cdots n$.

A ordem de crescimento habitual é

$$1\prec\log n\prec n\prec n\log n\prec n^2\prec n^3\prec2^n\prec n!.$$

A base do logaritmo muda apenas uma constante. Uma medição de 0,4 s com dimensão `n` sugere cerca de 1,6 s ao duplicar `n` num algoritmo quadrático, se a parcela quadrática dominar e as condições forem semelhantes. É uma estimativa, não uma garantia sobre outra máquina ou outra distribuição de dados.

## Recorrências e espaço

Uma função **recursiva** chama-se a si própria para resolver um problema menor. O caso base resolve diretamente um problema pequeno, sem nova chamada. Para provares terminação, verifica que cada chamada reduz uma dimensão inteira não negativa até ao caso base. A hipótese indutiva assume a correção dos subproblemas menores; tens de explicar como os seus resultados resolvem o problema atual. Cada chamada suspensa conserva parâmetros e variáveis na pilha de chamadas.

Uma **recorrência** exprime o custo de uma chamada pelo trabalho local e pelo custo das chamadas menores. Assume custo constante no caso base; divisões em metades de dimensão ímpar usam arredondamentos, que não alteram as ordens seguintes.

Uma chamada que resolve duas metades e faz trabalho linear satisfaz $T(n)=2T(n/2)+\Theta(n)$. Em cada nível da árvore de chamadas, o trabalho total é $\Theta(n)$ e há $\Theta(\log n)$ níveis. O total é $\Theta(n\log n)$.

Calcular o máximo de duas metades e comparar os dois resultados faz trabalho constante por chamada: $T(n)=2T(n/2)+\Theta(1)$. Os níveis têm 1, 2, 4, … chamadas e a soma até às `n` folhas é $2n-1$, ou seja, $\Theta(n)$. Ter duas chamadas recursivas não implica custo $n\log n$, porque o custo da junção é decisivo.

Uma chamada que só segue uma metade com trabalho constante satisfaz $T(n)=T(n/2)+\Theta(1)=\Theta(\log n)$. Uma chamada que reduz o tamanho em um e percorre o restante satisfaz $T(n)=T(n-1)+\Theta(n)=\Theta(n^2)$.

Conta também o **espaço auxiliar**, sem a entrada e a saída quando essa convenção é explícita. Uma recursão com profundidade `h` ocupa $O(h)$ na pilha de chamadas. Duas chamadas consecutivas não exigem o espaço das duas subárvores ao mesmo tempo. Um vetor auxiliar reutilizado de tamanho `n` mais uma pilha de profundidade $\log n$ custa $O(n)$.

## Pior caso, média e amortização

O pior caso maximiza o custo entre entradas da mesma dimensão. O caso médio exige uma distribuição de probabilidades: não basta dizer «normalmente». Com chaves distintas, um quicksort com pivô uniforme tem custo esperado $O(n\log n)$ devido à escolha aleatória do pivô, embora ainda exista uma execução quadrática. A partição também importa: Lomuto com chaves todas iguais continua quadrático, mesmo com pivô aleatório.

A análise **amortizada** limita uma sequência de operações, sem assumir entradas aleatórias. Num vetor que duplica a capacidade quando fica cheio, as cópias ao inserir `n` elementos somam $1+2+4+\cdots<2n$. Uma inserção isolada pode custar $\Theta(n)$, mas o custo amortizado por inserção é $O(1)$. Realocar pode invalidar referências e iteradores, mesmo com custo amortizado baixo.

## Pré-processar consultas

Para responderes à soma de um intervalo `[l,r)`, constrói prefixos: $p[0]=0$ e $p[i+1]=p[i]+v[i]$. Por indução, $p[i]$ é a soma das primeiras `i` posições. Assim,

$$\sum_{i=l}^{r-1}v[i]=p[r]-p[l].$$

Construir custa $\Theta(n)$, cada consulta custa $\Theta(1)$, e `q` consultas custam $\Theta(n+q)$ no total. Somar cada intervalo de novo pode custar $\Theta(nq)$. Se o vetor mudar, os prefixos deixam de corresponder aos dados.

  }
  input={'4 3\n4 -2 7 1\n1 3\n2 2\n0 4\n'}
/>

O programa aceita o intervalo vazio e limita os valores para que a soma caiba em `long long`. Testa também `n=0`, `q=1` e a consulta `0 0`.

:::details[Avaliar um polinómio com Horner]
Para $a_0+a_1x+\cdots+a_dx^d$, começa em `a[d]` e repete `r=r*x+a[i]` com `i` decrescente. Para $2-3x+4x^2$, com `x=2`, começa em 4, passa a `4×2-3=5` e termina em `5×2+2=12`. Depois de incorporar o coeficiente `a[i]`, o invariante é $r=a_i+a_{i+1}x+\cdots+a_dx^{d-i}$. Multiplicar por `x` e somar o coeficiente seguinte preserva essa forma. Faz `d` multiplicações e `d` somas, em vez de recalcular cada potência.
:::

## Melhor soma contígua

Considera a maior soma de um intervalo **não vazio**. Enumerar todos os pares de extremos e somar cada intervalo custa $O(n^3)$. Atualizar a soma enquanto avanças o extremo direito reduz para $O(n^2)$; prefixos também avaliam cada par em tempo constante, mas deixam um número quadrático de pares.

:::tip[Ideia-chave]
O algoritmo de Kadane guarda `atual`, a maior soma de um intervalo que termina exatamente na posição anterior, e `melhor`, a maior soma de qualquer intervalo processado. Ao ler `x`, um intervalo que acaba aqui começa em `x` ou prolonga um que acabava antes, ou seja, `atual=max(x,atual+x)`. Depois `melhor=max(melhor,atual)`.
:::

Em `[-3,5,-2,4,-8,6]`, os valores de `atual` são `-3,5,3,7,-1,6`, e a melhor soma é 7, do intervalo `[5,-2,4]`. Num vetor só de negativos, a resposta é o maior elemento, não zero. Se o intervalo vazio fosse permitido, zero passaria a ser uma resposta possível; seria outro contrato.

<CodePlayground

  title="Maior soma de um intervalo não vazio"
  code={
    '#include <algorithm>\n#include <iostream>\n#include <optional>\n#include <vector>\nstd::optional<long long> melhorSoma(const std::vector<int>& a) {\n    if (a.empty()) return std::nullopt;\n    long long atual = a[0], melhor = a[0];\n    for (std::size_t i = 1; i < a.size(); ++i) {\n        atual = std::max<long long>(a[i], atual + a[i]);\n        melhor = std::max(melhor, atual);\n    }\n    return melhor;\n}\nint main() {\n    for (const std::vector<int>& a : {std::vector<int>{-3, 5, -2, 4, -8, 6},\n                                     std::vector<int>{-6, -2, -8},\n                                     std::vector<int>{}}) {\n        const auto r = melhorSoma(a);\n        if (r) std::cout << *r << \'\\n\';\n        else std::cout << "sem intervalo\\n";\n    }\n}\n'
  }
/>

O programa usa `optional` para representar a ausência de intervalo numa entrada vazia. Assume até 10 000 valores com módulo até um milhão para que as somas caibam em `long long`. Tempo $O(n)$ e espaço auxiliar $O(1)$. A saída negativa no segundo caso distingue este contrato de uma implementação que começa o melhor em zero.
