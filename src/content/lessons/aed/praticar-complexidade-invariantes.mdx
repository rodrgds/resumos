<Exercise
  id="aed-triangular"
  revision={2}
  title="Contar um ciclo triangular"
  explanation="/cadeiras/aed/complexidade-invariantes/#contar-operações"
  answer={{ kind: 'self', checklist: ['Contei 66 comparações no ciclo triangular e generalizei para n(n-1)/2.', 'Contei 15 execuções com n=12 no ciclo por potências de dois.', 'Justifiquei Θ(n²) no primeiro e Θ(n) no segundo.'] }}
>
  <div>
    Um ciclo exterior usa i=1..12; o interior usa j=1..i-1 e faz uma comparação
    por iteração. Quantas comparações são feitas? Generaliza para dimensão `n`.
    Compara com outro ciclo exterior `i=1; i<n; i*=2`, cujo interior
    executa exatamente `i` vezes. Conta para `n=12` e justifica a ordem
    assintótica de ambos. Assume inteiros suficientemente largos para os índices.
  </div>
  <div slot="hint">
    <p>Escreve os comprimentos dos primeiros ciclos interiores.</p>
  </div>
  <div slot="hint-more">
    <p>A soma é 0+1+...+11.</p>
  </div>
  <div slot="solution">
    <div>
      São 12×11/2=66 comparações, ou seja, para dimensão n, n(n-1)/2 é Θ(n²). O
      ciclo com i=1 não executa o corpo interior. No segundo programa, com `n=12`,
      o índice exterior vale 1, 2, 4 e 8: o trabalho soma `1+2+4+8=15`.
      Em geral, a soma das potências de dois menores que `n` é menor que `2n`
      e a última é pelo menos `n/2`, para `n>1`. Por isso é `Θ(n)`, apesar
      de também haver dois ciclos encaixados.
    </div>
  </div>
  <div slot="mistakes">
    <p>Não uses n² como contagem exata; não incluas j=i.</p>
  </div>
</Exercise>

<Exercise
  id="aed-primeiro-maximo"
  revision={2}
  title="Provar uma política de empate"
  explanation="/cadeiras/aed/complexidade-invariantes/#contrato-e-invariante"
  answer={{
    kind: 'self',
    checklist: [
      'Indiquei a posição 1 e corrigi >= para > no programa.',
      'Mostrei inicialização, manutenção e conclusão com a política de empate.',
      'Justifiquei terminação e o contrato não vazio.',
    ],
  }}
>
  <div>
    O máximo do vetor [6,9,9,2] é procurado atualizando a posição só quando o
    novo valor é estritamente maior. Dá a posição com índices a partir de zero e
    prova que é a primeira ocorrência.
  </div>
  <div slot="work">
    <div>
      Este programa usa uma comparação que viola a política da primeira
      ocorrência. Corrige-a e confirma que cada resultado obtido coincide com o
      esperado. No vazio, a posição devolvida é o tamanho, sem aceder ao vetor.
    </div>
    <CodePlayground
      autoRun={false}
      language="cpp"
      title="Corrigir o empate do máximo"
      code={
        '#include <iostream>\n#include <vector>\nstd::size_t primeiraPosicao(const std::vector<int>& a) {\n    if (a.empty()) return a.size();\n    std::size_t melhor = 0;\n    for (std::size_t i = 1; i < a.size(); ++i)\n        if (a[i] >= a[melhor]) melhor = i;\n    return melhor;\n}\nint main() {\n    const std::vector<std::vector<int>> casos{{6,9,9,2},{4,4,4},{-2},{1,3,5},{}};\n    const std::vector<std::size_t> esperado{1,0,0,2,0};\n    for (std::size_t i = 0; i < casos.size(); ++i)\n        std::cout << "obtido=" << primeiraPosicao(casos[i])\n                  << "; esperado=" << esperado[i] << \'\\n\';\n}\n'
      }
    />
  </div>
  <div slot="hint">
    <div>
      A propriedade tem de referir o prefixo já examinado e a escolha entre
      iguais.
    </div>
  </div>
  <div slot="hint-more">
    <div>
      Antes da iteração i, a resposta é a primeira posição do máximo em [0,i).
    </div>
  </div>
  <div slot="solution">
    <div>
      A posição é 1. No programa, troca `>=` por `>`. No vazio, a verificação inicial devolve `size()` como ausência; o contrato do máximo aplica-se aos casos não vazios. Inicialmente o prefixo tem só a posição 0. Uma chave maior
      substitui o máximo; uma chave igual não troca a posição mais antiga, porque a política é a primeira ocorrência. Ao
      terminar, o prefixo é todo o vetor. n-i diminui até zero, provando
      terminação.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Provar só que o valor é máximo não justifica a primeira posição; usar
      &gt;= mudaria a resposta para 2.
    </div>
  </div>
</Exercise>

<Exercise
  id="aed-kadane"
  revision={2}
  title="Distinguir o intervalo vazio"
  explanation="/cadeiras/aed/complexidade-invariantes/#melhor-soma-contígua"
  answer={{
    kind: 'self',
    checklist: [
      'Tracei atual e melhor até à soma 8 de [3,5].',
      'Obtive -2 no vetor [-6,-2,-8] sob o contrato não vazio.',
      'Expliquei por que permitir o vazio altera a segunda resposta para zero.',
    ],
  }}
>
  <div>
    Qual é a maior soma de um intervalo contíguo não vazio de [-2,4,-6,3,5,-1]?
    Traça `atual` e `melhor` para justificar a resposta. Repete para
    `[-6,-2,-8]` e explica o que mudaria se fosse permitido um intervalo vazio.
  </div>
  <div slot="hint">
    <div>
      Em cada posição, compara começar aí com prolongar o melhor intervalo que
      acabava antes.
    </div>
  </div>
  <div slot="hint-more">
    <div>
      Os valores de atual começam por -2, 4 e -2; o valor 3 inicia um intervalo
      novo.
    </div>
  </div>
  <div slot="solution">
    <div>
      Os valores de atual são -2,4,-2,3,8,7. Os de melhor são -2,4,4,4,8,8. A
      soma máxima é 8, do intervalo [3,5]. Há apenas trabalho constante por
      posição, por isso o custo é O(n). Numa entrada só de negativos, a
      inicialização no primeiro elemento conserva o contrato não vazio. Para
      `[-6,-2,-8]`, `atual` vale -6, -2 e -8; `melhor` vale -6, -2 e -2. A
      resposta é -2, do elemento central. Se o vazio fosse permitido, a soma
      zero venceria qualquer intervalo negativo; no primeiro vetor, a resposta
      continuaria a ser 8.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Não escolhas valores separados: 4+3+5 ignora o -6 entre eles. Inicializar
      a resposta em zero devolveria um intervalo vazio quando todos os valores
      fossem negativos.
    </div>
  </div>
</Exercise>

<Exercise
  id="aed-janela-deslizante"
  revision={2}
  title="Contar janelas sem recomeçar"
  explanation="/cadeiras/aed/complexidade-invariantes/#janela-deslizante-com-contagem"
  answer={{ kind: 'number', value: 2, tolerance: 0 }}
>
  <div>
    Com <code>{'[150,149,151,148,147,153]'}</code>, <code>{'K=4'}</code> e{' '}
    <code>{'T=150'}</code>, quantas janelas têm pelo menos metade das posições
    com valor maior ou igual a <code>{'T'}</code>? Mostra as três contagens, identificando em cada avanço
    o valor que sai e o que entra.
  </div>
  <div slot="hint">Mantém a contagem da janela atual.</div>
  <div slot="hint-more">
    Ao avançar, retira a posição que sai e junta a que entra.
  </div>
  <div slot="solution">
    <div>
      As contagens são 2, 1 e 2. A primeira janela inclui 150 e 151; 150
      conta porque o teste é `>=T`. No primeiro avanço, sai 150 e entra 147: a
      contagem desce para 1. No segundo, sai 149 e entra 153: sobe para 2.
      Com `K=4`, pelo menos metade significa pelo menos dois valores, logo
      há duas janelas válidas. Inicializar custa `O(K)` e cada avanço custa
      `O(1)`, dando `O(N)` no total. Dados próprios, adaptados do contrato AED008.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Recontar cada janela do zero custa <code>{'O(NK)'}</code>; com{' '}
      <code>{'K=N'}</code> há uma só janela.
    </div>
  </div>
</Exercise>
