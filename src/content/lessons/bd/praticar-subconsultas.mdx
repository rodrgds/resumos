<Exercise
  id="not-in-null"
  revision={2}
  title="Ausência e desconhecido"
  explanation="/cadeiras/bd/sql-subconsultas/#o-perigo-de-not-in-com-null"
  answer={{
    kind: 'self',
    checklist: [
      'Previ resposta vazia para NOT IN.',
      'Previ 2 e 3 para NOT EXISTS e expliquei a correlação.',
    ],
  }}
>
  <div>
    Candidato tem ids 1,2,3. Registo contém 1 e NULL. Compara id NOT IN (SELECT
    id FROM Registo) e NOT EXISTS de um registo com r.id = c.id.
  </div>
  <div slot="hint">
    Para id 2, a comparação 2 = 1 é falsa e 2 = NULL é desconhecida. Analisa
    depois a negação de IN.
  </div>
  <div slot="hint-more">
    NOT EXISTS pergunta se existe uma igualdade verdadeira; o NULL não a
    fornece.
  </div>
  <div slot="solution">
    NOT IN não devolve candidatos: para 1, a pertença é verdadeira; para 2 e 3,
    a não pertença fica desconhecida devido ao NULL. NOT EXISTS devolve 2 e 3,
    pois não existe uma igualdade verdadeira para esses ids. A correlação r.id =
    c.id é necessária. Se a pergunta tratar valores desconhecidos de outra
    maneira, essa regra deve ser explícita.
  </div>
  <div slot="mistakes">
    Não uses NULL = NULL para testar ausência. Filtrar NULL interior também não
    resolve por si só um NULL exterior.
  </div>
</Exercise>

<Exercise
  id="todos-produtos-consulta"
  title="Comprar todos, mesmo com compras repetidas"
  explanation="/cadeiras/bd/sql-subconsultas/#perguntas-com-todos"
  answer={{
    kind: 'self',
    checklist: [
      'Usei a ausência de uma falta com correlações completas.',
      'Justifiquei repetição e conjunto vazio.',
    ],
  }}
>
  <div>
    Escreve a condição para clientes que compraram todos os ids de Exigido. Deve
    funcionar com várias encomendas do mesmo produto e com Exigido vazio. Usa
    Cliente como universo.
  </div>
  <div slot="work">
    <p>Acrescenta a condição à consulta. Com os requisitos 10 e 11, a resposta deve ser apenas Ana. Depois de apagares Exigido, deve incluir Ana, Rui e Mia. A execução apresenta o resultado; confere também estes dois casos.</p>
    <CodePlayground
      language="sql"
      title="Completar a consulta universal"
      code={`${loja}
CREATE TABLE Exigido(idProduto INTEGER PRIMARY KEY REFERENCES Produto(id));
INSERT INTO Exigido VALUES (10), (11);
-- Acrescenta a condição antes de ORDER BY.
SELECT c.id, c.nome FROM Cliente AS c
ORDER BY c.id;`}
    />
  </div>

  <div slot="hint">Traduz para não existe um requisito em falta.</div>
  <div slot="hint-more">
    Um requisito falta se não existe uma compra do produto por esse cliente.
  </div>
  <div slot="solution">
    Usa dois NOT EXISTS correlacionados. Exterior: não existe x em Exigido tal
    que não exista Encomenda e Item com e.idCliente = c.id, i.idEncomenda = e.id
    e i.idProduto = x.idProduto. O interior é um teste de existência, por isso
    compras repetidas não mudam o resultado. Com Exigido vazio, o exterior é
    verdadeiro para todos os clientes. Para exigir alguma compra, acrescenta
    outro EXISTS.

```sql
SELECT c.id, c.nome FROM Cliente AS c
WHERE NOT EXISTS (
  SELECT 1 FROM Exigido AS x
  WHERE NOT EXISTS (
    SELECT 1 FROM Encomenda AS e
    JOIN Item AS i ON i.idEncomenda = e.id
    WHERE e.idCliente = c.id AND i.idProduto = x.idProduto
  )
)
ORDER BY c.id;
```

</div>
  <div slot="mistakes">
    Contar linhas Item não conta produtos distintos. Um INNER JOIN que parte de
    compras pode perder clientes sem compras quando os requisitos estão vazios.
  </div>
</Exercise>

<Exercise
  id="maximos-empate-null"
  revision={1}
  title="Conservar empates e excluir desconhecidos"
  explanation="/cadeiras/bd/sql-subconsultas/#máximos-e-empates"
  answer={{
    kind: 'self',
    checklist: [
      'Devolvi os ids 2 e 3, sem perder o empate.',
      'Excluí o preço desconhecido e tratei a tabela vazia.',
      'Escrevi uma consulta que calcula o máximo a partir dos dados.',
    ],
  }}
>
  <div>
    Oferta(id,preco) contém (1,10), (2,30), (3,30) e (4,NULL). Escreve SQL que
    devolva os ids com o maior preço conhecido. Deve conservar todos os empates
    e não devolver linhas se a tabela estiver vazia ou só tiver preços NULL.
  </div>
  <div slot="hint">MAX ignora NULL; uma igualdade com NULL não passa WHERE.</div>
  <div slot="hint-more">Comparar cada preço com uma subconsulta MAX conserva todos os máximos.</div>
  <div slot="solution">

```sql
SELECT id FROM Oferta
WHERE preco = (SELECT MAX(preco) FROM Oferta)
ORDER BY id;
```

    Devolve 2 e 3. MAX calcula 30; a linha 4 não satisfaz a igualdade porque
    a comparação com NULL fica desconhecida. Numa tabela vazia ou só com
    preços NULL, MAX dá NULL e nenhuma linha passa. Uma alternativa é
    preco IS NOT NULL e NOT EXISTS de uma oferta com preço maior.

  </div>
  <div slot="mistakes">
    LIMIT 1 perde um dos máximos. NOT EXISTS de um preço maior, sem excluir o
    preço exterior NULL, aceitaria a linha 4. Não fixes o valor 30 na consulta.
  </div>
</Exercise>
