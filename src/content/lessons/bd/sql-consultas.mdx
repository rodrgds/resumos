A encomenda 100 tem duas linhas de compra. Contar essas linhas dá 2, mas contar encomendas dá 1. Antes de escrever SQL, define o que representa uma linha da resposta. A consulta declara esse resultado; o SGBD escolhe como o obter.

## SELECT e filtros

```sql
SELECT id, nome, precoCentimos / 100.0 AS euros
FROM Produto
WHERE precoCentimos > 3000
ORDER BY precoCentimos DESC, id;
```

A resposta contém Monitor/180 euros e Teclado/45 euros, nesta ordem. `WHERE` testa o preço em cêntimos; a lista de `SELECT` divide-o para mostrar euros. Uma coluna usada no filtro não tem de aparecer no resultado.

`AS` atribui um nome ao resultado de uma expressão. Um alias de tabela, como `Produto AS p`, abrevia referências e permite usar a mesma tabela com papéis diferentes. Não altera os dados nem o nome permanente da tabela.

`BETWEEN a AND b` inclui ambos os limites. `LIKE 'Ra%'` procura uma sequência que começa por Ra; `%` representa zero ou mais caracteres e `_`, um carácter. Em SQLite, `LIKE` é normalmente insensível à diferença de maiúsculas ASCII, enquanto `=` segue a collation escolhida. Não assumes o mesmo comportamento para todos os caracteres Unicode ou todos os motores.

Combina predicados com `AND`, `OR` e `NOT`. Usa parênteses quando misturas condições: `categoria = 'A' AND (stock = 0 OR precoCentimos > 10000)` exige categoria A em ambos os casos. Sem os parênteses, o segundo caso poderia aceitar outra categoria.

## Duplicados e ordem

SQL usa **multiconjuntos** por omissão. Se projetarmos `idCliente` de Encomenda, Ana aparece duas vezes. `SELECT DISTINCT idCliente` elimina a repetição. `DISTINCT` aplica-se à combinação completa das colunas escolhidas.

Eliminar nomes repetidos pode juntar pessoas diferentes. Para obter uma linha por cliente, escolhe o seu id e o nome ou usa uma condição de existência sobre Cliente. Não uses `DISTINCT` para esconder uma junção errada.

A ordem de uma tabela ou consulta não é garantida sem `ORDER BY`. `LIMIT 1` sem uma ordem definida escolhe uma linha sem significado estável. Se houver empates, acrescenta um critério de desempate quando a pergunta exigir exatamente uma linha; se pedir todos os máximos, não os elimines com `LIMIT 1`.

## Junções com condição

Uma junção liga linhas que satisfazem `ON`. Qualifica nomes ambíguos e escreve a ligação de cada par de tabelas:

<CodePlayground
  language="sqlite"
  title="Cada linha comprada com o seu cliente e produto"
  files={{ 'loja.sql': loja }}
  code={`SELECT e.id AS encomenda, c.nome AS cliente,
       p.nome AS produto, i.qtd,
       i.qtd * i.precoUnitario AS totalCentimos
FROM Encomenda AS e
JOIN Cliente AS c ON c.id = e.idCliente
JOIN Item AS i ON i.idEncomenda = e.id
JOIN Produto AS p ON p.id = i.idProduto
ORDER BY e.id, p.id;`}
/>

A resposta tem quatro linhas: duas da encomenda 100, uma da 101 e uma da 102. Cada linha corresponde a um Item. Ana aparece três vezes porque comprou três pares encomenda/produto, não porque sejam três clientes.

Omitir uma condição pode criar um produto cartesiano. Juntar três clientes com três encomendas sem condição produz nove pares, incluindo associações falsas. `NATURAL JOIN` não é uma correção automática: Cliente e Encomenda têm ambos `id`, com significados distintos.

`JOIN ... USING(idCliente)` exige uma coluna desse nome em ambos os lados e devolve uma só cópia dessa coluna. `ON` permite nomes diferentes e condições mais gerais.

## Pares sem repetição na mesma tabela

Para formar pares de encomendas do mesmo cliente, juntamos Encomenda consigo própria. Os aliases dão papéis diferentes à mesma tabela:

<CodePlayground
  language="sqlite"
  title="Pares de encomendas do mesmo cliente"
  files={{ 'loja.sql': loja }}
  code={`SELECT e1.id AS primeira, e2.id AS segunda
FROM Encomenda AS e1
JOIN Encomenda AS e2
  ON e2.idCliente = e1.idCliente AND e1.id < e2.id
ORDER BY primeira, segunda;`}
/>

A resposta é só o par 100 e 101, as duas encomendas de Ana. A condição `e1.id < e2.id` exclui pares de uma encomenda consigo própria e conserva cada par uma vez. Com `e1.id <> e2.id`, obteríamos também o par 101 e 100, a mesma combinação por outra ordem. Sem a condição de cliente, o par misturaria encomendas de pessoas diferentes.

## Junções externas e clientes sem compras

Um `INNER JOIN` elimina linhas sem correspondência. Um `LEFT JOIN` conserva todas as linhas da esquerda e preenche as colunas da direita com `NULL` quando não há correspondência.

<CodePlayground
  language="sqlite"
  title="Conservar Mia na contagem de encomendas"
  files={{ 'loja.sql': loja }}
  code={`SELECT c.id, c.nome, COUNT(e.id) AS encomendas
FROM Cliente AS c
LEFT JOIN Encomenda AS e ON e.idCliente = c.id
GROUP BY c.id, c.nome
ORDER BY c.id;`}
/>

As linhas que chegam ao agrupamento são:

| nome | e.id |
| ---- | ---- |
| Ana  | 100  |
| Ana  | 101  |
| Rui  | 102  |
| Mia  | NULL |

A resposta é Ana com 2, Rui com 1 e Mia com 0, porque `COUNT(e.id)` ignora o `NULL` da linha artificial de Mia, enquanto `COUNT(*)` contaria essa linha.

Se quisermos conservar clientes sem encomendas numa data, coloca o filtro da data no `ON`:

```sql
FROM Cliente AS c
LEFT JOIN Encomenda AS e
  ON e.idCliente = c.id AND e.data = '2026-01-05'
```

Mover `e.data = ...` para `WHERE` retira as linhas sem correspondência, pois a comparação com `NULL` não é verdadeira. Uma condição no `ON` decide correspondências; uma condição no `WHERE` filtra o resultado já produzido.

`RIGHT JOIN` conserva o lado direito e `FULL OUTER JOIN` conserva ambos os lados. SQLite inclui estes operadores a partir de 3.39; em versões anteriores, usa reescritas adequadas. Todos os exemplos executáveis destas páginas usam `LEFT JOIN` quando precisam de preservar linhas sem correspondência.

## NULL e lógica a três valores

Uma comparação com `NULL`, incluindo `NULL = NULL`, normalmente dá **desconhecido**. `WHERE` conserva apenas verdadeiro, descartando falso e desconhecido. Para testar ausência, usa `IS NULL` ou `IS NOT NULL`.

| p            | `NOT p`      |
| ------------ | ------------ |
| verdadeiro   | falso        |
| falso        | verdadeiro   |
| desconhecido | desconhecido |

`falso AND desconhecido` é falso; `verdadeiro AND desconhecido` é desconhecido. `verdadeiro OR desconhecido` é verdadeiro; `falso OR desconhecido` é desconhecido. Assim, `preco > 30 OR preco <= 30` não inclui automaticamente uma linha cujo preço seja `NULL`.

`COALESCE(x, alternativa)` devolve o primeiro argumento não nulo. Só transforma um desconhecido em zero quando zero for a interpretação certa. Um stock desconhecido não significa que não existe stock.

## GROUP BY e HAVING

`GROUP BY` reúne linhas com os mesmos valores das colunas de agrupamento. As funções de agregação calculam um resultado para cada grupo. `WHERE` filtra linhas antes do agrupamento; `HAVING` filtra grupos depois.

<CodePlayground
  language="sqlite"
  title="Encomendas que ultrapassam 100 euros"
  files={{ 'loja.sql': loja }}
  code={`SELECT idEncomenda, SUM(qtd * precoUnitario) / 100.0 AS euros
FROM Item
GROUP BY idEncomenda
HAVING SUM(qtd * precoUnitario) > 10000
ORDER BY idEncomenda;`}
/>

Os quatro Items formam três grupos. A soma calcula o valor de cada encomenda; só depois `HAVING` testa o total:

| Encomenda | Valores das linhas, em cêntimos | Total | Total > 10000 |
| --------- | ------------------------------- | ----- | ------------- |
| 100       | 9000 + 2500                     | 11500 | sim           |
| 101       | 18000                           | 18000 | sim           |
| 102       | 7500                            | 7500  | não           |

A resposta contém 100/115 euros e 101/180 euros. Um filtro sobre o preço de cada linha antes da soma faria outra pergunta. `WHERE SUM(...) > ...` não filtra o total de um grupo.

`COUNT(*)` conta linhas. `COUNT(x)` conta os x não nulos; `COUNT(DISTINCT x)` conta valores distintos não nulos. `SUM`, `AVG`, `MIN` e `MAX` ignoram valores nulos. Sem linhas e sem `GROUP BY`, `COUNT` dá 0, enquanto `SUM`, `AVG`, `MIN` e `MAX` dão `NULL`. Com `GROUP BY`, uma entrada vazia não produz grupos.

<CodePlayground
  language="sqlite"
  title="Agregações com NULL e com entrada vazia"
  code={`CREATE TABLE Valor(x INTEGER);
INSERT INTO Valor VALUES (10), (NULL), (20);
SELECT COUNT(*) AS linhas, COUNT(x) AS conhecidos,
       SUM(x) AS soma, AVG(x) AS media FROM Valor;
SELECT COUNT(*) AS linhas,
       SUM(x) AS soma
FROM Valor WHERE 0;
SELECT x, COUNT(*) FROM Valor WHERE 0 GROUP BY x;`}
/>

A primeira resposta tem 3 linhas, 2 valores conhecidos, soma 30 e média 15 porque a média divide por dois valores conhecidos, não por três linhas. A segunda tem contagem 0 e soma `NULL` e a terceira não devolve linhas.

SQLite permite colunas soltas numa consulta agregada, mas o valor escolhido pode não representar o grupo de forma estável. Há regras especiais para certos usos de `MIN` e `MAX`, que ainda deixam ambiguidades com empates. Escreve cada coluna da resposta no agrupamento ou numa agregação, ou formula explicitamente a escolha com uma subconsulta. Não uses essa permissividade para justificar SQL portátil.

## Multiplicação de linhas e contagens

Se juntarmos Cliente, Encomenda e Item, a encomenda 100 aparece duas vezes porque tem dois produtos. `COUNT(e.id)` passa a contar linhas compradas, dando 3 para Ana. Para contar encomendas nesse resultado, usa `COUNT(DISTINCT e.id)`; para somar valores de encomendas já agregados, evita uma junção que volte a multiplicá-los.

Agrupar por nome também funde pessoas de nome igual. Agrupa por chave e inclui o nome. Cada junção deve ter uma cardinalidade esperada antes de calculares a agregação.

## Expressões e datas

`CASE` calcula valores por condições:

```sql
SELECT nome,
       CASE WHEN stock = 0 THEN 'esgotado'
            WHEN stock < 10 THEN 'baixo'
            ELSE 'disponível' END AS estado
FROM Produto;
```

No exemplo, Monitor tem stock baixo; Teclado e Rato estão disponíveis. Um `CASE` sem `ELSE` devolve `NULL` quando nenhuma condição corresponde.

Datas ISO guardadas como texto, no formato `AAAA-MM-DD`, podem ser comparadas lexicograficamente se o formato for uniforme e válido. Para durações, usa funções de data, como `julianday(fim) - julianday(inicio)`. Subtrair dois textos com datas não calcula dias. Inclui a decisão de contar ou não os dias inicial e final no enunciado.

## Ordem lógica da consulta

Para explicar uma consulta, pensa em `FROM` e junções, depois `WHERE`, agrupamento, `HAVING`, expressões de `SELECT`, `DISTINCT`, `ORDER BY` e `LIMIT`. Esta é uma ordem de interpretação, não uma promessa sobre o plano físico do motor.

Quando uma resposta surpreender, observa a tabela intermédia antes de agregar. Quase sempre é mais útil conferir quais as linhas produzidas pela junção do que acrescentar outro `DISTINCT` no fim.
