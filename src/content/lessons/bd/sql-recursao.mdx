Totais por encomenda e depois por cliente são dois passos com nome numa só instrução. Números de 1 a 5 e descendentes de uma categoria nascem de outro mecanismo: produzir linhas a partir das já obtidas, até não haver novidade.

Uma **CTE**, _common table expression_, dá nome a um resultado dentro de uma instrução SQL. Ajuda a dividir uma pergunta em etapas sem criar uma vista permanente. Uma CTE recursiva produz linhas a partir de linhas já obtidas.

## WITH: dar nome a um passo

<CodePlayground
  language="sql"
  title="Totais por encomenda, depois por cliente"
  code={`${loja}
WITH Totais AS (
  SELECT idEncomenda, SUM(qtd * precoUnitario) AS total
  FROM Item GROUP BY idEncomenda
), PorCliente AS (
  SELECT e.idCliente, SUM(t.total) AS total
  FROM Encomenda AS e JOIN Totais AS t ON t.idEncomenda = e.id
  GROUP BY e.idCliente
)
SELECT c.id, c.nome, COALESCE(p.total, 0) / 100.0 AS euros
FROM Cliente AS c LEFT JOIN PorCliente AS p ON p.idCliente = c.id
ORDER BY c.id;`}
/>

Totais tem uma linha por encomenda. PorCliente reúne essas linhas por comprador, por isso a resposta tem Ana com 295 euros, Rui com 75 e Mia com 0. O `LEFT JOIN` conserva Mia e o `COALESCE` apresenta o total ausente como zero.

Uma CTE pode referenciar outra definida na mesma instrução. O seu nome deixa de existir no fim dessa instrução. Não garante materialização nem uma vantagem de desempenho; o otimizador pode integrá-la no plano. A razão inicial para a usar aqui é exprimir claramente o nível de cada agregação.

## Parte inicial e passo recursivo

Uma CTE recursiva tem uma **parte inicial**, que cria as primeiras linhas, e um **passo recursivo**, que usa o resultado anterior para criar mais. As duas partes têm de devolver o mesmo número de colunas com significados compatíveis.

<CodePlayground
  language="sql"
  title="Gerar os números de 1 a 5"
  code={`WITH RECURSIVE Numero(n) AS (
  SELECT 1
  UNION ALL
  SELECT n + 1 FROM Numero WHERE n < 5
)
SELECT n FROM Numero ORDER BY n;`}
/>

A parte inicial produz 1. O passo lê 1 e produz 2, depois 3, 4 e 5. Ao ler 5, `n < 5` é falso e não produz uma linha nova. A recursão termina. A condição usa o valor anterior: trocar `< 5` por `<= 5` produziria também 6.

Os estados da recursão:

| Iteração | Lê  | Produz | Acumulado     |
| -------- | --- | ------ | ------------- |
| 0        | —   | 1      | 1             |
| 1        | 1   | 2      | 1, 2          |
| 2        | 2   | 3      | 1, 2, 3       |
| 3        | 3   | 4      | 1, 2, 3, 4    |
| 4        | 4   | 5      | 1, 2, 3, 4, 5 |
| 5        | 5   | —      | 1, 2, 3, 4, 5 |

Não contes com um suposto limite fixo de profundidade para tornar uma consulta correta. Escreve uma condição de terminação e, quando necessário, um limite de trabalho compatível com a pergunta. Os limites e restrições dependem do motor.

## Percorrer uma hierarquia

Cada categoria tem no máximo uma categoria mãe. A raiz tem `NULL`. Queremos a raiz e todos os seus descendentes, com profundidade 0 para a raiz.

<CodePlayground
  language="sql"
  title="Categorias descendentes de Informática"
  code={`PRAGMA foreign_keys = ON;
CREATE TABLE Categoria(
  id INTEGER PRIMARY KEY,
  nome TEXT NOT NULL,
  idMae INTEGER REFERENCES Categoria(id)
);
INSERT INTO Categoria VALUES
  (1, 'Informática', NULL), (2, 'Periféricos', 1),
  (3, 'Teclados', 2), (4, 'Monitores', 1), (5, 'Casa', NULL);
WITH RECURSIVE Descendente(id, nome, profundidade) AS (
  SELECT id, nome, 0 FROM Categoria WHERE id = 1
  UNION ALL
  SELECT c.id, c.nome, d.profundidade + 1
  FROM Categoria AS c JOIN Descendente AS d ON c.idMae = d.id
)
SELECT id, nome, profundidade FROM Descendente
ORDER BY profundidade, id;`}
/>

A resposta é Informática/0, Periféricos/1, Monitores/1 e Teclados/2, porque a condição `c.idMae = d.id` segue filhos; inverter os papéis seguiria ascendentes. Casa não é alcançada.

O exemplo assume uma hierarquia sem ciclos. A estrangeira verifica que a mãe existe, mas permite criar um ciclo entre categorias. A validação da estrutura é uma regra adicional.

## Grafos e ciclos

Num grafo, o mesmo nó pode ser alcançado por vários caminhos. Se queremos apenas o conjunto de nós alcançáveis, podemos usar uma coluna id e `UNION`, que elimina resultados já obtidos:

<CodePlayground
  language="sql"
  title="Alcançabilidade com um ciclo"
  code={`CREATE TABLE Aresta(origem INTEGER, destino INTEGER,
  PRIMARY KEY(origem, destino));
INSERT INTO Aresta VALUES (1,2), (2,3), (3,1), (2,4);
WITH RECURSIVE Alcancavel(id) AS (
  SELECT 1
  UNION
  SELECT a.destino FROM Aresta AS a
  JOIN Alcancavel AS r ON a.origem = r.id
)
SELECT id FROM Alcancavel ORDER BY id;`}
/>

O resultado é 1, 2, 3 e 4. Voltar ao nó 1 não introduz um novo tuplo. `UNION ALL` conservaria as repetições e seguiria o ciclo indefinidamente se não houvesse outra condição.

Se acrescentarmos profundidade, `(1,0)` e `(1,3)` são tuplos diferentes. `UNION` já não elimina esse retorno apenas por ter o mesmo id. Para listar caminhos ou distâncias, precisamos de outra estratégia, como impedir a repetição de nós no caminho e limitar a exploração. A escolha das colunas faz parte da prova de terminação.

## Só os divisores precisam de recursão

No método de D'Hondt, cada lista compete com os quocientes votos/1, votos/2 e assim por diante, até ao número de mandatos M. Os M lugares vão para os M maiores quocientes. Com 4 mandatos e votos A=100, B=60, C=40, os quocientes são:

| Lista | /1    | /2   | /3   | /4   |
| ----- | ----- | ---- | ---- | ---- |
| A     | 100,0 | 50,0 | 33,3 | 25,0 |
| B     | 60,0  | 30,0 | 20,0 | 15,0 |
| C     | 40,0  | 20,0 | 13,3 | 10,0 |

Os quatro maiores são 100 de A, 60 de B, 50 de A e 40 de C. O resultado é A com 2, B com 1 e C com 1. Só a sequência de divisores 1 a M precisa de recursão; o resto são operações comuns:

<CodePlayground
  language="sql"
  title="Distribuir 4 mandatos pelo método de D'Hondt"
  code={`WITH RECURSIVE Divisor(k) AS (
  SELECT 1
  UNION ALL
  SELECT k + 1 FROM Divisor WHERE k < 4
),
Voto(lista, votos) AS (
  VALUES ('A', 100), ('B', 60), ('C', 40)
),
Quociente AS (
  SELECT v.lista, v.votos / (d.k * 1.0) AS q
  FROM Voto AS v CROSS JOIN Divisor AS d
),
Top AS (
  SELECT lista FROM Quociente
  ORDER BY q DESC, lista LIMIT 4
)
SELECT lista, COUNT(*) AS mandatos
FROM Top GROUP BY lista ORDER BY lista;`}
/>

A resposta é A com 2, B com 1 e C com 1. O `ORDER BY q DESC, lista` inclui uma regra de desempate explícita: em caso de quocientes iguais, vence a lista com nome menor. Sem esse segundo critério, a escolha entre empatados ficaria indefinida. A agregação final conta lugares, não votos: cada ocorrência de uma lista nos 4 primeiros quocientes vale um mandato.

## Limites de SQLite

Em SQLite, a parte recursiva tem de usar a tabela recursiva segundo as restrições do motor, sem referências adicionais em subconsultas, e não pode usar agregações nem funções de janela nessa parte. No exemplo de D'Hondt, a agregação está no `SELECT` exterior, depois de produzidas as linhas. Uma CTE recursiva não é necessariamente a melhor opção para toda a pergunta: a recursão pertence à geração dos divisores; não precisamos de tornar toda a agregação recursiva.
