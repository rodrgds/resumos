Depois da árvore da sintaxe, esta página responde se os nomes e os tipos do programa fazem sentido.

A análise semântica percorre a árvore sintática e pergunta o que a gramática não consegue responder: este nome foi declarado? Neste ponto do programa, o que significa? Os tipos desta operação são compatíveis? O caso concreto é `a + b` com `b` por declarar: passa na gramática e falha no significado. O instrumento central é a **tabela de símbolos**, ou seja, o registo de cada declaração com nome, tipo, **âmbito** (o bloco onde esse nome vale) e posição.

## Tabela de símbolos e âmbitos

Cada bloco abre um **âmbito** novo que vê os nomes dos âmbitos exteriores. Quando o mesmo nome é declarado dentro e fora, a declaração interior **esconde** (_shadowing_) a exterior dentro desse bloco, e a exterior volta a valer quando o bloco fecha. Na prática, a tabela é uma pilha de mapas: procurar um nome começa no âmbito atual e sobe até encontrar ou esgotar.

Funções e parâmetros vivem no âmbito da função: os parâmetros comportam-se como variáveis locais inicializadas pela chamada, e o tipo de retorno regista-se na entrada da função para verificar cada `return`.

## Exemplo: bloco com shadowing e erro de tipo

Neste pseudocódigo, cada bloco admite shadowing e uma declaração só fica visível **depois** do seu inicializador. É uma regra escolhida para o exemplo, que deve ser confirmada na especificação de cada linguagem. A tabela guarda tipos e declarações; os valores abaixo servem para seguir a execução.

```text
int x = 3;
{
  int x = x + 1;
  print(x);
}
```

Construção da tabela, por ordem:

1. Âmbito global: `x -> int`, valor 3.
2. Abre o bloco: âmbito novo vazio.
3. Declaração `int x = ...`: o inicializador avalia-se **antes** de a nova entrada existir, por isso o `x` de `x + 1` resolve-se no global e vale 3. Depois regista-se `x -> int` no âmbito do bloco (shadowing ativo daqui em diante).
4. `print(x)`: resolve-se no âmbito do bloco, o `x` interior, que vale 4. Escreve 4.

Agora a chamada com argumentos trocados. Com `int soma(int a, int b)` declarada, a chamada `soma(true, 2)` percorre a árvore da chamada e compara cada argumento com o parâmetro correspondente: o primeiro é booleano onde se esperava inteiro, ou seja, erro semântico com a posição da chamada, antes de gerar uma única instrução. Repara na divisão de trabalho: a sintaxe aceitou a chamada (a forma está certa), a semântica rejeita-a (o significado está errado).

Estes três exemplos têm forma sintática válida, mas violam as regras semânticas indicadas.

Em Java usamos nomes locais diferentes para este bloco, porque Java não permite esta redeclaração de `x` local num bloco aninhado. O `y` interior lê o `x` do bloco do método, que é um âmbito exterior, não global. Além disso, o âmbito de uma variável local Java inclui o seu inicializador: `int z = z + 1` não lê automaticamente uma declaração exterior e falha por falta de inicialização. Não transfiras as regras do pseudocódigo para Java ou para o projeto sem as confirmar.

## Verificação de tipos

Na linguagem didática, só admitimos `int` e `boolean`, sem conversões implícitas. As regras de tipo sobem pela árvore: o tipo de `a + b` exige operandos numéricos do mesmo tipo e devolve esse tipo; uma condição de `if` ou `while` exige booleano; uma atribuição exige compatibilidade entre o lado direito e a variável, porque cada regra violada é um erro com posição. Outras linguagens podem promover tipos numéricos ou permitir sobrecarga. A regra depende da especificação, não do aspeto do operador.

:::tip[Como seguir os âmbitos]
Nesta linguagem didática, para construir a tabela e encontrar erros, desenha uma coluna por âmbito, regista cada declaração quando ela entra em vigor (o inicializador usa o âmbito anterior) e verifica cada uso e cada operação contra a tabela.
:::

## Atributos e ordem de cálculo

:::details[Ver atributos herdados e sintetizados]
Uma definição dirigida pela sintaxe associa atributos aos nós e regras para os calcular. Um atributo **sintetizado** usa informação dos filhos; um atributo **herdado** recebe contexto do pai ou de irmãos, segundo as regras definidas.

Na produção `E → E1 + T`, a regra `E.tipo = verificarSoma(E1.tipo, T.tipo)` sintetiza o tipo da expressão a partir dos operandos. A tabela de símbolos disponível num nó pode ser um atributo herdado: o bloco entrega o seu âmbito aos filhos antes de estes resolverem nomes. Assim, o contexto desce e os tipos sobem. A ordem de avaliação deve respeitar estas dependências; um ciclo sem regra de resolução impede este cálculo simples.
:::
