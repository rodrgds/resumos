<Exercise
  id="c-recursao-frames"
  revision={2}
  title="Seguir chamadas e retornos"
  explanation="/cadeiras/c/ambientes-execucao/#registos-de-uma-chamada-recursiva"
  answer={{ kind: 'self', checklist: [
    'Listei fat(4), fat(3), fat(2) e fat(1), com quatro registos no máximo.',
    'Obtive retornos 1, 2, 6 e 24, retirando um registo de cada vez.',
    'Expliquei que cada chamada conserva o seu próprio n enquanto espera.',
  ] }}
>

Para `fat(4)`, usa o caso base `n ≤ 1` e o retorno `n * fat(n - 1)`, sem otimizações. Mostra as chamadas até ao caso base, o máximo de registos simultaneamente ativos e o valor devolvido em cada retorno. Conta apenas registos de `fat`, sem o chamador.

<div slot="hint">

Primeiro segue as chamadas sem multiplicar. As multiplicações só terminam quando a chamada interior devolve o resultado.

</div>
<div slot="solution">

As chamadas são `fat(4) → fat(3) → fat(2) → fat(1)`. No caso base há quatro registos ativos; os três exteriores ainda esperam.

| Chamada  | Retorno      |
| -------- | ------------ |
| `fat(1)` | 1, caso base |
| `fat(2)` | `2 × 1 = 2`  |
| `fat(3)` | `3 × 2 = 6`  |
| `fat(4)` | `4 × 6 = 24` |

Depois de cada retorno, ficam respetivamente 3, 2, 1 e 0 registos de `fat` na pilha. Cada linha retira a chamada mais interior ainda ativa.

Cada chamada usa o `n` guardado no seu registo. O máximo de registos é 4; o resultado da função é 24. São grandezas diferentes.

</div>
</Exercise>

<Exercise
  id="c-java-copia-referencia"
  title="Seguir uma referência passada por valor"
  explanation="/cadeiras/c/ambientes-execucao/#passagem-de-parâmetros"
  answer={{
    kind: 'self',
    checklist: [
      'Obtive v[0] = 8 depois da chamada.',
      'Expliquei que p e v partilham inicialmente a referência ao mesmo vetor.',
      'Expliquei que p = new int[]{20} não altera a variável v do chamador.',
    ],
  }}
>

    Em Java, int[] v = &#123;3&#125;; é passado a muda. Qual é v[0] depois da
    chamada? Distingue alterar o objeto de reatribuir o parâmetro.

```java
static void muda(int[] p) {
  p[0] = 8;
  p = new int[]{20};
}
```

  <div slot="hint">

O valor copiado é a referência, não uma cópia do vetor.

</div>
  <div slot="solution">

Ao entrar, p contém uma cópia da referência de v. p[0] = 8 altera o vetor
partilhado, por isso v[0] passa a 8. A atribuição seguinte cria outro vetor e
muda apenas a referência local p. v continua a apontar para o primeiro vetor e
v[0] continua a 8. Java passou o argumento por valor em ambos os passos.

</div>
  <div slot="mistakes">

Não chames a isto passagem por referência à variável v nem confundas a cópia
da referência com a cópia do objeto.

</div>
</Exercise>

<Exercise id="c-ligacoes-ativacao" title="Distinguir chamador e âmbito lexical" explanation="/cadeiras/c/ambientes-execucao/#organização-de-memória" answer={{"kind": "self", "checklist": ["A ligação dinâmica de f aponta para g, o chamador.", "A ligação estática de f aponta para externo, o âmbito lexical exterior.", "Procurei x no registo de externo e distingui as duas ligações."]}}>

Numa linguagem com funções aninhadas, externo declara x, f e g. f lê x; g chama f. externo está ativo e chama g. Para o registo de f, identifica a ligação dinâmica, a ligação estática e o registo onde se encontra x.

<div slot="hint">

O texto das declarações fixa o âmbito lexical; a execução fixa o chamador.

</div>
<div slot="solution">

A cadeia de chamadas é externo → g → f. Por isso, a ligação dinâmica de f aponta
para g. A ligação estática aponta para externo, porque é aí que f foi
declarado. O acesso não local a x segue esta ligação para o registo de
externo. O endereço de retorno é outra informação: indica onde continuar em g.

</div>
<div slot="mistakes">

Não escolhas g como âmbito de x só por ter feito a chamada nem confundas uma
ligação para um registo com uma instrução de retorno.

</div>
</Exercise>
