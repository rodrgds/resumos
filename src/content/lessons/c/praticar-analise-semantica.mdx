<Exercise
  id="c-ambitos-inicializador"
  title="Resolver nomes com uma regra explícita"
  explanation="/cadeiras/c/analise-semantica/#shadowing-e-inicializadores"
  answer={{
    kind: 'self',
    checklist: [
      'O inicializador de n interior usa n exterior, com valor 6.',
      'Associei o primeiro print ao n interior e o segundo ao exterior.',
      'Obtive a sequência 12, 6 e mantive as duas declarações distintas.',
    ],
  }}
>

    No pseudocódigo abaixo, uma declaração só fica visível depois do
    inicializador e o bloco permite shadowing. Dá a declaração usada em cada
    print e os valores impressos.

```text
int n = 6;
{
  int n = n * 2;
  print(n);
}
print(n);
```

  <div slot="hint">

Abre um mapa vazio ao entrar no bloco.

</div>
  <div slot="hint-more">

A nova entrada n ainda não existe quando calculas n \* 2.

</div>
  <div slot="solution">

A tabela exterior contém n: int. Ao entrar no bloco, o mapa interior está
vazio; n \* 2 resolve n no exterior e calcula 12, porque a nova entrada ainda não existe. Depois inserimos n: int no
mapa interior. O primeiro print encontra esta declaração e escreve 12. Ao
fechar o bloco, retiramos o mapa; o segundo print encontra a declaração
exterior e escreve 6. A tabela não precisa de guardar estes valores para
resolver os nomes.

</div>
  <div slot="mistakes">

Não generalizes a regra do inicializador a Java nem alteres o valor exterior
por redeclaração.

</div>
</Exercise>

<Exercise id="c-tipos-chamada" title="Verificar chamada e retorno" explanation="/cadeiras/c/analise-semantica/#verificação-de-tipos" answer={{"kind": "self", "checklist": ["Detetei que o segundo argumento 1 é int e o parâmetro exige boolean.", "Detetei que o retorno boolean não pode inicializar r de tipo int.", "Propus testa(4, true) e boolean r = testa(4, true), respetivamente."]}}>

A linguagem não tem conversões implícitas. Com boolean testa(int n, boolean ativo), verifica testa(4, 1) e int r = testa(4, true). Identifica o erro em cada caso e propõe uma correção.

<div slot="hint">

Verifica argumentos antes de comparar o retorno com o destino.

</div>
<div slot="solution">

testa(4, 1) tem dois argumentos, mas o segundo não tem o tipo boolean exigido.
Substituí-lo por true corrige esse erro. Em int r = testa(4, true), os
argumentos estão corretos; a chamada devolve boolean e o destino é int.
Declarar boolean r corrige esta atribuição. São dois pontos de verificação
independentes.

</div>
<div slot="mistakes">

Não confundas número de argumentos correto com tipos corretos nem assumes 1
como true nesta linguagem.

</div>
</Exercise>

<Exercise id="c-java-referencia-programa" title="Programar o âmbito de um campo" explanation="/cadeiras/c/analise-semantica/#tabela-de-símbolos-e-âmbitos" answer={{"kind": "self", "checklist": ["Escrevi um programa Java completo com public static void main(String[] args).", "Acedi ao campo por uma referência ao objeto, sem redeclarar a mesma variável local num bloco interior.", "O programa imprime 2 e 9 e expliquei o acesso caixa.valor."]}}>

Escreve uma classe Java Caixa com campo int valor = 9 e método main. Em main, cria uma Caixa, declara int valor = 2 e escreve primeiro a variável local e depois o campo do objeto. Explica como distingues os nomes.

<div slot="hint">

Um campo e uma variável local podem ter o mesmo nome.

</div>
<div slot="hint-more">

Cria Caixa caixa = new Caixa(); e usa caixa.valor para tornar o acesso ao
campo explícito.

</div>
<div slot="solution">

Uma solução completa: valor sem qualificação resolve a variável local.
caixa.valor acede ao campo do objeto criado. Esta prática tem autoavaliação;
corre o programa Java e compara as duas linhas.

```java
public class Caixa {
    int valor = 9;

    public static void main(String[] args) {
        Caixa caixa = new Caixa();
        int valor = 2;
        System.out.println(valor);
        System.out.println(caixa.valor);
    }
}
```

</div>
<div slot="mistakes">

main é estático, por isso não podes usar this nele. Não troques o acesso ao
campo por outra variável local.

</div>
</Exercise>

<Exercise id="c-atributos-tipos" title="Planear a ordem dos atributos" explanation="/cadeiras/c/analise-semantica/#atributos-herdados-e-sintetizados" answer={{"kind": "self", "checklist": ["Passei Γ aos nós que resolvem identificadores.", "Resolvi x como int e sintetizei int para o literal 5.", "Calculei o tipo de + só depois dos tipos dos dois operandos."]}}>

Para E → E1 + T, um nó recebe o âmbito Γ e deve calcular o tipo de x + 5. Γ contém x:int. Indica a informação herdada e sintetizada e uma ordem válida de cálculo. O + só admite inteiros.

<div slot="hint">

A procura de x precisa de contexto; a soma precisa dos resultados dos filhos.

</div>
<div slot="solution">

Primeiro entregamos Γ aos filhos. O identificador x consulta Γ e obtém int; o
literal 5 tem tipo int. Estes tipos sobem como atributos sintetizados. Por
fim, verificarSoma(int,int) devolve int para E. Γ é herdado, porque transporta
contexto para baixo; o tipo de E é sintetizado, porque depende dos filhos.

</div>
<div slot="mistakes">

Não uses o valor 5 como se fosse um tipo nem confundas a direção dos atributos
com a ordem física dos tokens.

</div>
</Exercise>

<Exercise
  id="c-sobrecarga-ambito"
  revision={1}
  title="Escolher a assinatura depois de resolver o nome"
  explanation="/cadeiras/c/analise-semantica/#resolução-de-sobrecargas"
  answer={{kind: 'self', checklist: ['Associei o n interior a double e o n exterior a int.', 'Escolhi combina(double,int) no bloco e combina(int,int) depois.', 'Obtive 4,5 e 7 e distingui a seleção da conversão do resultado para double.']}}
>

O excerto usa as regras de C++, não as da linguagem didática sem conversões. Existem `int combina(int a,int b)` e `double combina(double a,int b)`, ambas devolvendo a+b. Em main:

```cpp
double origem = 2.5;
int n = 4;
{
    double n = origem;
    double resultado = combina(n, 2);
}
double resultado = combina(n, 3);
```

Dá as ligações dos âmbitos e a assinatura escolhida em cada chamada. Que valores recebem os dois resultados? O destino double da última atribuição faz escolher a sobrecarga double? Justifica. Problema próprio inspirado na distinção entre âmbito e assinatura da questão 3 do teste de 23/4/2026.

  <div slot="solution">

O âmbito global contém as duas candidatas combina. main tem origem:double e n:int; o bloco filho tem outro n:double e resultado:double. A primeira chamada resolve n no bloco e tem argumentos double,int, escolhendo combina(double,int); dá 2,5+2=4,5.

Depois de fechar o bloco, n resolve-se em main como int. combina(n,3) tem argumentos int,int e escolhe combina(int,int), dando 7. Esse int é depois convertido para double na inicialização de resultado. O tipo do destino não muda os tipos dos argumentos nem seleciona a outra sobrecarga. Nos dois casos vence a candidata com correspondência exata, face à alternativa que precisaria de converter o primeiro argumento.

  </div>
</Exercise>
