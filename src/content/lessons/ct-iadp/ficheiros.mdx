O ficheiro de vendas conserva produto, quantidade e preço depois de o programa terminar. Ao relê-lo, os caracteres `"2"` têm de passar a inteiro antes da multiplicação. Caminho, codificação e formato determinam que dados chegam ao cálculo.

## Contextos e modos de abertura

```python
with open("vendas.txt", "r", encoding="utf-8") as ficheiro:
    texto = ficheiro.read()
```

`with` fecha o ficheiro quando sais do bloco, incluindo quando ocorre uma exceção. `read()` lê todo o texto; `read(n)` lê até n caracteres em modo texto ou n bytes em modo binário. `readline()` lê uma linha, normalmente conservando a mudança de linha. No fim do ficheiro, devolve uma string vazia; uma linha em branco pode conter `"\n"`. O iterador do ficheiro permite processar uma linha de cada vez. Sem `with`, chama `close()` quando terminares.

| Modo   | Efeito                                   |
| ------ | ---------------------------------------- |
| `"r"`  | Lê um ficheiro existente                 |
| `"w"`  | Cria ou substitui o conteúdo do ficheiro |
| `"a"`  | Acrescenta ao fim                        |
| `"x"`  | Cria e falha se já existir               |
| `"rb"` | Lê bytes, sem descodificar texto         |

`"w"` pode apagar conteúdo anterior. Para fazer uma experiência, escolhe um ficheiro de teste. O diretório de trabalho é a base dos caminhos relativos, não necessariamente a pasta onde está o script.

## Linhas e campos

Um ficheiro com cabeçalho e duas linhas de dados pode ter este conteúdo:

```text
produto,quantidade,preco
pão,2,1.50
leite,3,1.20
```

Separar cada linha por vírgulas funciona neste exemplo, mas falha quando um campo contém uma vírgula entre aspas. Usa o módulo `csv`, que conhece essas regras.

O ficheiro `vendas.csv` está na tab ao lado do programa e o seu conteúdo é o que está citado acima. `open` lê-o como num programa local.

`DictReader` usa o cabeçalho para nomear as colunas, mas os campos continuam a ser strings. A conversão numérica faz parte da leitura. Se uma célula estiver vazia ou tiver `"n/a"`, decide como representar a ausência antes de converter.

`newline=""` deixa o módulo `csv` tratar as mudanças de linha. Se o separador for ponto e vírgula, passa `delimiter=";"`.

## Escrever resultados

```python
import csv

with open("totais.csv", "w", newline="", encoding="utf-8") as ficheiro:
    escritor = csv.writer(ficheiro)
    escritor.writerow(["produto", "total"])
    escritor.writerows([["pão", 3.0], ["leite", 3.6]])
```

`ficheiro.write(texto)` escreve a string e devolve o número de caracteres escritos; não acrescenta automaticamente uma mudança de linha. Em modo binário, recebe bytes. O modo `"t"` é texto e `"b"` é binário; `"rt"` equivale à leitura de texto habitual.

A escrita CSV converte os valores para texto. Ao reler, os tipos não reaparecem por magia. Define os tipos esperados e o significado de cada coluna.

## Integridade e unidades

Verifica se há cabeçalho, se cada linha tem o número de campos esperado e se a unidade é constante. Uma coluna pode guardar euros ou cêntimos; as duas contêm números, mas produzem totais diferentes por um fator de cem.

Para dados grandes, percorre as linhas sem as guardar todas. Para análise tabular com filtros, junções e agregações, a próxima parte usa pandas. A regra mantém-se: primeiro compreender a tabela, depois escolher a operação.

## Média por leitura sequencial

Para calcular a média de um ficheiro com um número por linha, percorre as linhas e acumula. Não precisas de guardar a lista completa:

```python
soma = 0.0
contagem = 0
with open("valores.txt", "r", encoding="utf-8") as ficheiro:
    for linha in ficheiro:
        soma += float(linha)
        contagem += 1
if contagem == 0:
    raise ValueError("Sem observações")
media = soma / contagem
print(media)
```

Este exemplo exige um número válido por linha, sem linhas em branco. Cada iteração lê a linha seguinte. No fim, `soma` tem o total e `contagem` o número de valores. É o problema 14.01 da turma. Se os dois ficheiros tiverem comprimentos diferentes, decide a política antes de calculares: o enunciado 14.03 trata os valores em falta como zero e calcula a média do par.

## Dois ficheiros de comprimentos diferentes

O problema 14.03 associa valores pela posição da linha e usa zero quando um dos ficheiros já terminou. Esta hipótese pertence ao enunciado; não é uma regra geral para dados em falta. Com valores 20 e 40 no primeiro ficheiro, e 100, 10 e 80 no segundo:

| Linha | Primeiro         | Segundo | Média do par |
| ----- | ---------------- | ------- | ------------ |
| 1     | 20               | 100     | 60           |
| 2     | 40               | 10      | 25           |
| 3     | terminou, usar 0 | 80      | 40           |

`zip` pararia ao terminar o ficheiro mais curto e perderia a terceira linha. `zip_longest` continua até ambos terminarem:

```python
from itertools import zip_longest

with open("primeiro.txt", encoding="utf-8") as primeiro, \
        open("segundo.txt", encoding="utf-8") as segundo, \
        open("medias.txt", "w", encoding="utf-8") as destino:
    for linha_a, linha_b in zip_longest(primeiro, segundo, fillvalue="0"):
        media = (float(linha_a) + float(linha_b)) / 2
        destino.write(f"{media}\n")
```

Os ficheiros contêm um número válido por linha, sem linhas vazias, e o destino tem um nome diferente das entradas. Cada passo lê no máximo uma linha de cada ficheiro e escreve uma média, sem guardar arrays. O resultado é 60, 25 e 40, em três linhas. Se ambos estiverem vazios, o ciclo não escreve nenhuma média.
