<Exercise
  id="media-sequencial"
  revision={1}
  title="Calcular a média sem guardar a lista"
  explanation="/cadeiras/ct-iadp/ficheiros/#média-por-leitura-sequencial"
  answer={{
    kind: 'code',
    language: 'python',
    starter: 'def media_texto(texto):\n    pass',
    tests: [
      {
        name: 'Três valores',
        code: 'print(repr(media_texto("1\\n2\\n3\\n")))',
        output: '2.0',
      },
      {
        name: 'Ignora linhas em branco',
        code: 'print(repr(media_texto("4\\n\\n2\\n")))',
        output: '3.0',
      },
      {
        name: 'Sem quebra de linha final',
        code: 'print(repr(media_texto("5")))',
        output: '5.0',
      },
      {
        name: 'Sem valores',
        code: 'try:\n    media_texto("")\nexcept ValueError:\n    print("ValueError")\nelse:\n    print("Não lançou ValueError")',
        output: 'ValueError',
      },
    ],
  }}
>
  <div>
    Define <code>{'media_texto(texto)'}</code>: recebe números, um por linha, e
    devolve a média. Percorre as linhas sem guardar a lista completa. Linhas em
    branco são ignoradas. Sem valores, lança <code>{'ValueError'}</code>.
  </div>
  <div slot="hint">Trata a string como um ficheiro de texto em memória.</div>
  <div slot="hint-more">
    Acumula a soma e a contagem linha a linha; só divides no fim.
  </div>
  <div slot="solution">
    <pre>
      <code>
        {
          'from io import StringIO\n\ndef media_texto(texto):\n    soma = 0.0\n    contagem = 0\n    ficheiro = StringIO(texto)\n    for linha in ficheiro:\n        linha = linha.strip()\n        if linha == "":\n            continue\n        soma += float(linha)\n        contagem += 1\n    if contagem == 0:\n        raise ValueError("Sem valores")\n    return soma / contagem'
        }
      </code>
    </pre>
  </div>
  <div slot="mistakes">
    Guardar todas as linhas quando só precisas de soma e contagem; dividir por
    um total fixo em vez da contagem lida; esquecer o fim do ficheiro e as
    linhas em branco.
  </div>
</Exercise>

<Exercise
  id="ficheiros-media-pares"
  title="Continuar depois do ficheiro mais curto"
  explanation="/cadeiras/ct-iadp/ficheiros/#dois-ficheiros-de-comprimentos-diferentes"
  answer={{ kind: 'self', checklist: ["Obtive 60, 25 e 40 nas três linhas.", "Continuei até ambos os ficheiros terminarem, sem guardar arrays.", "Distingui fim de ficheiro, linha vazia e valor zero."] }}
>

Adaptação do problema 14.03. O primeiro ficheiro tem 20 e 40, um número por linha. O segundo tem 100, 10 e 80. Escreve o processamento sequencial que grava a média de cada par num terceiro ficheiro. Quando uma entrada já terminou, o enunciado manda usar zero.

Indica o resultado e explica por que `zip` perde uma linha. Não guardes arrays. Assume linhas numéricas não vazias e um destino diferente das entradas. O que muda se o primeiro ficheiro estiver vazio?

<div slot="hint">

A condição de paragem depende de ambos os ficheiros, não apenas do primeiro.

</div>
<div slot="solution">

```python
from itertools import zip_longest

with open("primeiro.txt", encoding="utf-8") as a, \
        open("segundo.txt", encoding="utf-8") as b, \
        open("medias.txt", "w", encoding="utf-8") as destino:
    for linha_a, linha_b in zip_longest(a, b, fillvalue="0"):
        destino.write(f"{(float(linha_a) + float(linha_b)) / 2}\n")
```

As médias são `(20 + 100)/2 = 60`, `(40 + 10)/2 = 25` e `(0 + 80)/2 = 40`. `zip` termina ao esgotar a primeira entrada e não processa 80. `zip_longest` continua com a substituição definida.

Se o primeiro ficheiro estiver vazio, o resultado é 50, 5 e 40. Um zero escrito é uma observação numérica; fim de ficheiro significa que não há outra linha; uma linha vazia viola a hipótese e não deve ser confundida com nenhum deles. Só usamos zero para o fim de uma entrada porque o problema o exige.

</div>
</Exercise>
