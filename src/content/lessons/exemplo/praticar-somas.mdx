## Compreender a soma

<Exercise
  id="soma-pares"
  title="1. Justificar a fórmula"
  explanation="/exemplo/apontamentos/#uma-ideia-de-cada-vez"
  answer={{
    kind: 'self',
    checklist: [
      'Associei o primeiro termo ao último.',
      'Cada par soma n + 1.',
      'Expliquei como contar os termos sem falhar quando n é ímpar.',
    ],
  }}
>
  <p>
    Justifica a fórmula da soma de 1 até n sem indução. O teu argumento deve
    funcionar também para n ímpar.
  </p>
  <div slot="hint">
    Escreve a soma uma vez por ordem crescente e outra por ordem decrescente.
  </div>
  <div slot="hint-more">
    Soma as duas linhas coluna a coluna. Quantas colunas tens e quanto vale cada
    uma?
  </div>
  <div slot="solution">
    Se S = 1 + 2 + … + n, então 2S = (1 + n) + (2 + n − 1) + … + (n + 1). Há n
    colunas, cada uma com soma n + 1. Logo S = n(n + 1)/2, incluindo n ímpar.
  </div>
  <div slot="mistakes">
    Dizer que há n/2 pares sem tratar o termo central quando n é ímpar. A soma
    das duas linhas evita esse problema.
  </div>
</Exercise>

## Prever e corrigir código

<Exercise id="soma-range" title="4. Prever a saída" explanation="/exemplo/apontamentos/#limites-de-um-ciclo" answer={{kind: 'number', value: 6, tolerance: 0}}>
  <p>Qual é o valor que este programa escreve?</p>

```python
total = 0
for k in range(1, 4):
    total += k
print(total)
```

  <div slot="hint">O limite superior de range não é incluído.</div>
  <div slot="hint-more">O ciclo soma os valores 1, 2 e 3.</div>
  <div slot="solution">O programa escreve 6. Não executa uma iteração com k = 4.</div>
  <div slot="mistakes">Prever 10 porque se incluiu o limite superior.</div>
</Exercise>

<Exercise
  id="soma-corrigir"
  title="6. Corrigir uma função"
  explanation="/exemplo/apontamentos/#limites-de-um-ciclo"

    kind: 'self',
    checklist: [
      'A função devolve 0 para n = 0.',
      'Inclui n na soma e devolve 1 para n = 1.',
      'Passa os quatro testes sem alterar os valores esperados.',
      'Consigo explicar por que range termina em n + 1.',
    ],
  }}
>
  <p>
    Corrige apenas a função para somar de 1 até n, com n inteiro não negativo.
    Mantém os testes. Antes de executar, prevê qual é o primeiro teste que
    falha.
  </p>
  <div slot="work">
    <CodePlayground
      language="python"
      title="Corrigir soma_naturais"
      code={
        'def soma_naturais(n):\n    total = 0\n    for k in range(1, n):\n        total += k\n    return total\n\nfor n, esperado in [(0, 0), (1, 1), (4, 10), (20, 210)]:\n    obtido = soma_naturais(n)\n    assert obtido == esperado, f"n={n}: esperado {esperado}, obtido {obtido}"\nprint("Os quatro testes passaram.")'
      }
    />
  </div>
  <div slot="hint">Verifica n = 1: quantas iterações faz o ciclo original?</div>
  <div slot="hint-more">
    O limite superior de range é exclusivo. Para incluir n, usa o inteiro
    seguinte.
  </div>
  <div slot="solution">
    Substitui range(1, n) por range(1, n + 1). O primeiro teste original que
    falha é n = 1: esperava-se 1 e obtém-se 0. Com a correção, o programa
    escreve “Os quatro testes passaram.”. Os testes são exemplos, não uma prova
    para todos os inteiros.
  </div>
  <div slot="mistakes">
    Alterar os resultados esperados para esconder a falha ou resolver só n = 1
    com um caso especial.
  </div>
</Exercise>

## Verificar limites e custo

<Exercise
  id="soma-caso-vazio"
  title="7. Explicar o caso vazio"
  explanation="/exemplo/apontamentos/#limites-de-um-ciclo"
  answer={{
    kind: 'self',
    checklist: [
      'Indiquei que o ciclo não executa nenhuma iteração.',
      'Relacionei o resultado com o valor inicial zero.',
      'Verifiquei que a fórmula também dá zero.',
    ],
  }}
>
  <p>
    Na função corrigida, por que motivo n = 0 devolve zero? Confirma o resultado
    pela fórmula e pelo ciclo.
  </p>
  <div slot="hint">Observa range(1, 1).</div>
  <div slot="hint-more">
    O conjunto de valores do ciclo é vazio, por isso total conserva o valor
    inicial.
  </div>
  <div slot="solution">
    O ciclo não executa iterações e total continua a zero. Na fórmula, 0 × (0 +
    1)/2 = 0. Os dois métodos concordam sobre a soma vazia.
  </div>
  <div slot="mistakes">
    Dizer que a função falha por não haver iterações ou confundir soma vazia com
    produto vazio.
  </div>
</Exercise>

<Exercise
  id="soma-custo"
  title="8. Comparar os dois métodos"
  explanation="/exemplo/apontamentos/#contar-as-operações"
  answer={{

      'Indiquei que esta comparação assume operações aritméticas de custo constante.',
    ],
  }}
>
  <p>
    Compara o custo do ciclo e da fórmula quando n aumenta. Que hipótese sobre o
    custo das operações estás a usar?
  </p>
  <div slot="hint">
    Conta quantas vezes cada método atualiza ou calcula um valor.
  </div>
  <div slot="hint-more">
    O ciclo repete uma soma n vezes. A fórmula não contém um ciclo, mas os
    inteiros podem crescer.
  </div>
  <div slot="solution">
    Com operações aritméticas de custo constante, o ciclo custa Θ(n) e a fórmula
    custa Θ(1). Para inteiros de precisão arbitrária, o custo de uma operação
    depende do número de bits. A conclusão Θ(1) não é uma análise do custo em
    bits.
  </div>
  <div slot="mistakes">
    Afirmar que qualquer multiplicação demora o mesmo tempo, independentemente
    do tamanho dos inteiros.
  </div>
</Exercise>
