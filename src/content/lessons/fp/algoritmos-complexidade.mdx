Queremos encontrar um valor numa lista. A primeira decisão não é escrever um ciclo, é perceber o que sabes sobre a entrada, porque a ordenação permite excluir candidatos que uma lista desordenada obrigaria a verificar.

## Pesquisa linear e pesquisa binária

A pesquisa **linear** visita os elementos por ordem até encontrar o alvo. Escolhemos neste exemplo devolver um índice, ou `None` quando o alvo falta. Essa convenção evita confundir ausência com o índice zero.

A pesquisa **binária** exige uma lista ordenada. Mantém um intervalo de candidatos, compara com o meio e conserva só a metade possível.

| Intervalo de índices | Meio e valor | Decisão ao procurar 14                   |
| -------------------- | ------------ | ---------------------------------------- |
| `[0, 6]`             | 3, valor 11  | Excluir até 3, porque 14 é maior         |
| `[4, 6]`             | 5, valor 17  | Excluir a partir de 5, porque 14 é menor |
| `[4, 4]`             | 4, valor 14  | Encontrado                               |

A condição `inicio <= fim` inclui o último candidato. Atualizar para `meio - 1` ou `meio + 1` exclui o meio que já foi comparado e garante progresso. Se o alvo faltar, o intervalo torna-se vazio. A ordenação é a razão para descartar cada metade; numa lista desordenada, essa decisão pode perder o alvo.

Com valores repetidos, esta função pode devolver qualquer posição com o alvo. Se o contrato pede a primeira, encontrar uma ocorrência ainda não chega; tens de continuar à esquerda ou usar outra estratégia.

## Contar operações

Se `n` é o comprimento da lista, a pesquisa linear faz até `n` comparações de igualdade. A binária reduz o número de candidatos aproximadamente a metade por iteração, fazendo um número de iterações proporcional a $\log_2 n$.

A notação $O(g(n))$ é um limite superior do crescimento do trabalho para entradas suficientemente grandes. Ignora constantes multiplicativas e termos de menor crescimento. Para exprimir crescimento apertado, usa-se $\Theta$; dizer apenas $O(n^2)$ não prova que um algoritmo precise de trabalho quadrático.

| Crescimento típico | Situação                                               |
| ------------------ | ------------------------------------------------------ |
| $O(1)$             | Aceder a uma posição de lista                          |
| $O(\log n)$        | Pesquisa binária numa lista ordenada                   |
| $O(n)$             | Percorrer toda a lista uma vez                         |
| $O(n\log n)$       | Ordenação por comparação como limite geral de `sorted` |
| $O(n^2)$           | Comparar todos os pares de `n` elementos               |

Isto é um complemento para comparar estratégias. O tamanho da entrada e a operação contada têm de estar definidos. Os inteiros Python podem ter tamanho arbitrário; tratar qualquer operação aritmética como constante é uma simplificação que exige valores de tamanho limitado.

## Ciclos sucessivos e aninhados

Dois percursos sucessivos de `n` elementos fazem trabalho proporcional a $2n$, portanto linear. Dois percursos aninhados, ambos de `n`, fazem $n^2$ visitas. Não é o número de ciclos escritos que decide o custo, é quantas vezes o corpo executa.

```python
n = 4
pares = 0
for i in range(n):
    for j in range(i + 1, n):
        pares += 1
print(pares)
```

A saída é 6. Há $n(n-1)/2$ pares com `i < j`, logo o crescimento é quadrático embora o ciclo interior não percorra sempre `n` posições.

## Custos das operações mais usadas

Uma fatia de `k` elementos de lista cria outra lista e custa trabalho proporcional a `k`. Inserir no início desloca elementos. `append` tem custo amortizado constante.

:::details[Ver custos com hipóteses]
Algumas inserções com `append` exigem aumentar a capacidade. Pertença numa lista pode visitar todos os elementos; num dicionário ou conjunto, espera-se custo médio constante com hipóteses adequadas sobre hashes, mas o pior caso pode ser linear.
:::

Para uma única procura, ordenar primeiro costuma acrescentar trabalho desnecessário. Para muitas procuras sobre a mesma lista, a preparação pode compensar. Uma medição em segundos compara uma implementação e um ambiente; a análise de crescimento explica o que muda quando a entrada aumenta. Nenhuma destas medidas substitui a prova de que a resposta está correta.
