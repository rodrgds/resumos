Na última página do percurso, depois de comparares o trabalho das pesquisas, esta página responde a esta pergunta: como guarda um programa dados para além do fim da execução, e como reage quando algo falha?

O resultado de um programa pode precisar de sobreviver ao fim da execução. Um ficheiro guarda esses dados, mas cria falhas novas: o caminho pode faltar ou o texto pode não representar o número esperado.

## Módulos e organização

Um módulo é normalmente um ficheiro `.py` com definições e instruções. `import math` permite usar `math.sqrt`; `from math import sqrt` introduz `sqrt` no âmbito atual. Evita `import *`, porque torna a origem dos nomes menos clara.

```python
import math

print(math.isclose(math.sqrt(2) ** 2, 2.0))
```

A saída é `True`. A comparação aceita uma pequena diferença numérica. Para separar um módulo reutilizável da execução direta, usa `if __name__ == "__main__":` junto do código de entrada e saída. Ao importar, as instruções no nível do módulo executam; esse guarda evita correr a interface de entrada como efeito da importação.

## Ler e escrever ficheiros

`open(caminho, modo, encoding="utf-8")` abre um ficheiro de texto. Um caminho relativo é interpretado a partir da pasta de trabalho do processo, não automaticamente da pasta onde está o programa.

| Modo  | Comportamento                                 |
| ----- | --------------------------------------------- |
| `"r"` | Ler; falha se o ficheiro não existir          |
| `"w"` | Criar ou substituir todo o conteúdo existente |
| `"a"` | Acrescentar no fim, criando se faltar         |
| `"x"` | Criar e falhar se o ficheiro já existir       |

`with` fecha o recurso ao sair do bloco, incluindo quando há uma exceção. `read()` lê tudo; percorrer `for linha in ficheiro` lê linha a linha; `readline()` lê a próxima linha e devolve `""` ao chegar ao fim. Uma linha em branco costuma ser `"\n"`, portanto difere do fim do ficheiro.

<CodePlayground

A saída é `[12, 16]` e `14.0` porque o programa cria o ficheiro antes de o ler. Aqui as linhas são não vazias e contêm inteiros; se o formato permitir outros casos, trata-os explicitamente.

No editor, o ficheiro existe apenas durante esta execução. Num programa local, fica no disco. `write` recebe texto, não acrescenta uma mudança de linha por si só e devolve o número de caracteres escritos.

## CSV sem dividir à mão

Um ficheiro CSV representa linhas de campos. Os campos podem conter separadores e aspas, por isso `split(",")` não é um leitor CSV completo. Usa o módulo `csv`, que conhece essas regras.

<CodePlayground
  language="python"
  title="Ler e escrever CSV"
  input=""
  code={
    'import csv\n\nwith open("alunos.csv", "w", encoding="utf-8", newline="") as ficheiro:\n    escritor = csv.writer(ficheiro)\n    escritor.writerow(["nome", "nota"])\n    escritor.writerow(["Ana, Silva", 15])\n\nwith open("alunos.csv", encoding="utf-8", newline="") as ficheiro:\n    leitor = csv.DictReader(ficheiro)\n    for linha in leitor:\n        print(linha["nome"], int(linha["nota"]))'
  }
/>

`DictReader` usa a primeira linha como nomes das colunas. O nome conserva a vírgula porque o escritor delimitou o campo. Os valores lidos são strings, por isso convertemos a nota. `newline=""` deixa o módulo tratar as mudanças de linha do formato.

## Exceções, try, except, else e finally

Uma exceção interrompe o percurso normal e procura um tratador compatível nas chamadas ativas. `try` envolve a operação que pode falhar. `except Tipo` trata esse tipo de falha. `else` corre se o corpo de `try` acabar sem exceção; `finally` corre na saída, haja ou não exceção tratada.

<CodePlayground
  language="python"
  title="Tratar entrada inválida"
  input="abc"
  code={
    'texto = input()\ntry:\n    numero = int(texto)\nexcept ValueError:\n    print("não é inteiro")\nelse:\n    print(numero * 2)\nfinally:\n    print("fim")'
  }
/>

Com `abc`, a conversão falha e a saída é `não é inteiro` seguida de `fim`. Com `12`, a saída é `24` seguida de `fim`. Um `except ValueError` não trata `ZeroDivisionError`. Escolhe o erro esperado em vez de esconder qualquer falha com `except:`.

Alguns erros comuns são `ValueError` para um valor inadequado, `TypeError` para tipos incompatíveis, `IndexError` para índices inválidos, `KeyError` para chaves em falta e `FileNotFoundError` para um ficheiro inexistente. `raise ValueError("mensagem")` comunica uma violação do contrato. Depois de uma falha, define se a operação deve pedir novos dados, ignorar a linha, devolver um sinal ou terminar; não inventes um resultado válido.

## Asserções e testes

`assert condicao` exprime uma hipótese interna e lança `AssertionError` se for falsa. Pode ser desativado ao correr Python com otimizações, por isso não o uses como única validação de entradas do utilizador.

Um teste compara o resultado real com um esperado calculado independentemente. Escolhe um caso normal, os limites e as entradas inválidas previstas pelo contrato.

```python
def media(valores):
    if not valores:
        raise ValueError("sequência vazia")
    return sum(valores) / len(valores)

assert media([10, 14]) == 12
assert media([7]) == 7
try:
    media([])
except ValueError:
    print("entrada vazia rejeitada")
else:
    raise AssertionError("devia rejeitar a entrada vazia")
```

A saída é `entrada vazia rejeitada`. O resultado 12 vem de $(10+14)/2$, não de copiar o cálculo interno para o teste. A entrada de um elemento e a entrada vazia testam decisões diferentes.

## Depurar um resultado errado

Reproduz a falha com a menor entrada útil. Segue os valores antes e depois da instrução suspeita, usando um depurador, uma tabela de execução ou `print` temporários. Confirma o primeiro ponto onde o estado diverge do esperado, porque um teste que passa num exemplo não demonstra todos os casos.

Para problemas numéricos, verifica unidades, domínio e precisão. Para coleções, verifica ordem, repetições e mutação. Para ficheiros, verifica pasta de trabalho, modo e formato antes de alterar o algoritmo de cálculo.
