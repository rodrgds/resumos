Queremos decidir se um número é perfeito. Em vez de misturar leitura, procura de divisores e apresentação, separamos o cálculo numa função que recebe um inteiro e devolve um booleano. Assim podemos testar o mesmo cálculo sem pedir dados ao utilizador.

## Definir e chamar

`def` define uma função. Os nomes na definição são **parâmetros**; os valores de uma chamada são **argumentos**. Em `quadrado(5)`, o parâmetro `x` recebe o objeto inteiro 5 e `return x * x` devolve 25.

```python
def quadrado(x):
    return x * x

print(quadrado(5))
print(quadrado(2) + quadrado(3))
```

A saída é `25` e `13`. Definir a função não executa o seu corpo. Cada chamada tem os seus nomes locais. O resultado de uma chamada pode participar noutra expressão.

## Return e print

`return` termina a chamada e entrega um valor ao chamador. `print` escreve na saída e devolve `None`. Uma função que chega ao fim sem `return`, ou executa `return` sem expressão, também devolve `None`.

```python
def saudar(nome):
    print("Olá,", nome)

resposta = saudar("Ana")
print(resposta)
```

A saída é `Olá, Ana` e depois `None`. A saudação é um efeito da chamada, não o seu resultado. Se pretendes reutilizar o texto, escreve `return "Olá, " + nome` e imprime apenas fora da função. Num exercício que pede uma função, confirma se deve devolver ou imprimir.

## Contrato e decomposição

O **contrato** indica o que a função recebe, as condições exigidas e o resultado. Uma docstring descreve esse contrato; não muda a execução.

Os divisores próprios de 6 são 1, 2 e 3, cuja soma é 6. Os de 12 somam 16, por isso 12 não é perfeito. Para 28, $1+2+4+7+14=28$. O 1 tem soma vazia de divisores próprios, igual a zero, por isso não é perfeito.

A função exterior decide; a interior resolve a soma. `n > 0 and ...` evita chamar a função interior fora da sua condição de entrada. Testamos um caso positivo, um negativo na decisão, a fronteira 1 e a entrada zero.

## Âmbito das variáveis

O **âmbito** diz onde um nome pode ser usado. Um nome atribuído dentro de uma função é normalmente local a essa função. A função procura nomes no âmbito local, nos âmbitos envolventes, no módulo e nos nomes predefinidos. Esta procura segue a estrutura do código, o **âmbito léxico**, não as variáveis locais de quem chamou.

```python
valor = 10

def dobrar(valor):
    return 2 * valor

print(dobrar(4), valor)
```

A saída é `8 10`. O parâmetro local não altera a associação global. Se atribuíres a `valor` no corpo, Python trata-o como local nesse corpo. Ler esse local antes de o definir causa `UnboundLocalError`. `global` permite reatribuir um nome do módulo, mas cria uma dependência adicional; prefere parâmetros e retorno para um cálculo.

Uma função pode conservar acesso a nomes de uma função envolvente mesmo depois de essa chamada acabar. Veremos esse comportamento, uma closure, em [programação funcional](/cadeiras/fp/programacao-funcional/#devolver-funções-e-âmbito-léxico). Por isso, não confundas âmbito com a afirmação de que todos os objetos locais são destruídos no fim da chamada.

## Passagem de argumentos e efeitos

Python associa o parâmetro ao objeto passado. Reatribuir o parâmetro muda só o nome local; alterar um objeto mutável pode afetar o chamador.

## Argumentos por nome e valores por defeito

Em `def potencia(base, expoente=2):`, podes chamar `potencia(3)` ou `potencia(base=3, expoente=4)`. Um argumento por nome identifica o parâmetro. Os parâmetros obrigatórios anteriores não deixam de ser necessários.

Os valores por defeito são calculados quando `def` executa, não em cada chamada. Uma lista usada como valor por defeito fica partilhada entre chamadas. Para criar uma lista nova quando não é passada nenhuma, usa `None` como sinal e cria-a no corpo.

```python
def juntar(valor, valores=None):
    if valores is None:
        valores = []
    return valores + [valor]

print(juntar(1), juntar(2))
```

A saída é `[1] [2]`. O `is None` testa o objeto especial `None`, que é o uso apropriado de identidade neste caso. O contrato desta função também conserva qualquer lista recebida.
