Para decidir se 6 é um número perfeito, somamos os seus divisores positivos menores que 6: $1+2+3=6$. Podemos separar essa soma da comparação com o número original. Uma **função** dá um nome a cada cálculo e permite chamá-lo com argumentos diferentes, sem repetir o código.

## Definir e chamar

`def` define uma função. Os nomes na definição são **parâmetros**; os valores de uma chamada são **argumentos**. Os dois pontos e a indentação delimitam o corpo, como num `if`. Segue `quadrado(5)`: a chamada associa `x` a 5, calcula `5 * 5` e `return` entrega 25 ao chamador.

```python
def quadrado(x):
    return x * x

print(quadrado(5))
print(quadrado(2) + quadrado(3))
```

A saída é `25` e `13`. Definir a função não executa o seu corpo. Cada chamada tem os seus nomes locais. O resultado de uma chamada pode participar noutra expressão.

## Return e print

`return` termina a chamada e entrega um valor ao chamador. `print` escreve na saída e devolve `None`. Uma função que chega ao fim sem `return`, ou executa `return` sem expressão, também devolve `None`.

```python
def saudar(nome):
    print("Olá,", nome)

resposta = saudar("Ana")
print(resposta)
```

A saída é `Olá, Ana` e depois `None`. A saudação é um efeito da chamada, não o seu resultado. Se pretendes reutilizar o texto, escreve `return "Olá, " + nome` e imprime apenas fora da função. Num exercício que pede uma função, confirma se deve devolver ou imprimir.

## Contrato e decomposição

O **contrato** indica o que a função recebe, as condições exigidas e o resultado. `soma_divisores` recebe um inteiro positivo e devolve a soma dos seus divisores próprios. `e_perfeito` recebe qualquer inteiro e devolve `False` para os não positivos. Uma docstring descreve o contrato entre aspas triplas no início do corpo; não valida a entrada.

Para 6, `range(1, 6)` visita 1, 2, 3, 4 e 5. O teste `6 % d == 0` aceita os três primeiros e rejeita 4 e 5. O acumulador termina em 6, e a função exterior compara esse resultado com a entrada. Os divisores próprios de 12 somam $1+2+3+4+6=16$, por isso 12 não é perfeito. Para 28, $1+2+4+7+14=28$. O 1 tem soma vazia de divisores próprios, igual a zero, por isso não é perfeito.

A função exterior decide; a interior resolve a soma. `n > 0 and ...` evita chamar a função interior fora da sua condição de entrada. Testamos números perfeitos, um número que não é perfeito, a fronteira 1 e a entrada zero.

Podemos reutilizar a procura de divisores para outra decisão. Um número **primo** é um inteiro maior que 1 cujos únicos divisores positivos são 1 e o próprio número. Para decidir se é primo, uma função pode procurar um divisor de 2 até `n - 1`: encontrar um basta para devolver `False`; só devolve `True` depois de excluir todos. O 2 é primo, embora esse percurso seja vazio; o 1 não é primo.

## Âmbito das variáveis

O **âmbito** diz onde um nome pode ser usado. Um nome atribuído dentro de uma função é normalmente local a essa função. A função procura nomes no âmbito local, nos âmbitos envolventes, no módulo e nos nomes predefinidos. Esta procura segue a estrutura do código, o **âmbito léxico**, não as variáveis locais de quem chamou.

```python
valor = 10

def dobrar(valor):
    return 2 * valor

print(dobrar(4), valor)
```

A saída é `8 10` porque o parâmetro local não altera a associação global. Se atribuíres a `valor` no corpo, Python trata-o como local nesse corpo. Ler esse local antes de o definir causa `UnboundLocalError`. `global` permite reatribuir um nome do módulo, mas cria uma dependência adicional; prefere parâmetros e retorno para um cálculo.

Uma função pode conservar acesso a nomes de uma função envolvente mesmo depois de essa chamada acabar. Veremos esse comportamento, uma closure, em [programação funcional](/cadeiras/fp/programacao-funcional/#devolver-funções-e-âmbito-léxico). Por isso, não confundas âmbito com a afirmação de que todos os objetos locais são destruídos no fim da chamada.

## Passagem de argumentos e efeitos

Python associa o parâmetro ao objeto passado, sem o copiar. Reatribuir o parâmetro muda só o nome local:

```python
def tentar_mudar(x):
    x = 99

n = 5
tentar_mudar(n)
print(n)
```

A saída é `5`. A chamada associa `x` a 5 e depois associa `x` a 99; o nome `n` continua associado a 5.

Alterar um objeto recebido é diferente de reatribuir o parâmetro. Uma lista permite observar essa diferença: `valores.append(99)` altera a lista partilhada, enquanto `return valores + [99]` devolve outra lista. A [lição de listas](/cadeiras/fp/tuplos-listas/#alias-contra-cópia-igualdade-contra-identidade) segue as referências num esquema. Os exercícios sobre esse caso podem ficar para depois dessa leitura.

## Argumentos por nome e valores por defeito

Em `def potencia(base, expoente=2):`, podes chamar `potencia(3)` ou `potencia(base=3, expoente=4)`. Um argumento por nome identifica o parâmetro. Os parâmetros obrigatórios anteriores não deixam de ser necessários.

Os valores por defeito são calculados quando `def` executa, não em cada chamada. Uma lista usada como valor por defeito fica partilhada entre chamadas, como verás na lição de listas. Para criar uma lista nova quando não é passada nenhuma, usa `None` como sinal e cria-a no corpo.

```python
def juntar(valor, valores=None):
    if valores is None:
        valores = []
    return valores + [valor]

print(juntar(1), juntar(2))
```

A saída é `[1] [2]`. O `is None` testa o objeto especial `None`, que é o uso apropriado de identidade neste caso. O contrato desta função também conserva qualquer lista recebida.
