<Exercise
 id="iterador-memoria"
 title="Escolher entre guardar e recalcular"
 revision={3}
 explanation="/cadeiras/fp/compreensoes-geradores/#escolher-entre-lista-e-gerador"
 answer={{kind: 'self', checklist: ['Escolhi uma lista para índice e percursos repetidos.', 'Expliquei que um gerador novo repete o cálculo.', 'Escolhi consumo progressivo para uma soma única.']}}
>

Uma transformação demorada produz pelo menos 11 resultados. Queres percorrê-los
três vezes e consultar o resultado no índice 10, sem recalcular a transformação.
Escolhes uma lista ou um gerador? Explica por que criar outro gerador não
satisfaz a última condição. Se só quisesses somar os resultados uma vez,
que escolha permitiria evitar guardá-los todos?

<div slot="solution">
Uma lista guarda os resultados, permite novos percursos e acesso por índice.
Um gerador único não permite índices nem reinicia quando esgota. Criar outro
gerador repete a transformação, contrariando o requisito de não recalcular.

Para uma soma única, `sum` pode consumir um gerador valor a valor, sem uma lista
de todos os resultados. Isso evita essa memória intermédia, mas não elimina o
trabalho da transformação. A entrada e o estado do gerador continuam a ocupar
memória.

</div>
</Exercise>

<Exercise
  id="compreensao-matriz"
  title="Filtrar numa lista de listas"
  revision={1}

  answer={{
    kind: 'code',
    language: 'python',
    starter: 'def quadrados_positivos(linhas):\n    return []',
    tests: [
      {
        name: 'Valores negativos, zero e linhas diferentes',
        code: 'print(quadrados_positivos([[-2, 3], [], [0, 4, 1]]))',
        output: '[9, 16, 1]',
      },
      {
        name: 'Sem linhas',
        code: 'print(quadrados_positivos([]))',
        output: '[]',
      },
      {
        name: 'Nenhum positivo',
        code: 'print(quadrados_positivos([[-1, 0], []]))',
        output: '[]',
      },
      {
        name: 'Repetições e decimais',
        code: 'print(quadrados_positivos([[0.5, 2], [2]]))',
        output: '[0.25, 4, 4]',
      },
      {
        name: 'Entrada preservada',
        code: 'xs = [[-2, 3], [1]]\nprint(quadrados_positivos(xs))\nprint(xs)',
        output: '[9, 1]\n[[-2, 3], [1]]',
      },
    ],
  }}
>
  <div>
    Define <code>{"quadrados_positivos(linhas)"}</code>: recebe uma lista de listas de números e
    devolve uma lista plana com os quadrados dos valores estritamente positivos.
    Percorre as linhas e os valores pela ordem original. As linhas podem ter
    comprimentos diferentes; conserva a entrada. Experimenta uma compreensão.
  </div>
  <div slot="hint">
    Há duas decisões de percurso: escolher a linha e depois o valor dessa linha.
  </div>
  <div slot="hint-more">
    Escreve primeiro for linha in linhas, depois for x in linha. O filtro x &gt;
    0 decide sobre o valor original.
  </div>
  <div slot="solution">
    O primeiro for percorre as linhas; o segundo percorre cada linha. O filtro
    exclui negativos e zero antes de calcular o quadrado. Linhas vazias não
    acrescentam valores.

```python
def quadrados_positivos(linhas):
    return [x * x for linha in linhas for x in linha if x > 0]
```

  </div>
  <div slot="mistakes">
    Filtrar o quadrado em vez do valor original, incluir zero ou assumir que
    todas as linhas têm o mesmo comprimento.
  </div>
</Exercise>

<Exercise
  id="efeito-na-compreensao"
  title="Diagnosticar uma compreensão com efeitos"
  revision={2}
  explanation="/cadeiras/fp/compreensoes-geradores/#compreensões-de-listas"
  answer={{kind: 'self', checklist: ['Previ xs como [[1, 9], [2, 9]].', 'Previ resultado como [None, None].', 'Construí listas novas e preservei a entrada na correção.']}}
>

Prevê `xs` e `resultado` depois deste trecho. Substitui a compreensão por uma que devolva `[[1, 9], [2, 9]]` e mantenha `xs` como `[[1], [2]]`. Justifica por que construir uma lista exterior nova não chega para preservar a entrada.

```python
xs = [[1], [2]]
resultado = [linha.append(9) for linha in xs]
```

<div slot="hint">Segue separadamente o efeito e o retorno de cada `append`.</div>
<div slot="solution">
`xs` passa a `[[1, 9], [2, 9]]`, porque `linha` refere cada lista interior. Cada `append` devolve `None`, logo `resultado` é `[None, None]`. A lista exterior nova guarda os retornos dessas chamadas; não desfaz os efeitos nas linhas.

Partindo novamente de `xs = [[1], [2]]`, a correção é `resultado = [linha + [9] for linha in xs]`. A concatenação cria uma lista nova por linha e não altera as listas recebidas. Com `xs = []`, o resultado é `[]`.

</div>
</Exercise>
