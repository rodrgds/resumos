<Exercise
  id="ramos-nota"
  title="Diagnosticar a ordem dos ramos"
  revision={3}
  explanation="/cadeiras/fp/condicoes-ciclos/#escolher-um-ramo"
  answer={{kind: 'self', checklist: ['Previ aprovado para 16.', 'Pus o teste mais restrito primeiro.', 'Distingui uma cadeia de dois if independentes.']}}
>

Prevê a saída para `nota = 16`. Corrige a ordem para escrever `bom` nas notas de 15 a 20 e `aprovado` nas de 10 a 14. Assume uma nota válida de 0 a 20. Explica o que aconteceria se substituísses `elif` por outro `if`.

```python
if nota >= 10:
    print("aprovado")
elif nota >= 15:
    print("bom")
else:
    print("reprovado")
```

<div slot="hint">Uma condição mais geral pode impedir a avaliação da mais restrita.</div>
<div slot="solution">
Para 16, o primeiro teste é verdadeiro e a saída é `aprovado`; o `elif` nem é avaliado. A correção testa primeiro `nota >= 15`, depois `nota >= 10`. Para 9, ambos falham e corre o `else`; para 10, só o segundo ramo é escolhido; para 15, o primeiro.

Com dois `if` independentes na versão original, 16 satisfaz ambos e escreve `aprovado` e `bom`. Nesse código, o `else` pertence ao segundo `if`, por isso 10 escreveria `aprovado` e depois `reprovado`.

</div>
</Exercise>

<Exercise
  id="while-digitos"
  title="Distinguir dígito zero de prefixo zero"
  revision={2}
  explanation="/cadeiras/fp/condicoes-ciclos/#ciclos-while-e-terminação"
  answer={{kind: 'self', checklist: ['Segui os prefixos 4072, 407, 40, 4 e 0.', 'Obtive soma 13.', 'Expliquei por que parar num dígito zero dá 9.']}}
>

Segue este programa para `n = 4072`: indica o dígito extraído, o prefixo restante e a soma em cada iteração. Um colega propõe parar quando `n % 10 == 0`. Que resultado obteria e por que está errado?

```python
soma = 0
while n > 0:
    soma += n % 10
    n //= 10
print(soma)
```

<div slot="hint">Em 40, o último dígito é zero, mas ainda falta tratar o 4.</div>
<div slot="solution">

| `n` antes | Dígito | Prefixo depois | Soma depois |
| --------- | ------ | -------------- | ----------- |
| 4072      | 2      | 407            | 2           |
| 407       | 7      | 40             | 9           |
| 40        | 0      | 4              | 9           |
| 4         | 4      | 0              | 13          |

O ciclo correto termina no prefixo zero e escreve 13. Parar no dígito zero terminaria em 40 com soma 9, perdendo o 4. A medida de progresso é o inteiro não negativo `n`, que diminui por divisão inteira em cada iteração.

</div>
</Exercise>

<Exercise
  id="else-ciclo"
  title="Distinguir encontrar de esgotar a procura"
  revision={2}
  explanation="/cadeiras/fp/condicoes-ciclos/#sentinelas-break-continue-e-else"
  answer={{kind: 'self', checklist: ['Previ encontrado só quando existe um negativo.', 'Previ nenhum tanto sem negativos como na lista vazia.', 'Expliquei que break impede else.']}}
>

Prevê a saída para `valores = [2, -1, 4]`, depois `[2, 0, 4]` e finalmente
`[]`. Um colega substitui `break` por `continue`. Que saída terá agora a
primeira lista e por que já não resolve a mesma procura?

```python
for valor in valores:
    if valor < 0:
        print("encontrado")
        break
else:
    print("nenhum")
```

<div slot="solution">
Com `[2, -1, 4]`, escreve `encontrado` e sai por `break`, sem executar o
`else`. Com `[2, 0, 4]`, percorre tudo sem negativo e escreve `nenhum`.
Com `[]`, também esgota o percurso sem `break` e escreve `nenhum`.

Substituindo por `continue`, o -1 ainda escreve `encontrado`, mas só salta o
resto dessa iteração. O percurso continua com 4 e acaba normalmente,
executando `else`: escreve também `nenhum`. O `else` não pergunta se houve
iterações ou se a condição do `if` alguma vez foi verdadeira; pergunta se
o ciclo terminou normalmente, sem `break`.

</div>
</Exercise>

  <div>
    Lê um inteiro n não negativo e escreve a soma dos múltiplos positivos de 3
    entre 1 e n, incluindo n se for múltiplo de 3. Para n = 10, somas 3 + 6 + 9
    = 18. Usa um ciclo para praticar o acumulador.
  </div>
  <div slot="hint">
    Começa a soma em zero. O último valor permitido é n.
  </div>
  <div slot="hint-more">
    Podes percorrer <code>{"range(3, n + 1, 3)"}</code>, ou percorrer todos os inteiros e testar

    O passo 3 visita só os múltiplos. O limite n + 1 permite incluir n. Quando n
    é menor que 3, o percurso é vazio e o total permanece zero.

```python
n = int(input())
total = 0
for valor in range(3, n + 1, 3):
    total += valor
print(total)
```

>

  <div>
    Define <code>soma_ate_zero(valores)</code>: soma todos os valores até ao primeiro zero, incluindo negativos, sem incluir a sentinela nem o que vem depois. Ao contrário do exemplo da lição, que filtra só positivos, aqui cada valor antes do zero conta.
  </div>
  <div slot="hint">
    Para no zero antes de somar.
  </div>
  <div slot="hint-more">
    Um filtro `if valor &gt; 0` copiado da lição chumba o teste com negativos: `[3, -2, 0]` deve dar 1, não 3. Soma cada valor antes do zero sem filtrar.
  </div>
  <div slot="solution">
    Percorre a lista e interrompe no zero. Para `[3, 5, 0, 9]`, a soma passa por 0, 3 e 8. Para `[3, -2, 0, 9]`, passa por 0, 3 e 1.

```python
def soma_ate_zero(valores):
    soma = 0
    for valor in valores:
        if valor == 0:
            break
        soma += valor
    return soma
```

  </div>
  <div slot="mistakes">
    Somar o zero da sentinela; continuar a somar depois do zero; filtrar só positivos e ignorar negativos.
  </div>

</Exercise>

<Exercise

  title="Construir uma representação noutra base"

  answer={{

    tests: [
      { name: 'Zero tem um dígito', code: 'print(repr(representar(0, 2)))', output: "'0'" },
      { name: 'Restos por ordem inversa', code: 'print(repr(representar(13, 2)))', output: "'1101'" },
      { name: 'Zeros interiores', code: 'print(repr(representar(100, 10)))', output: "'100'" },
      { name: 'Outra base', code: 'print(repr(representar(46, 7)))', output: "'64'" },
      { name: 'Um dígito', code: 'print(repr(representar(5, 6)))', output: "'5'" },
    ],

>

Define `representar(n, base)`: recebe um inteiro não negativo e uma base inteira
de 2 a 10, incluindo os extremos. Devolve uma string com a representação de `n`
nessa base, sem zeros à esquerda, exceto o próprio zero, que se representa por
`"0"`. Usa divisões sucessivas com resto. Justifica por que a ordem dos restos
difere da ordem dos dígitos no resultado.

<div slot="hint">O primeiro resto é o dígito das unidades, independentemente da base.</div>
<div slot="solution">
Cada resto fica entre zero e `base - 1`, portanto cabe num único carácter
decimal para as bases permitidas. Retiramos esse dígito do prefixo e
acrescentamo-lo à esquerda do texto já construído.

```python
def representar(n, base):
    if n == 0:
        return "0"
    resultado = ""
    while n > 0:
        resultado = str(n % base) + resultado
        n //= base
    return resultado
```

Para 46 em base 7, o primeiro resto é 4 e o quociente 6; o segundo resto é 6
com quociente zero. O texto final é `"64"`, pois $6\times7+4=46$.
A medida `n` diminui quando é positiva porque a base é pelo menos 2.
Sem o caso de zero, a função devolveria uma string vazia. Concatenar os restos
à direita daria a ordem errada para 13 em base 2, `"1011"`.

</div>
</Exercise>
