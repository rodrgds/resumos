<Exercise
 id="assert-entrada"
 title="Separar validação de asserção interna"
 revision={2}
 explanation="/cadeiras/fp/ficheiros-excecoes/#asserções-e-testes"
 answer={{kind: 'self', checklist: ['Expliquei que -1 é aceite se asserções forem desativadas.', 'Usei uma condição com ValueError.', 'Validei o intervalo completo de 0 a 20.']}}
>

Uma função recebe uma nota inteira de um utilizador. O contrato exige 0 a 20 e
manda lançar `ValueError` fora desse intervalo. Diagnostica esta implementação
para -1 e 21, e explica o que muda quando Python corre com asserções desativadas.
Corrige a validação.

```python
def validar_nota(nota):
    assert nota >= 0
    return nota
```

<div slot="solution">
Com asserções ativas, -1 lança `AssertionError`, que já difere do erro pedido;
21 passa porque o limite superior não é verificado. Com asserções desativadas,
ambos chegam ao retorno. A validação necessária deve ser explícita:

```python
def validar_nota(nota):
    if not 0 <= nota <= 20:
        raise ValueError("nota fora de 0 a 20")
    return nota
```

Os extremos 0 e 20 são válidos. A condição rejeita -1 e 21 em ambos os modos.
`assert` continua útil para hipóteses internas e testes, cujo funcionamento não
se confunde com a validação exigida pelo contrato.

</div>
</Exercise>

      },
      {

        output: "1\n['4', 'erro', '-3']",
      },
    ],
  }}
>
  <div>
    Define <code>{"soma_validos(linhas)"}</code>: recebe uma lista de strings, soma as que <code>{"int"}</code>
    consegue converter e ignora apenas as que levantam <code>{"ValueError"}</code>. Aceita
    números negativos, espaços em torno do inteiro e zero. Devolve a soma sem
    imprimir.
  </div>
  <div slot="hint">
    A conversão pode levantar <code>{"ValueError"}</code>.
  </div>
  <div slot="hint-more">
    Coloca a conversão em try. Acumula só depois de obter um inteiro.
  </div>
  <div slot="solution">
    As entradas válidas do primeiro caso são 3, -1 e 4, cuja soma é 6. O
    tratador salta a string x. Os testes públicos não provam que só <code>{"ValueError"}</code> é
    tratado; confere também esse requisito na solução.

```python
def soma_validos(linhas):
    total = 0
    for linha in linhas:
        try:
            numero = int(linha)
        except ValueError:
            continue
        total += numero
    return total
```

  </div>
  <div slot="mistakes">
    Usar <code>{"isdigit"}</code> e perder negativos ou sinais, converter primeiro em float e
    aceitar decimais, ou esconder todas as exceções.
  </div>
</Exercise>

        output: 'ficheiro em falta',
      },
    ],
  }}
>
  <div>
    Define <code>{"ler_inteiros(caminho)"}</code>: lê um ficheiro UTF-8 com um inteiro por linha
    e devolve uma lista pela ordem do ficheiro. Ignora linhas só com espaços ou
    mudanças de linha. As restantes linhas são inteiros válidos. Conserva o
    conteúdo; deixa <code>{"FileNotFoundError"}</code> propagar se o caminho faltar.
  </div>
  <div slot="hint">
    Percorrer o ficheiro com for termina no fim, sem confundir uma linha em
    branco com esse fim.
  </div>
  <div slot="hint-more">
    Abre com with em modo de leitura. Aplica strip à linha e só converte se
    restar texto.
  </div>
  <div slot="solution">
    strip remove espaços e mudanças de linha. Uma linha em branco é ignorada,
    mas o for continua. O modo r conserva o conteúdo; with fecha o ficheiro
    mesmo se a leitura falhar.

```python
def ler_inteiros(caminho):
    resultado = []
    with open(caminho, "r", encoding="utf-8") as ficheiro:
        for linha in ficheiro:
            texto = linha.strip()
            if texto:
                resultado.append(int(texto))
    return resultado
```

  </div>
  <div slot="mistakes">
    Abrir com w, parar na primeira linha em branco ou devolver uma lista vazia
    para esconder um caminho inexistente.
  </div>
</Exercise>

<Exercise
  id="try-else-return"
  title="Seguir return e finally"
  revision={2}
  explanation="/cadeiras/fp/ficheiros-excecoes/#exceções-try-except-else-e-finally"
  answer={{kind: 'self', checklist: ['Previ fim seguido de 12 na versão original.', 'Expliquei que return salta else e executa finally.', 'Movi o return para else e previ sucesso, fim e 12.']}}
>

Prevê a saída completa. Depois move `return numero` para o fim de `else` e prevê a nova saída. Compara também a entrada `"abc"` nas duas versões.

```python
def converter(texto):
    try:
        numero = int(texto)
        return numero
    except ValueError:
        return None
    else:
        print("sucesso")
    finally:
        print("fim")

print(converter("12"))
```

<div slot="hint">O retorno sai da função, mas o bloco `finally` executa antes dessa saída.</div>
<div slot="solution">
Na versão original, o `return` dentro de `try` salta `else`. A saída é `fim` e depois `12`, porque `finally` corre antes de a função entregar o resultado ao `print` exterior.

Movendo o retorno para depois de `print("sucesso")` no `else`, `try` acaba normalmente. A saída passa a `sucesso`, `fim` e `12`, por essa ordem. Com `"abc"`, a conversão lança `ValueError`; nas duas versões, `except` devolve `None` depois de executar `finally`. A saída é `fim` e depois `None`.

</div>
</Exercise>
