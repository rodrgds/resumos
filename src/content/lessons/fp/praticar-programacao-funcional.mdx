<Exercise
 id="ordem-superior-aplicar"
 title="Passar a função ou o seu resultado"
 revision={2}
 explanation="/cadeiras/fp/programacao-funcional/#funções-são-valores"
 answer={{kind: 'self', checklist: ['Obtive 8 na primeira chamada.', 'Identifiquei o inteiro 5 na segunda chamada.', 'Expliquei o TypeError ao tentar chamar 5.']}}
>

Prevê o resultado da primeira chamada e explica a falha da segunda. Não
alteres as definições; corrige apenas o argumento da chamada que falha.

```python
def f(x):
    return x + 3

def aplicar_duas_vezes(funcao, x):
    return funcao(funcao(x))

print(aplicar_duas_vezes(f, 2))
print(aplicar_duas_vezes(f(2), 2))
```

<div slot="solution">
A primeira chamada calcula `f(f(2))`, isto é, `f(5)`, e escreve 8. Na segunda,
Python calcula `f(2)` antes de entrar em `aplicar_duas_vezes`, passando o inteiro
5 como `funcao`. Ao tentar executar `funcao(x)`, lança `TypeError`: esse inteiro
não é chamável. Passar `f` em vez de `f(2)` entrega o objeto função e corrige a
chamada.
</div>
</Exercise>

<Exercise

  answer={{
    kind: 'code',
    language: 'python',
    starter: 'def classificacao(alunos):\n    return alunos',
    tests: [
      {
        name: 'Desempatar pelo nome',
        code: 'print(classificacao([("B", 10), ("C", 12), ("A", 12)]))',
        output: "[('A', 12), ('C', 12), ('B', 10)]",
      },
      { name: 'Lista vazia', code: 'print(classificacao([]))', output: '[]' },
      {
        name: 'Notas diferentes',
        code: 'print(classificacao([("A", 0), ("B", 20), ("C", 10)]))',
        output: "[('B', 20), ('C', 10), ('A', 0)]",
      },
      {
        name: 'Entrada preservada',
        code: 'xs = [("B", 10), ("A", 12)]\nprint(classificacao(xs))\nprint(xs)',
        output: "[('A', 12), ('B', 10)]\n[('B', 10), ('A', 12)]",
      },
    ],
  }}
>
  <div>
    Define <code>{"classificacao(alunos)"}</code>: recebe uma lista de pares (nome, nota) e
    devolve uma lista por nota decrescente e, nos empates, nome crescente.
    Conserva a entrada. Procura uma <code>{"key"}</code> que represente as duas regras; os testes
    verificam o comportamento.
  </div>
  <div slot="hint">
    Uma chave em tuplo compara o primeiro campo e usa o segundo para desempatar.
  </div>
  <div slot="hint-more">
    Nega só a nota. O nome deve continuar crescente.
  </div>
  <div slot="solution">
    O negativo da nota coloca notas maiores primeiro. O nome conserva a ordem
    crescente. <code>{"sorted"}</code> devolve outra lista, sem alterar alunos.

```python
def classificacao(alunos):
    return sorted(alunos, key=lambda aluno: (-aluno[1], aluno[0]))
```

  </div>
  <div slot="mistakes">
    Usar <code>{"reverse=True"}</code> na chave completa e inverter também os nomes, ou usar <code>{"sort"}</code>
    e alterar a entrada.
  </div>
</Exercise>

<Exercise
  id="map-filter-fold"
  title="Comparar a ordem de seleção e transformação"
  revision={2}
  explanation="/cadeiras/fp/programacao-funcional/#map-filter-e-reduce"
  answer={{kind: 'self', checklist: ['Obtive 10 ao filtrar positivos antes dos quadrados.', 'Obtive 14 ao filtrar quadrados positivos.', 'Distingui seleção por sinal de seleção por paridade.']}}
>

Com `valores = [-2, 1, 3]`, calcula a soma dos quadrados depois de filtrar os valores positivos. Compara com elevar todos ao quadrado e só depois filtrar os resultados positivos. Segue o acumulador de `reduce`, com inicial 0. Esta mudança de ordem também muda os elementos aceites se o filtro selecionar ímpares?

<div slot="hint">O quadrado perde o sinal, mas conserva a paridade de um inteiro.</div>
<div slot="solution">
Ao filtrar positivos primeiro, aceitamos `[1, 3]`, obtemos `[1, 9]` e o acumulador passa por 0, 1, 10. Ao transformar primeiro, obtemos `[4, 1, 9]`: os três quadrados são positivos e o acumulador passa por 0, 4, 5, 14. O valor -2, originalmente rejeitado, passou a ter quadrado positivo.

Para inteiros, `x` é ímpar exatamente quando `x * x` é ímpar. O filtro de paridade aceita os mesmos elementos nas duas ordens; neste exemplo, rejeita -2 e conserva 1 e 3. Não podemos transferir o contraexemplo do sinal para a paridade.

</div>
</Exercise>

<Exercise
  id="closure-fator"
  title="Distinguir contextos de funções"
  revision={2}
  explanation="/cadeiras/fp/programacao-funcional/#devolver-funções-e-âmbito-léxico"
  answer={{kind: 'self', checklist: ['Previ [30, 30, 30] na primeira versão.', 'Usei multiplicador para criar contextos diferentes.', 'Obtive [10, 20, 30] depois da correção.']}}
>

Prevê a saída e explica por que não é `[10, 20, 30]`. Usa a função `multiplicador(fator)` da lição para obter esse resultado, sem alterar a chamada final.

```python
funcoes = [lambda x: fator * x for fator in range(1, 4)]
print([f(10) for f in funcoes])
```

<div slot="solution">
A saída é `[30, 30, 30]`: as lambdas consultam o mesmo nome `fator`, cujo valor final é 3. A criação de uma função não congela automaticamente esse valor.

Com `funcoes = [multiplicador(fator) for fator in range(1, 4)]`, cada chamada a `multiplicador` cria o seu próprio parâmetro local. As funções devolvidas conservam 1, 2 e 3 em contextos diferentes. A chamada final produz `[10, 20, 30]`.

</div>
</Exercise>

<Exercise
  id="reducao-acumulador"
  title="Seguir o acumulador"
  revision={2}
  explanation="/cadeiras/fp/programacao-funcional/#map-filter-e-reduce"
  answer={{
    kind: 'code',
    language: 'python',
    starter: 'from functools import reduce\ndef soma_quadrados_impares(valores):\n    return 0',
    tests: [
      { name: 'Exemplo', code: 'print(soma_quadrados_impares([1, 2, 3, 4, 5]))', output: '35' },
      { name: 'Vazia', code: 'print(soma_quadrados_impares([]))', output: '0' },
      { name: 'Só pares', code: 'print(soma_quadrados_impares([2, 4]))', output: '0' },
      { name: 'Ímpares negativos', code: 'print(soma_quadrados_impares([-3, -2, 1]))', output: '10' },
    ],
  }}
>

  <div>
    Define <code>soma_quadrados_impares(valores)</code>: recebe uma lista de
    inteiros e devolve a soma dos quadrados dos ímpares, incluindo os negativos.
    A soma vazia é zero. Usa `filter`, `map` e `reduce`, sem alterar a entrada.
    Para `[1, 2, 3, 4, 5]`, indica também os estados do acumulador.
  </div>
  <div slot="hint">
    Filtra ímpares, eleva ao quadrado e acumula de zero.
  </div>
  <div slot="hint-more">
    Sem valor inicial, `reduce` falha na lista vazia; com inicial 0, a entrada
    vazia devolve 0. Um inteiro negativo também pode ser ímpar: `-3 % 2` vale 1.
  </div>
  <div slot="solution">
    O filtro dá 1, 3, 5; os quadrados dão 1, 9, 25; o acumulador passa por 1, 10 e 35.

```python
from functools import reduce

def soma_quadrados_impares(valores):
    impares = filter(lambda x: x % 2 != 0, valores)
    quadrados = map(lambda x: x * x, impares)
    return reduce(lambda acumulado, x: acumulado + x, quadrados, 0)
```

  </div>
  <div slot="mistakes">
    Omitir o valor inicial e falhar na lista vazia; usar `x % 2 == 1 and x > 0`
    e perder os ímpares negativos. Elevar ao quadrado conserva a paridade de
    inteiros, por isso trocar essas duas etapas não é, por si só, um erro neste problema.
  </div>

</Exercise>
