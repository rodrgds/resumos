<Exercise
  id="recursao-digitos"
  title="Analisar a redução de um inteiro"
  revision={2}
  explanation="/cadeiras/fp/recursao/#recursão-sobre-dígitos"
  answer={{kind: 'self', checklist: ['Expandi as chamadas 9008, 900, 90, 9 e 0.', 'Obtive 17 e distingui dígito zero de caso base.', 'Expliquei por que -1 // 10 é -1.']}}
>

Usa a função `soma_digitos` da lição para expandir `soma_digitos(9008)` até ao caso base e obter o resultado. Explica por que os zeros interiores não param a recursão. O que acontece com `soma_digitos(-1)` se ignorarmos a pré-condição de entrada não negativa?

<div slot="hint">Python arredonda `//` para baixo também com números negativos.</div>
<div slot="solution">
A expansão é `8 + (0 + (0 + (9 + soma_digitos(0))))`. O caso base devolve 0 e o resultado é 17. Os prefixos são 9008, 900, 90, 9 e 0; só o último é zero.

Para -1, `-1 // 10` vale -1. A chamada repete a mesma entrada sem chegar a zero e acaba em `RecursionError`. Para aceitar negativos, podemos converter a entrada com `abs` antes de aplicar esta redução; para os rejeitar, podemos lançar `ValueError` numa função de validação.

</div>
</Exercise>

        output: '10\n[1, [2, [3]], 4]',
      },
    ],
  }}
>
  <div>
    Define <code>{"soma_aninhada(xs)"}</code>: devolve a soma de todos os números nas listas,
    mesmo dentro de outras listas. O domínio contém apenas números e listas
    finitas sem referências cíclicas. Conserva a entrada. Pratica a decomposição
    recursiva; os testes verificam o resultado e a preservação dos dados.
  </div>
  <div slot="hint">
    Um número contribui diretamente. Uma lista coloca o mesmo problema num nível
    interior.
  </div>
  <div slot="hint-more">
    Percorre os elementos. Se <code>{"isinstance(x, list)"}</code>, soma o resultado de
    <code>{"soma_aninhada(x)"}</code>; caso contrário, soma x.
  </div>
  <div slot="solution">
    Cada lista vazia devolve zero. Na primeira entrada, a chamada exterior junta
    1, a soma interior 5, a soma vazia 0 e 4, produzindo 10. Cada chamada tem o
    seu acumulador.

```python
def soma_aninhada(xs):
    total = 0
    for x in xs:
        if isinstance(x, list):
            total += soma_aninhada(x)
        else:
            total += x
    return total
```

  </div>
  <div slot="mistakes">
    Tratar apenas um nível, devolver antes de acabar o percurso ou retirar
    elementos da entrada.
  </div>
</Exercise>

<Exercise
  id="medida-e-base"
  title="Identificar base e medida"
  revision={2}
  explanation="/cadeiras/fp/recursao/#justificar-que-termina"
  answer={{ kind: 'self', checklist: ['Indiquei o caso base de soma_digitos.', 'Indiquei a medida que diminui.', 'Expliquei porque fib repete trabalho.'] }}
>

Para `soma_digitos`, com entrada inteira não negativa, indica o caso base e uma
medida que diminui em cada chamada fora dele. Para a árvore de `fib(4)` da
lição, conta as chamadas a `fib(2)` e explica que trabalho um ciclo evita.

<div slot="hint">
  Segue `n // 10` até zero; conta os ramos repetidos da árvore.
</div>
<div slot="hint-more">
  Desenha a árvore de `fib(4)`: `fib(3)` e `fib(2)` no primeiro nível; `fib(2)`
  aparece uma vez de cada lado. Conta quantas vezes cada chamada se repete antes
  de responder.
</div>
<div slot="solution">
  O caso base é `n == 0` com soma 0. A medida é o valor inteiro `n`; a chamada
  seguinte recebe `n // 10`, que é menor quando `n > 0` e continua não negativo.
  Em `fib(4)`, `fib(2)` corre duas vezes e `fib(1)` três vezes. Um ciclo conserva
  os dois valores anteriores e calcula cada novo valor uma vez, sem reconstruir
  as mesmas subárvores.
</div>
<div slot="mistakes">
  Confundir o dígito extraído com o prefixo restante; contar apenas entradas
  distintas e esquecer que duas chamadas com a mesma entrada repetem o cálculo.
</div>

</Exercise>

      { name: 'Mesma chave em vários ramos', code: 'print(sorted(contar_folhas(["a", ["b", "a"], [], [["b", "a"]]]).items()))', output: "[('a', 3), ('b', 2)]" },

      { name: 'Entrada intacta', code: 'xs = ["a", ["a", "b"]]\nprint(sorted(contar_folhas(xs).items()))\nprint(xs)', output: "[('a', 2), ('b', 1)]\n['a', ['a', 'b']]" },
    ],
  }}
>

Define `contar_folhas(xs)`: recebe uma lista finita, sem referências cíclicas,
cujos elementos são strings ou listas com a mesma regra. Devolve um dicionário
com a frequência de cada string em todos os níveis. Uma string vazia conta
como qualquer outra; maiúsculas distinguem valores. Conserva a entrada.
Constrói a solução recursivamente e explica como juntas as contagens de duas
sublistas que contêm a mesma string.

<div slot="hint">Substituir um dicionário por outro não soma as frequências.</div>
<div slot="solution">
Cada chamada começa com um dicionário próprio. Uma folha acrescenta 1 à sua
chave. Uma sublista devolve contagens, que acrescentamos chave a chave ao
resultado exterior. A lista vazia devolve `{}` e não contribui com folhas.

```python
def contar_folhas(xs):
    resultado = {}
    for elemento in xs:
        if isinstance(elemento, list):
            contagens = contar_folhas(elemento)
            for chave, quantidade in contagens.items():
                resultado[chave] = resultado.get(chave, 0) + quantidade
        else:
            resultado[elemento] = resultado.get(elemento, 0) + 1
    return resultado
```

Na primeira entrada, os ramos interiores contribuem com `{'b': 1, 'a': 1}`
cada um. Somando também a folha exterior `"a"`, obtemos três ocorrências de
`"a"` e duas de `"b"`. `update` sozinho substituiria valores comuns e perderia
as contagens anteriores. A chamada só desce para uma sublista própria, por
isso a estrutura finita sem ciclos garante a redução. Strings são hashable,
o que permite usá-las como chaves.

</div>
</Exercise>

    ],
  }}
>

Define `avaliar(expr)`: a expressão é um inteiro ou um tuplo
`(esquerda, operador, direita)`, onde cada operando é uma expressão válida e
`operador` é `"+"`, `"-"` ou `"*"`. A árvore é finita. Devolve o resultado inteiro
sem alterar a expressão nem usar `eval`. Explica a ordem de avaliação de
`(1, "-", (3, "-", 8))`.

<div slot="hint">O tuplo diz como combinar os resultados dos dois operandos.</div>
<div slot="solution">
Um inteiro já é um valor. Num tuplo, cada chamada recursiva resolve um
operando, e só depois aplicamos a operação exterior.

```python
def avaliar(expr):
    if isinstance(expr, int):
        return expr
    esquerda, operador, direita = expr
    a = avaliar(esquerda)
    b = avaliar(direita)
    if operador == "+":
        return a + b
    if operador == "-":
        return a - b
    return a * b
```

Na expressão pedida, o operando direito vale $3-8=-5$. A subtração exterior
é $1-(-5)=6$, e não $(1-3)-8=-10$. A forma da árvore determina os
agrupamentos. O último ramo usa multiplicação porque o contrato já garante
que só existem os três operadores permitidos. Cada chamada trata uma
subárvore própria; uma folha termina diretamente.

</div>
</Exercise>

      { name: 'Não reutilizar uma posição', code: 'print(soma_exata([3], 6))', output: 'False' },
      { name: 'Posições diferentes com preços iguais', code: 'print(soma_exata([3, 3], 6))', output: 'True' },
      { name: 'Escolha vazia', code: 'print(soma_exata([], 0), soma_exata([2, 4], 0), soma_exata([], 1))', output: 'True True False' },
      { name: 'Sem solução e entrada intacta', code: 'xs = [6, 4, 3]\nprint(soma_exata(xs, 8))\nprint(xs)', output: 'False\n[6, 4, 3]' },
    ],
  }}
>

Define `soma_exata(precos, alvo)`: os preços são uma lista de inteiros
estritamente positivos e o alvo é um inteiro não negativo. Devolve `True` se
algumas posições, cada uma usada no máximo uma vez, somam exatamente o alvo.
A escolha vazia soma zero. Posições diferentes podem ter o mesmo preço.
Conserva a entrada e usa uma decomposição recursiva que considere escolher
ou ignorar a primeira posição. Explica por que ordenar e escolher sempre o
maior não basta.

<div slot="solution">
Testamos alvo zero antes de rejeitar a lista vazia. Nos restantes casos,
retiramos a primeira posição nos dois ramos. O primeiro tenta usá-la e reduz
o alvo; o segundo ignora-a. O `or` aceita se algum ramo tiver sucesso.

```python
def soma_exata(precos, alvo):
    if alvo == 0:
        return True
    if alvo < 0 or not precos:
        return False
    return (soma_exata(precos[1:], alvo - precos[0])
            or soma_exata(precos[1:], alvo))
```

Com `[6, 4, 3]` e alvo 7, o ramo que escolhe 6 falha, mas ignorá-lo permite
somar 4 e 3. Para alvo 8, as somas possíveis são 0, 3, 4, 6, 7, 9, 10 e 13;
nenhuma é 8. Com `[3]`, não podemos usar a mesma posição duas vezes;
`[3, 3]` tem duas posições e permite formar 6.

Cada chamada tem uma lista mais curta e as fatias não alteram a entrada.
Essa redução garante terminação, mas cria cópias e pode explorar um número
exponencial de subconjuntos. A condição `alvo < 0` só é válida porque todos
os preços são positivos.

</div>
</Exercise>
