Uma função pode calcular um resultado sem alterar os argumentos, sem escrever no ecrã e sem depender de um contador global. Esta separação permite comparar duas chamadas pelos valores que recebem e devolvem.

## Funções livres de efeitos

Uma função **pura** devolve o mesmo resultado para os mesmos argumentos e não tem efeitos observáveis fora do cálculo. Ler a hora, pedir entrada, imprimir, alterar uma lista recebida ou atualizar estado global quebra essa condição.

`sorted(notas)` cria outra lista, enquanto `notas.sort()` altera a existente. Uma solução livre de efeitos devolve os dados transformados e deixa a apresentação para outra parte do programa.

```python
def com_bonus(notas, bonus):
    return [nota + bonus for nota in notas]

notas = [10, 14]
print(com_bonus(notas, 2))
print(notas)
```

A saída é `[12, 16]` e `[10, 14]`. A expressão `[nota + bonus for nota in notas]` constrói uma lista calculando `nota + bonus` para cada entrada. Esta forma, uma compreensão, será estudada na próxima lição. Para já, observa o contrato: cada resultado depende dos argumentos e as notas originais permanecem iguais.

Python permite misturar estilos. Alterar um acumulador local não prova, por si só, um efeito observável no chamador. Se um exercício exige um estilo sem atribuições nem mutação, esse requisito é mais restrito do que apenas preservar os argumentos. Nesse caso, usa operações sobre valores e funções de ordem superior em vez de atualizar uma coleção.

## Funções são valores

O nome de uma função pode ser guardado, passado ou devolvido. `quadrado` é o objeto função; `quadrado(3)` é o resultado da chamada. Passar `quadrado(3)` onde se espera uma função passa o número 9 e impede a chamada posterior.

```python
def quadrado(x):
    return x * x

def aplicar_duas_vezes(funcao, x):
    return funcao(funcao(x))

print(aplicar_duas_vezes(quadrado, 2))
```

O resultado é 16: primeiro 2 passa a 4, depois 4 passa a 16. Uma função que recebe ou devolve outras funções é uma **função de ordem superior**. Um **predicado** é uma função usada para decidir se um valor satisfaz uma condição, como `x > 0`.

## Funções de ordem superior e lambda

`lambda x: x * x` cria uma função com uma expressão como corpo. Não é uma instrução para executar já. Usa `def` quando precisas de vários passos ou quando dar um nome à operação ajuda a ler.

A chave é um tuplo. As chaves são `(-15, "Ana")`, `(-12, "Bruno")` e `(-15, "Carla")`. Python compara primeiro o primeiro campo e só usa o segundo se houver empate. Como -15 é menor que -12, o negativo da nota põe as notas maiores primeiro; o nome desempata por ordem crescente. A entrada permanece igual. `sorted` é estável: elementos com chaves iguais conservam a ordem relativa que tinham na entrada.

## Map, filter e reduce

`map(f, xs)` aplica `f` a cada elemento. `filter(p, xs)` conserva os elementos para os quais o predicado `p` dá um valor verdadeiro. Em Python 3, ambos devolvem iteradores; `list` materializa os resultados.

`reduce`, de `functools`, combina os elementos da esquerda para a direita com um acumulador. Com valor inicial `z` e elementos `a`, `b`, `c`, calcula `f(f(f(z, a), b), c)`. Esse percurso também se chama fold à esquerda. Sem valor inicial, a primeira entrada torna-se o acumulador e a sequência vazia causa `TypeError`.

<CodePlayground

O filtro conserva 1, 3 e 5. A transformação produz 1, 9 e 25. O fold começa em zero e passa por 1, 10 e 35. O valor inicial também define a resposta para a entrada vazia. Para somar, `sum` é uma alternativa direta; aqui usamos `reduce` para seguir o acumulador.

A ordem importa se a operação não for associativa. `reduce(lambda a, x: a - x, [2, 3], 10)` calcula `(10 - 2) - 3`, que vale 5. Não calcula `10 - (2 - 3)`.

## Devolver funções e âmbito léxico

Uma função interior pode conservar acesso ao contexto onde foi criada. Chamamos **closure** a essa combinação de função e contexto.

<CodePlayground
  language="python"
  title="Construir funções com um parâmetro fixo"
  input=""
  code={
    'def multiplicador(fator):\n    def multiplicar(x):\n        return fator * x\n    return multiplicar\n\ndobro = multiplicador(2)\ntriplo = multiplicador(3)\nprint(dobro(5), triplo(5))'
  }
/>

As duas funções conservam fatores diferentes. `return multiplicar` devolve a função, sem a chamar. Depois de `multiplicador` regressar, o fator de cada contexto continua acessível.

A closure consulta as associações dos nomes conservados, não tira automaticamente uma fotografia do seu valor. Criar várias lambdas sobre um único contador que continua a mudar pode fazê-las observar o mesmo valor final. Se precisares de fixar cada valor, passa-o a uma função criadora como neste exemplo, ou usa um parâmetro por defeito deliberado.

## Compor sem perder o contrato

Para compor `f` e `g`, calculamos primeiro `g(x)` e passamos esse resultado a `f`. A função devolvida conserva ambas:

```python
def compor(f, g):
    return lambda x: f(g(x))

quadrado_depois = compor(lambda x: x * x, lambda x: x + 1)
incremento_depois = compor(lambda x: x + 1, lambda x: x * x)
print(quadrado_depois(3), incremento_depois(3))
```

A saída é `16 10`: $(3+1)^2$ difere de $3^2+1$. O resultado de `g` tem de ser uma entrada válida para `f`.

Transformar, filtrar e acumular são decisões diferentes. A ordem pode mudar o resultado: elevar ao quadrado antes de filtrar os positivos conserva quadrados de valores originalmente negativos. Escreve primeiro a condição sobre os dados de entrada, depois escolhe a sequência de operações. Uma função chamada por `map` ou `filter` também deve respeitar a ausência de efeitos quando esse é o contrato do programa.
