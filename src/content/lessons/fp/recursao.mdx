Uma função pode resolver um problema usando a solução de uma versão mais pequena do mesmo problema. Reduz a entrada até um caso que resolves diretamente e depois combina os resultados no regresso.

## O modelo da recursão

O **fatorial** de `n` é o produto dos inteiros de 1 até `n`. Por exemplo, $4!=4\times3\times2\times1=24$. Para um inteiro não negativo, $0!=1$ e $n!=n\times(n-1)!$ quando $n>0$. Esta relação dá o caso base e o passo recursivo.

<CodePlayground
  language="python"
  title="Calcular um fatorial"
  code={
    'def fatorial(n):\n    if n < 0:\n        raise ValueError("n deve ser não negativo")\n    if n == 0:\n        return 1\n    return n * fatorial(n - 1)\n\nprint(fatorial(0))\nprint(fatorial(4))'
  }
/>

Para calcular `fatorial(4)`, ficam pendentes as multiplicações por 4, 3, 2 e 1. Quando `fatorial(0)` devolve 1, as chamadas regressam pela ordem inversa. Segue a pilha:

| Profundidade | Chamada ativa | Trabalho pendente                     |
| ------------ | ------------- | ------------------------------------- |
| 1            | `fatorial(4)` | `4 * ...`                             |
| 2            | `fatorial(3)` | `4 * (3 * ...)`                       |
| 3            | `fatorial(2)` | `4 * (3 * (2 * ...))`                 |
| 4            | `fatorial(1)` | `4 * (3 * (2 * (1 * ...)))`           |
| 5            | `fatorial(0)` | devolve 1, depois combina 1, 2, 6, 24 |

| Chamada       | Resultado que espera  | Valor devolvido |
| ------------- | --------------------- | --------------- |
| `fatorial(0)` | Nenhum, é o caso base | 1               |
| `fatorial(1)` | `1 * fatorial(0)`     | 1               |
| `fatorial(2)` | `2 * fatorial(1)`     | 2               |
| `fatorial(3)` | `3 * fatorial(2)`     | 6               |
| `fatorial(4)` | `4 * fatorial(3)`     | 24              |

Cada chamada tem o seu parâmetro `n`. A **pilha de chamadas** conserva essas chamadas e o trabalho pendente. `return` devolve o resultado de cada uma. Esquecer o `return` do passo recursivo pode deixar a função exterior devolver `None`.

## Justificar que termina

Para `n` não negativo, cada chamada reduz `n` em um. Essa quantidade não pode diminuir para sempre sem chegar a zero. Um caso base por si só não chega: `return n * fatorial(n)` não se aproxima dele. A validação dos negativos evita afastar-se de zero com `n - 1`.

Python limita a profundidade de chamadas. Mesmo uma função matematicamente terminante pode lançar `RecursionError` para uma entrada profunda. Python não elimina chamadas em posição terminal. Para uma sequência longa, um ciclo pode evitar o custo da pilha.

## Recursão sobre dígitos

Um inteiro positivo divide-se no último dígito `n % 10` e no prefixo `n // 10`. Se o prefixo é zero, já não há mais dígitos a somar.

```python
def soma_digitos(n):
    if n == 0:
        return 0
    return n % 10 + soma_digitos(n // 10)

print(soma_digitos(502))
```

O resultado é 7. A chamada soma 2 com a soma de 50; essa soma junta 0 com a soma de 5; por fim junta 5 com zero. O contrato exige um inteiro não negativo. Esta decomposição calcula o mesmo que o ciclo anterior, mas deixa a adição pendente nas chamadas.

## Estruturas aninhadas

A recursão é útil quando os dados também são recursivos. Uma lista pode conter números ou outras listas com a mesma regra. Queremos somar todos os números, por mais níveis que existam.

<CodePlayground
  language="python"
  title="Somar números em listas aninhadas"
  code={
    'def soma_aninhada(elementos):\n    soma = 0\n    for elemento in elementos:\n        if isinstance(elemento, list):\n            soma += soma_aninhada(elemento)\n        else:\n            soma += elemento\n    return soma\n\nprint(soma_aninhada([2, [3, [], [4]], 1]))\nprint(soma_aninhada([]))'
  }
/>

A lista vazia tem soma zero. Um número soma-se diretamente; uma lista exige outra chamada. Para `[2, [3, [], [4]], 1]`, a soma interior vale $3+0+4=7$ e a exterior vale $2+7+1=10$.

O contrato aceita apenas números e listas finitas sem referências cíclicas. Uma lista que contém a si própria não satisfaz a redução estrutural. `isinstance(elemento, list)` devolve `True` quando o elemento é uma lista. Assim o programa decide se deve tratar um número ou percorrer outra lista.

## Evitar trabalho repetido

Na sequência de Fibonacci, os primeiros valores são 0 e 1; cada valor seguinte é a soma dos dois anteriores. A definição recursiva direta faz duas chamadas por nível e repete muito trabalho.

Para `fib(4)`, a árvore repete chamadas:

```
fib(4)
├── fib(3)
│   ├── fib(2)
│   │   ├── fib(1)
│   │   └── fib(0)
│   └── fib(1)
└── fib(2)
    ├── fib(1)
    └── fib(0)
```

`fib(2)` corre duas vezes e `fib(1)` corre três vezes, num total de 9 chamadas para devolver 3. Um ciclo que conserva os dois valores anteriores evita essa repetição.

A recursão não torna automaticamente um programa mais eficiente. Escolhe-a pela decomposição do problema, depois examina profundidade, trabalho repetido e criação de cópias. Por exemplo, usar `xs[1:]` em cada chamada cria sucessivas fatias; passar um índice pode evitar essas cópias.
