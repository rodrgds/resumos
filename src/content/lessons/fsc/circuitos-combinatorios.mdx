Um módulo combinatório pode ser tratado como uma função entre conjuntos de bits. Conhecer a sua tabela e a largura de cada entrada permite compor um circuito maior sem redesenhar todas as portas.

## Multiplexador e descodificador

Um multiplexador 2:1 seleciona $I_0$ quando $S=0$ e $I_1$ quando $S=1$:

$$Y=\overline S I_0+S I_1.$$

Um MUX com $2^k$ entradas precisa de $k$ bits de seleção. Se os dados forem palavras de 32 bits, há 32 seleções paralelas com os mesmos bits de seleção. Um MUX 8:1 de palavras não precisa de 32 bits de seleção, precisa de 3.

Um descodificador de $k$ entradas ativa uma entre $2^k$ saídas. Num 2:4 ativo a 1, $D_0=\overline A\overline B$, $D_1=\overline AB$, $D_2=A\overline B$ e $D_3=AB$. Um enable $E$ multiplica estas expressões. $E=0$ desativa todas as saídas; $E=1$ permite a seleção normal. Aqui $A$ é o bit mais significativo da seleção. Se as saídas forem ativas a 0, a linha selecionada fica 0 e as restantes 1.

Um demultiplexador encaminha um dado para a saída selecionada; pode ser construído aplicando o dado ao enable de um descodificador. Um codificador faz a operação de indicar o índice de uma entrada ativa. Se várias entradas puderem estar ativas, define prioridade e um sinal `valid`: o código `00` sozinho não distingue a entrada 0 ativa de nenhuma entrada ativa.

## Implementar uma função por seleção

Para $F=\Sigma m(1,3,5,6,7)$, usa um MUX 4:1 com seleção $AB$. Nas quatro combinações de $AB$, a saída em função de $C$ é:

| $AB$ | $F$ se $C=0$ | $F$ se $C=1$ | Entrada do MUX |
| ---- | ------------ | ------------ | -------------- |
| 00   | 0            | 1            | $C$            |
| 01   | 0            | 1            | $C$            |
| 10   | 0            | 1            | $C$            |
| 11   | 1            | 1            | 1              |

Logo liga $I_0=I_1=I_2=C$, $I_3=1$. A escolha das variáveis de seleção altera as subfunções necessárias, mas não a função final.

## Comparadores

A igualdade entre palavras é o AND das igualdades bit a bit: $Eq=\prod_i\overline{A_i\oplus B_i}$. Para a ordem sem sinal, o primeiro bit diferente a partir do MSB decide.

Em duas partes, alta $H$ e baixa $L$, temos

$$A>B=(A_H>B_H)+Eq_H(A_L>B_L).$$

Por exemplo, `1010` é maior que `1001`: as partes altas `10` são iguais, então comparamos `10` com `01`. Num comparador com sinal, começa por distinguir os sinais; dois códigos com sinais diferentes não seguem a ordem sem sinal.

## Somador completo

Um meio somador calcula $S=A\oplus B$ e $C=AB$. Um somador completo recebe ainda o carry $C_i$:

$$S=A\oplus B\oplus C_i,\qquad C_{i+1}=AB+AC_i+BC_i.$$

| $ABC_i$ | $S$ | $C_{i+1}$ |
| ------- | --- | --------- |
| 000     | 0   | 0         |
| 001     | 1   | 0         |
| 010     | 1   | 0         |
| 011     | 0   | 1         |
| 100     | 1   | 0         |
| 101     | 0   | 1         |
| 110     | 0   | 1         |
| 111     | 1   | 1         |

Ligando o carry de cada posição à seguinte construímos um somador ripple-carry. Para $1011+0110$, do LSB para o MSB, os pares $(S,C_{out})$ são $(1,0),(0,1),(0,1),(0,1)$. O resultado completo é `10001`.

## Somar, subtrair e acelerar

Um controlo $M$ permite usar o mesmo somador: aplica $B_i\oplus M$ a cada entrada e usa $C_0=M$. Com $M=0$, calcula $A+B$; com $M=1$, calcula $A+\overline B+1=A-B$.

No ripple-carry, o caminho crítico pode atravessar todos os carries. Definindo $G_i=A_iB_i$ e $P_i=A_i\oplus B_i$, temos $C_{i+1}=G_i+P_iC_i$. Expandir estas equações permite calcular carries em paralelo, com mais lógica. O ganho depende do circuito e dos atrasos, não apenas do número de portas.

Se cada etapa de carry atrasar 2 ns e a soma final atrasar mais 3 ns, um caminho que atravesse quatro etapas exige 11 ns neste modelo. Os caminhos em paralelo não se somam: escolhe o maior atraso entre uma entrada e uma saída. Um multiplicador, por sua vez, forma produtos parciais e soma-os com o alinhamento dos respetivos pesos.
