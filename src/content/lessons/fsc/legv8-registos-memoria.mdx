Depois de ver como a memória guarda dados por endereço, esta página responde a como o computador organiza programas e memória para executar instruções.

O CPU executa instruções guardadas em memória. O **PC**, que é o registo com o endereço da instrução atual, contém esse endereço. Um ciclo conceptual faz fetch, decode e execute: o CPU lê a instrução, identifica a operação e os operandos, depois produz o efeito e escolhe o PC seguinte.

## Programa e arquitetura

A ISA, arquitetura do conjunto de instruções, define as instruções e os efeitos observáveis pelo programa. A organização interna do CPU pode mudar sem mudar esses efeitos. A ABI, interface binária de aplicação, acrescenta acordos entre programas, como os registos de argumentos e a utilização da pilha.

Um compilador traduz código de alto nível; um assembler converte assembly em código máquina. O linker resolve ligações entre módulos e símbolos. O loader coloca o programa em memória e prepara a execução. Uma etiqueta não é um registo: é um nome que o assembler associa a uma posição.

RISC-V usa uma organização load/store: a aritmética opera sobre registos; loads e stores transferem entre registos e memória. Uma instrução como `add` não soma diretamente duas posições de memória. RISC favorece operações simples e regulares; CISC inclui operações mais complexas. Esta distinção não decide, por si só, qual computador executa um programa mais depressa.

## Registos de RV32

RV32 tem 32 registos inteiros, `x0` a `x31`, de 32 bits. `x0`, também chamado `zero`, lê sempre 0. Uma tentativa de escrever nele descarta o resultado. O PC é separado destes registos.

Os nomes `t0`, `a0` ou `sp` são aliases, não registos adicionais. Alguns são:

| Registo    | Alias      | Uso habitual                       |
| ---------- | ---------- | ---------------------------------- |
| x1         | ra         | Endereço de retorno                |
| x2         | sp         | Topo da pilha                      |
| x5, x6, x7 | t0, t1, t2 | Temporários                        |
| x8, x9     | s0, s1     | Valores preservados por uma rotina |
| x10 a x17  | a0 a a7    | Argumentos e temporários           |
| x18 a x27  | s2 a s11   | Valores preservados                |
| x28 a x31  | t3 a t6    | Temporários                        |

Um registo guarda bits. Uma instrução pode tratá-los como número com sinal, sem sinal, máscara ou endereço. A instrução de comparação é que escolhe a interpretação.

## Endereços e little endian

A memória é endereçada ao byte. Uma word tem 4 bytes, uma halfword 2 e um byte 1. Com 32 bits de endereço há $2^{32}$ endereços possíveis, 4 GiB de espaço de endereçamento; isto não obriga um simulador ou computador a ter toda essa RAM.

No ambiente aqui usado, a memória é little endian: o byte menos significativo fica no menor endereço. Guardar `0x12345678` a partir de `0x1000` dá:

| Endereço | Byte |
| -------- | ---- |
| 0x1000   | 78   |
| 0x1001   | 56   |
| 0x1002   | 34   |
| 0x1003   | 12   |

A ordem dos bits dentro do registo não se inverte. Um `lw` a partir de `0x1000` reconstrói a mesma palavra. Um `sb` altera só um byte. Acesso naturalmente alinhado significa endereço múltiplo de 4 para words e de 2 para halfwords. Usa estes alinhamentos nos programas; o tratamento de acessos desalinhados depende do ambiente.

Num vetor de words com base B, `v[i]` fica em $B+4i$. Se B=`0x10010000`, `v[3]` fica em `0x1001000C`. Confundir o índice 3 com um deslocamento de 3 bytes seleciona outro endereço e pode desalinhá-lo.

## Secções e diretivas

`.text` contém instruções; `.data` contém dados estáticos. A pilha guarda informação de chamadas e valores locais; o heap serve para alocações dinâmicas. A memória não ganha tipos por estar numa secção: os programas têm de usar as instruções e tamanhos corretos.

| Diretiva RARS    | Efeito                             |
| ---------------- | ---------------------------------- |
| `.word`          | Emite palavras de 32 bits          |
| `.half`, `.byte` | Emitem unidades de 16 ou 8 bits    |
| `.asciz`         | Emite texto e byte zero final      |
| `.space n`       | Reserva n bytes                    |
| `.align n`       | Alinha na fronteira de $2^n$ bytes |

Assim `.align 2` alinha words, não em fronteiras de 2 bytes. Uma diretiva orienta o assembler e não é executada pelo CPU. `la t0, vetor` obtém o endereço; `lw t1,0(t0)` lê o conteúdo. Copiar o endereço não copia o elemento.
