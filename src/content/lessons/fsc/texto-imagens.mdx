Depois de representar números com bits, esta página responde a como interpretar bits como texto e imagens.

Os bits de um ficheiro não dizem, por si, se representam texto, números ou uma imagem. Para os interpretar precisamos de um formato, ou seja, precisamos de saber que unidades existem, que tamanho têm e que significado damos a cada código.

## ASCII e Unicode

ASCII define 128 códigos, portanto 7 bits. Inclui letras latinas sem acentos, dígitos, pontuação e controlos. O código de `A` é 65, ou `0x41`; o de `a` é 97, ou `0x61`. Os dígitos `0` a `9` têm códigos consecutivos de 48 a 57. Para obter o valor do carácter `7`, subtrai o código de `0`: $55-48=7$.

Unicode atribui pontos de código a caracteres, mas um ponto de código ainda não é uma sequência de bytes. UTF-8 e UTF-16 são formas de o codificar.

UTF-8 usa de 1 a 4 bytes por ponto de código. Os caracteres ASCII mantêm os mesmos códigos num byte. `á`, ponto de código U+00E1, usa dois bytes: `C3 A1`. UTF-16 usa uma unidade de 16 bits para muitos pontos de código e um par de unidades para outros. Não assumes um tamanho fixo de dois bytes para qualquer carácter.

Uma letra visível também pode corresponder a mais de um ponto de código, como uma letra seguida de um acento combinatório. Por isso, número de bytes, pontos de código e símbolos visíveis podem diferir.

## Ler uma sequência UTF-8

Nos bytes de dois caracteres ASCII `A7`, temos `41 37`. Em UTF-8, `Aá` é `41 C3 A1`, três bytes. A sequência inicial `110` de `C3` anuncia um carácter de dois bytes; o byte seguinte começa por `10`, como byte de continuação.

Um programa que avança um byte de cada vez conta bytes corretamente, mas não necessariamente letras. Em `Aá` (`41 C3 A1`), há 3 bytes e 2 pontos de código. Um contador de bytes devolve 3; um contador de pontos UTF-8 reconhece `C3` como início de 2 bytes e salta o byte de continuação `A1`. Nas rotinas simples desta cadeira, a classificação de letras e dígitos trabalha sobre ASCII, e essa hipótese faz parte do contrato da rotina.

## Imagens raster e vetoriais

Uma imagem raster é uma grelha de píxeis. Uma imagem vetorial descreve formas, posições e atributos. Aumentar muito uma raster expõe a grelha; uma forma vetorial pode ser novamente desenhada à nova resolução.

Em RGB, os canais vermelho, verde e azul são aditivos. Com 8 bits por canal, `00 00 00` é preto e `FF FF FF` é branco. São 24 bits por píxel, com $2^{24}$ combinações. Um canal alfa adicional de 8 bits dá 32 bits por píxel.

CMYK descreve tintas subtrativas usadas na impressão. O suporte branco corresponde à ausência de tinta, e o canal preto permite obter preto sem depender apenas da mistura dos outros três canais. Não troques o modelo de luz emitida pelo de tinta sobre papel.

## Calcular o tamanho

Uma raster de 640 por 480 píxeis, com 24 bits por píxel e sem compressão, requer

$$640\times480\times24/8=921\,600\ \text{bytes}=900\ \text{KiB}.$$

Este é o tamanho dos dados dos píxeis. Um formato pode acrescentar cabeçalho, alinhamento das linhas, metadados e outros campos.

Numa imagem indexada de 8 bits por píxel, cada píxel guarda um índice para uma paleta de até 256 cores. Para a mesma imagem, os índices ocupam 307 200 bytes. Se a paleta usar 3 bytes por cor, acrescentam-se $256\times3=768$ bytes: total 307 968, antes do cabeçalho. A paleta não garante que a imagem original tenha só 256 cores, por isso convertê-la pode perder cores.

Compressão sem perdas permite reconstruir os dados exatamente; compressão com perdas pode alterar os valores para reduzir o tamanho. JPEG é normalmente usado com perdas em fotografias, por isso o tamanho final não se obtém só por largura vezes altura. TIFF admite diferentes modos de armazenamento e compressão, por isso a extensão não determina uma razão de compressão fixa.
