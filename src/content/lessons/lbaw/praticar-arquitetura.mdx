    Um pedido sai de Brave, chega a Nginx, executa a aplicação PHP e consulta

  </div>

    <p>Segue a direção do pedido.</p>
  </div>

      lógica.
    </div>

<Exercise
  id="php-captura"
  revision={1}
  title="Ler uma captura por valor"
  explanation="/cadeiras/lbaw/aplicacao-laravel/#ler-o-âmbito-de-uma-variável-em-php"
  answer={{ kind: 'number', value: 13, tolerance: 0 }}
>
  <div>
    Em PHP, executas{' '}
    <code>
      {'$taxa = 3; $f = fn($n) => $n + $taxa; $taxa = 8; echo $f(10);'}
    </code>
    . Que número aparece?
  </div>
  <div slot="hint">
    <p>A arrow function captura automaticamente por valor.</p>
  </div>
  <div slot="hint-more">
    <p>Observa o valor quando a função foi criada.</p>
  </div>
  <div slot="solution">
    <div>
      Aparece 13. A captura conservou 3. Alterar depois a variável exterior para
      8 não altera essa captura.
    </div>
  </div>
  <div slot="mistakes">
    <p>Não confundas fn com uma closure que declara use (&amp;$taxa).</p>
  </div>
</Exercise>

<Exercise
  id="contrato-ajax"
  revision={1}
  title="Definir o contrato de uma resposta"
  explanation="/cadeiras/lbaw/http-estado/#especificar-um-recurso-web"
  answer={{
    kind: 'self',
    checklist: [
      'Defino método, caminho e parâmetros.',
      'Declaro permissões e campos públicos devolvidos.',
      'Declaro código, tipo e estrutura do corpo em sucesso e falha.',
      'Escolho json() apenas para o corpo JSON definido.',
    ],
  }}
>
  <div>

Uma página carrega lugares disponíveis com `GET /api/sessoes/{id}`. Propõe o contrato do recurso para que o JavaScript distinga uma sessão visível, uma sessão ausente e uma falha técnica. Basta documentar os parâmetros?

  </div>
  <div slot="hint">

O cliente tem de decidir como ler cada resposta.

  </div>
  <div slot="hint-more">

Inclui códigos HTTP, Content-Type, campos e permissões.

  </div>
  <div slot="solution">

Não basta documentar parâmetros. Um contrato possível tem id no caminho, 200 com JSON de campos públicos da sessão visível, 404 para ausência ou existência não revelada e 500 sem detalhes internos para uma falha técnica. O cliente verifica o estado antes de usar <code>{"json()"}</code>. Pode haver outro contrato válido, desde que tipo, estrutura e tratamento de erros sejam explícitos. A disponibilidade indicada pode mudar antes da reserva.

  </div>
  <div slot="mistakes">

Responder 200 com uma página HTML de erro quebra um cliente que espera JSON de uma sessão. Documentar o recurso não dispensa autorização e coordenação no servidor.

  </div>
</Exercise>
