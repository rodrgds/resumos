<Exercise
  id="count"
  title="Contar numa junção opcional"
  explanation="/cadeiras/lbaw/consultas-relacionais/#left-join-e-o-lugar-do-filtro"
  answer={{ kind: 'number', value: 0, tolerance: 0 }}
>
  <p>
    Uma sessão sem bilhetes chega a um LEFT JOIN como uma linha com b.id=NULL.
    Quanto dá COUNT(b.id)?
  </p>
  <div slot="hint">
    <p>COUNT(coluna) ignora NULL.</p>
  </div>
  <div slot="hint-more">
    <p>COUNT(*) daria 1 para essa linha.</p>
  </div>
  <div slot="solution">
    <p>
      Dá 0, porque não há valor não nulo em b.id. A linha da sessão continua no
      resultado.
    </p>
  </div>
  <div slot="mistakes">
    <p>Não troques COUNT(b.id) por COUNT(*) sem rever a pergunta.</p>
  </div>
</Exercise>

<Exercise
  id="notin"
  title="O caso NULL"
  explanation="/cadeiras/lbaw/consultas-relacionais/#exists-not-in-e-todos"
  answer={{
    kind: 'choice',
    options: [
      {
        text: 'Desconhecido.',
        correct: true,
        explanation: '2 difere de 1, mas a comparação com NULL é desconhecida.',
      },
      {
        text: 'Verdadeiro.',
        correct: false,
        explanation: 'A lista contém uma informação ausente.',
      },
      {
        text: 'Falso por 2=1.',
        correct: false,
        explanation: 'Essa comparação é falsa, não verdadeira.',
      },
    ],
  }}
>
  <p>Que valor lógico tem 2 NOT IN (1,NULL)?</p>
  <div slot="hint">
    <p>Expande como 2&lt;&gt;1 AND 2&lt;&gt;NULL.</p>
  </div>
  <div slot="hint-more">
    <p>TRUE AND desconhecido é desconhecido.</p>
  </div>
  <div slot="solution">
    <p>
      O resultado é desconhecido e o WHERE rejeita a linha. Uma subconsulta NOT
      EXISTS adequada evita esta armadilha.
    </p>
  </div>
  <div slot="mistakes">
    <p>Não trates NULL como um valor concreto diferente de 2.</p>
  </div>
</Exercise>

<Exercise
  id="vazio-todos"
  title="Quantificação sobre conjunto vazio"
  explanation="/cadeiras/lbaw/consultas-relacionais/#exists-not-in-e-todos"
  answer={{
    kind: 'choice',
    options: [
      {
        text: 'Sim, salvo uma condição adicional de existência.',
        correct: true,
        explanation: 'Não há nenhuma sessão que viole a condição.',
      },
      {
        text: 'Não, todos significa pelo menos um.',
        correct: false,
        explanation: 'A quantificação universal não exige existência.',
      },
      {
        text: 'Só se o utilizador tiver um bilhete nulo.',
        correct: false,
        explanation: 'A condição exterior já não encontra sessões.',
      },
    ],
  }}
>
  <p>
    O duplo NOT EXISTS para «comprou em todas as sessões» aceita um evento sem
    sessões?
  </p>
  <div slot="hint">
    <p>Procura uma sessão que possa ser contraexemplo.</p>
  </div>
  <div slot="hint-more">
    <p>O conjunto de sessões está vazio.</p>
  </div>
  <div slot="solution">
    <p>
      Aceita por vacuidade. Se o domínio exige pelo menos uma sessão, acrescenta
      um EXISTS que o afirme.
    </p>
  </div>
  <div slot="mistakes">
    <p>Não introduzas uma pré-condição que o SQL não contém.</p>
  </div>
</Exercise>

<Exercise
  id="janela"
  title="Manter ou reduzir linhas"
  explanation="/cadeiras/lbaw/consultas-relacionais/#agregar-sem-esconder-o-detalhe"
  answer={{ kind: 'number', value: 2, tolerance: 0 }}
>
  <p>
    Duas vendas da mesma sessão valem 8 e 12. SUM(preco) OVER(PARTITION BY
    sessao_id) produz quantas linhas?
  </p>
  <div slot="hint">
    <p>Uma janela mantém o detalhe de cada linha.</p>
  </div>
  <div slot="hint-more">
    <p>Cada linha recebe o mesmo total 20.</p>
  </div>
  <div slot="solution">
    <p>
      Produz duas linhas, com total 20 em cada uma. GROUP BY produziria uma
      linha por sessão.
    </p>
  </div>
  <div slot="mistakes">
    <p>Não confundas agregação de janela com agregação que reduz grupos.</p>
  </div>
</Exercise>
