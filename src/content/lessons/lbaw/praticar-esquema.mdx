<Exercise
  id="escrever-associacao"
  revision={1}
  title="Traduzir uma regra para SQL"
  explanation="/cadeiras/lbaw/esquema-relacional/#as-regras-de-conversão"
  answer={{
    kind: 'self',
    checklist: [
      'Coloco sessao_id no cartaz e faço referência a sessoes(id).',
      "Uso `NOT NULL` para impedir um cartaz sem sessão.",
      'Uso UNIQUE para impedir dois cartazes na mesma sessão.',
      'Permito criar uma sessão sem cartaz.',
    ],
  }}
>
  <div>

Cada cartaz pertence a uma sessão e cada sessão pode ter zero ou um cartaz. A tabela `sessoes` já tem a PK `id`. Escreve a declaração de `cartazes` com uma PK própria e as restrições necessárias. A verificação do SQL é manual.

  </div>
  <div slot="hint">

O lado obrigatório deve guardar a referência.

  </div>
  <div slot="hint-more">

Uma FK sem <code>{"UNIQUE"}</code> também permitiria vários cartazes por sessão.

  </div>
  <div slot="solution">

<CodeSnippet language="sql" code={cartazesIdentidade} />

`NOT NULL` exige uma sessão para cada cartaz. A FK exige que essa sessão exista. `UNIQUE` limita a um cartaz por sessão. Nenhuma destas regras obriga a criar um cartaz para cada sessão.

  </div>
  <div slot="mistakes">

Uma FK opcional em sessoes pode representar a associação, mas por si só não impede cartazes sem sessão. Não acrescentes IDENTITY à FK: o seu valor refere uma chave já existente.

  </div>
</Exercise>
<Exercise
  id="notacao-compacta"
  revision={2}
  title="Traduzir notação compacta para DDL"
  explanation="/cadeiras/lbaw/esquema-relacional/#notação-compacta-schema-e-passagem-a-sql"
  answer={{ kind: 'self', checklist: ['Traduzo referência, NN, UK e CK.', 'Declaro PK e não gero a FK.', 'Coloco as tabelas no schema criado.'] }}
>
  <div>

Assume `sessoes(id INTEGER PRIMARY KEY)` no schema do grupo. Na notação compacta, `id` é a PK de `bilhetes(id, sessao_id -> sessoes NN, codigo UK NN, estado NN CK estado IN Estados)`, com `Estados = {reservado, pago, cancelado}`. Escreve o DDL PostgreSQL, incluindo a seleção do schema. Usa `lbawXXg` apenas como nome ilustrativo.

  </div>
  <div slot="hint">

Traduz cada marca separadamente e depois combina as restrições da coluna.

  </div>
  <div slot="solution">

```sql
CREATE SCHEMA lbawXXg;
SET search_path TO lbawXXg;
-- A tabela sessoes é criada neste schema antes de bilhetes.
CREATE TABLE bilhetes (
  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  sessao_id INTEGER NOT NULL REFERENCES sessoes(id),
  codigo TEXT NOT NULL UNIQUE,
  estado TEXT NOT NULL CHECK (estado IN ('reservado', 'pago', 'cancelado'))
);
```

`NN` impede NULL, `UK` impede códigos repetidos e `CK` restringe o domínio. A FK refere uma sessão existente, por isso não recebe IDENTITY. A PK gera uma identidade própria para cada bilhete, permitindo vários bilhetes da mesma sessão.

  </div>
</Exercise>
