      },
    ],
  }}
>
  <p>Em PostgreSQL, CHECK(preco&gt;=0) sem NOT NULL impede preco=NULL?</p>
  <div slot="hint">
    <p>Calcula o valor lógico de NULL&gt;=0.</p>
  </div>
  <div slot="hint-more">
    <p>Desconhecido não é falso.</p>
  </div>

  </div>

<Exercise
  id="minimo-inverso"
  title="O limite de uma chave estrangeira"
  explanation="/cadeiras/lbaw/modelo-conceptual/#o-que-o-modelo-não-garante-sozinho"
  answer={{
    kind: 'choice',
    options: [
      {
        text: 'Não. Garante a referência de cada sessão.',
        correct: true,
        explanation: 'Um evento pode existir sem nenhuma linha em sessoes.',
      },
      {
        text: 'Sim, porque NOT NULL implica 1..*.',
        correct: false,
        explanation:
          'Aplica-se à coluna de cada sessão, não à existência de filhos.',
      },
      {
        text: 'Só se evento_id tiver índice.',
        correct: false,
        explanation: 'Um índice não cria sessões.',
      },
    ],
  }}
>
  <p>
    evento_id NOT NULL REFERENCES eventos(id) garante que cada evento tem uma
    sessão?
  </p>
  <div slot="hint">
    <p>Tenta inserir só um evento.</p>
  </div>
  <div slot="hint-more">
    <p>A FK verifica as linhas da tabela que referencia.</p>
  </div>
  <div slot="solution">
    <p>
      O evento sem sessões não viola esta FK. O mínimo na direção inversa exige
      outra verificação ou um protocolo de criação.
    </p>
  </div>
  <div slot="mistakes">
    <p>Não traduzas uma associação só num sentido.</p>
  </div>
</Exercise>

  <p>
    bilhetes.sessao_id referencia sessoes.id com ON DELETE CASCADE. Apagar um

  </p>
  <div slot="hint">

  </div>

  </div>
