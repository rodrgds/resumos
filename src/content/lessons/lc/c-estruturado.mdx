Um driver precisa de representar bytes, chamar funções do sistema e guardar estado entre eventos. Em LC fazemos isso em C. O primeiro passo é distinguir o que a linguagem garante do que depende do compilador ou do ambiente Minix.

## De C++ para C

C tem funções, estruturas, apontadores e controlo de fluxo. Não tem classes, referências de C++, sobrecarga de funções nem `new` e `delete`. Uma `struct` guarda dados; funções recebem o seu endereço para os consultar ou alterar. Para alocar memória usamos `malloc` e para a devolver usamos `free`.

C e C++ partilham muita sintaxe, mas um programa aceite como C++ não é necessariamente C válido. Por exemplo, em C escreve `struct position` se não tiveres criado um `typedef`. Uma declaração `int f(void)` diz que `f` não recebe argumentos. Usa protótipos completos, para o compilador poder conferir as chamadas.

```c
#include <stdbool.h>
#include <stdint.h>

typedef struct {
  int16_t x;
  int16_t y;
} position;

bool position_equal(position a, position b) {
  return a.x == b.x && a.y == b.y;
}
```

Esta função recebe cópias das posições. Alterar `a.x` dentro dela não altera a posição do chamador. Para alterar um objeto do chamador, a função precisa de receber um apontador para esse objeto.

## Tipos e saída formatada

O tamanho de `int` depende da implementação. Quando o tamanho faz parte do contrato de um dispositivo, usa os tipos de `<stdint.h>`: `uint8_t` para um byte sem sinal, `uint16_t` para 16 bits e `uint32_t` para 32 bits. Usa `size_t` para tamanhos e índices de objetos na memória.

`printf` não deduz os tipos pela cadeia de formato. Cada conversão tem de corresponder ao argumento: `%d` recebe `int`, `%u` recebe `unsigned int`, `%zu` recebe `size_t` e `%p` recebe `void *`. Para tipos de largura fixa, `<inttypes.h>` fornece macros como `PRIu32`.

```c
#include <inttypes.h>
#include <stdio.h>

int main(void) {
  uint32_t ticks = 300;
  uint8_t status = 0xA5;
  printf("ticks=%" PRIu32 " status=0x%02X\n",
         ticks, (unsigned)status);
  return 0;
}
```

A saída é `ticks=300 status=0xA5`. O cast explicita o tipo pedido por `%X`. Uma incompatibilidade de formato não é apenas uma apresentação errada: pode causar comportamento indefinido. Ativa os avisos do compilador.

## Promoções e conversões de inteiros

Antes de muitas operações, C promove valores mais pequenos do que `int`. Num sistema onde `int` representa todos os valores de `uint8_t`, um byte torna-se um `int`. A operação deixa de ter apenas oito bits.

Considera `uint8_t value = 0x5A`. O complemento de oito bits seria `0xA5`. Porém, `~value` opera sobre o valor promovido. Com `int` de 32 bits e representação em complemento para dois, o resultado tem os bits de `0xFFFFFFA5`. Deslocar esse valor negativo à direita depende da implementação da linguagem usada no curso. Não derives um resultado portátil a partir de um deslocamento de um inteiro negativo.

Para complementar exatamente o byte, reduz o resultado a `uint8_t` antes do deslocamento:

```c
uint8_t value = 0x5A;
uint8_t result = (uint8_t)~value >> 4;
```

O cast produz `0xA5`. Esse valor é promovido a um `int` positivo para o deslocamento, por isso o resultado é `0x0A`, ou 10. Converter apenas no fim não corrige a operação anterior.

Outro caso frequente mistura um inteiro negativo com um inteiro sem sinal:

```c
int delta = -1;
unsigned int width = 10;
bool inside = delta < width;
```

Quando os tipos têm a mesma categoria e o `int` não representa todos os valores de `unsigned int`, `delta` converte-se para um grande valor sem sinal. O teste pode dar falso. Valida primeiro que `delta >= 0` e só depois compara `(unsigned int)delta < width`. Para posições com movimento negativo, mantém as contas num tipo com sinal até validares os limites.

## Apontadores, arrays e tamanho

`&x` obtém o endereço de `x`. Se `p` aponta para um `int` válido, `*p` lê ou altera esse inteiro. `p + 1` avança o tamanho de um `int`, não um byte. O tipo do apontador determina a unidade da aritmética.

```c
int values[] = {10, 20, 30};
int *p = values;
p++;
*p = 25;
```

Agora `values` contém `{10, 25, 30}`. Em muitas expressões, o array converte-se num apontador para o primeiro elemento. O array e o apontador continuam a ser objetos diferentes: `sizeof values` dá o tamanho de todo o array, mas `sizeof p` dá o tamanho de um endereço.

Um parâmetro `int values[]` é ajustado para `int *values`. A função não recebe o comprimento do array. Passa-o à parte e nunca acedas fora do intervalo. Podes formar um apontador para uma posição imediatamente a seguir ao fim para controlar um ciclo, mas não o podes desreferenciar.

## Módulos e encapsulamento

O ficheiro `.h` declara o que outros módulos podem usar. O `.c` implementa essas operações. Inclui o próprio cabeçalho no `.c`, para o compilador conferir que a definição corresponde à declaração.

Este módulo de contador é completo e independente do Minix.

```c title="counter.h"
#ifndef COUNTER_H
#define COUNTER_H

#include <stdint.h>

void counter_reset(void);
void counter_tick(void);
uint32_t counter_value(void);

#endif
```

```c title="counter.c"
#include "counter.h"

static uint32_t ticks;

void counter_reset(void) { ticks = 0; }
void counter_tick(void) { ++ticks; }
uint32_t counter_value(void) { return ticks; }
```

```c title="main.c"
#include "counter.h"
#include <inttypes.h>
#include <stdio.h>

int main(void) {
  counter_reset();
  counter_tick();
  counter_tick();
  printf("%" PRIu32 "\n", counter_value());
  return 0;
}
```

A variável `ticks` tem duração estática e visibilidade limitada ao ficheiro porque foi declarada com `static`. Os outros módulos chamam as funções, sem modificar o contador por acesso direto. Não definas uma variável global num cabeçalho incluído por vários `.c`. Se a partilha for necessária, declara-a com `extern` no cabeçalho e define-a uma única vez.

## Compilar e ligar

A construção tem quatro etapas: o pré-processador expande `#include` e macros; o compilador traduz C para assembly; o assembler produz código objeto; o linker resolve referências entre objetos e bibliotecas. Um `.o` ainda pode conter chamadas a funções cuja definição está noutro objeto.

Com os três ficheiros anteriores na mesma pasta:

```sh
cc -std=c11 -Wall -Wextra -Wpedantic -c counter.c
cc -std=c11 -Wall -Wextra -Wpedantic -c main.c
cc main.o counter.o -o demo
./demo
```

A saída é `2`. Um erro de sintaxe ou de tipo aparece na compilação. Uma referência a `counter_tick` sem definição aparece na ligação. Incluir `counter.h` dá a declaração, não acrescenta automaticamente `counter.c` ao executável.

Para criar e usar uma biblioteca estática:

```sh
ar rcs libcounter.a counter.o
cc main.o -L. -lcounter -o demo
```

`ar` agrupa código objeto num arquivo. `-L.` acrescenta a pasta atual à procura; `-lcounter` procura uma biblioteca com nome como `libcounter.a`. Com linkers que processam arquivos por ordem, coloca a biblioteca depois dos objetos que usam os seus símbolos. A ligação estática copia para o executável o código necessário do arquivo, não liga o programa ao código fonte.

## Make, Git e documentação

Um Makefile descreve alvos e dependências. Se mudares `counter.h`, tanto `counter.o` como `main.o` precisam de ser recompilados. As linhas das receitas começam com uma tabulação.

```makefile
CC = cc
CFLAGS = -std=c11 -Wall -Wextra -Wpedantic

demo: main.o counter.o
	$(CC) main.o counter.o -o demo

main.o: main.c counter.h
counter.o: counter.c counter.h

clean:
	rm -f demo main.o counter.o

.PHONY: clean
```

`make` compara dependências e datas para construir o que mudou. Os Makefiles do ambiente de LC também ligam as bibliotecas de apoio necessárias; não substituas esse ambiente por este exemplo portátil.

No Git, revê `git diff` antes de guardar uma alteração. `diff -u old.c new.c` produz um patch de texto; `patch` aplica-o a uma base compatível. Um patch não é um executável nem resolve automaticamente alterações incompatíveis na mesma linha.

Documenta a interface com Doxygen: o que a operação faz, pré-condições, parâmetros, resultado e quem liberta a memória. Uma descrição como "incrementa contador" não explica a política de overflow nem o instante em que o contador reinicia. A documentação útil permite chamar a função sem ler a sua implementação.
