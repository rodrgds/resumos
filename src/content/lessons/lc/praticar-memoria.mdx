<Exercise
  id="lc-apontador-libertado"
  title="Quem fica com o endereço?"
  explanation="/cadeiras/lc/memoria-funcoes/#passagem-de-parâmetros"
  answer={{
    kind: 'self',
    checklist: [
      'Expliquei a cópia do apontador.',
      'Identifiquei o endereço pendente no chamador.',
      'Propus retorno de NULL ou parâmetro duplo.',
    ],
  }}
>
  <p>
    Uma função recebe int *p, chama free(p) e depois faz p = NULL. O chamador
    passou a sua variável values. Depois da chamada, pode testar values != NULL
    para saber se a memória ainda existe? Justifica e propõe uma interface
    adequada.
  </p>
  <div slot="hint">A função recebe uma cópia do valor de values.</div>
  <div slot="hint-more">Alterar p não altera o objeto values do chamador.</div>
  <div slot="solution">
    Não. O objeto dinâmico foi libertado, mas values pode conservar o endereço
    antigo. A comparação com NULL não prova validade. O chamador pode fazer
    values = destroy(values), com a função a devolver NULL, ou a função pode
    receber int ** e alterar *p depois da libertação. Outros aliases continuam a
    exigir uma política de propriedade.
  </div>
  <div slot="mistakes">
    Um apontador não se torna automaticamente NULL quando o objeto é libertado.
    Pôr um alias a NULL também não corrige os restantes.
  </div>
</Exercise>

<Exercise
  id="lc-duracao-local"
  title="Devolver um resultado válido"
  explanation="/cadeiras/lc/memoria-funcoes/#chamada-stack-frame-e-retorno"
  answer={{
    kind: 'self',
    checklist: [
      'Identifiquei o fim da duração do objeto.',
      'Não usei um teste isolado como prova de validade.',
      'Propus retorno por valor ou armazenamento do chamador.',
    ],
  }}
>
  <p>
    Uma função cria int result = 17 e devolve &amp;result. Num teste, o chamador
    imprime 17. Esse resultado prova que a função está correta? Dá duas
    alternativas sem esse erro de duração.
  </p>
  <div slot="hint">
    A memória pode ainda conter os mesmos bits depois do retorno.
  </div>
  <div slot="hint-more">
    A validade depende da existência do objeto, não dos bits antigos.
  </div>
  <div slot="solution">
    O objeto automático deixa de existir no retorno. Desreferenciar o endereço
    devolvido é inválido, mesmo que os bits ainda mostrem 17. Devolve o inteiro
    por valor ou recebe um apontador para um int que o chamador conserva durante
    toda a chamada e escreve nesse objeto.
  </div>
  <div slot="mistakes">
    Declarar result como apontador não prolonga a duração de um objeto
    automático. Usar static mudaria o contrato para armazenamento partilhado
    entre chamadas.
  </div>
</Exercise>

<Exercise
  id="lc-despacho-funcoes"
  title="Ler uma tabela de funções"
  explanation="/cadeiras/lc/memoria-funcoes/#apontadores-para-funções"
  answer={{ kind: 'number', value: 11, tolerance: 0 }}
>
  <p>
    Uma tabela contém primeiro f(n) = 3n e depois g(n) = n + 7. Todas as funções
    têm tipo int(int). Qual é o resultado da chamada à função do índice 1 com
    argumento 4?
  </p>
  <div slot="hint">Os índices começam em zero.</div>
  <div slot="hint-more">O índice 1 escolhe g, não f.</div>
  <div slot="solution">
    table[1] aponta para g. A chamada passa 4 e calcula 4 + 7 = 11. O apontador
    seleciona a função; não aplica o índice ao argumento.
  </div>
  <div slot="mistakes">
    Confundir índice 1 com a primeira entrada ou somar os resultados das duas
    funções.
  </div>
</Exercise>
