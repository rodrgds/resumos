<Exercise
  revision={1}
  id="git-snapshot"
  title="O que entra no commit?"
  explanation="/cadeiras/ldts/controlo-versoes/#as-três-áreas-do-git"
  answer={{
    kind: 'choice',
    options: [
      {
        text: 'A',
        correct: false,
        explanation: 'O add substituiu o conteúdo preparado por B.',
      },
      {
        text: 'B',
        correct: true,
        explanation: 'O commit usa o índice, que continua com B.',
      },
      {
        text: 'C',
        correct: false,
        explanation: 'A edição posterior ficou apenas no working tree.',
      },
    ],
  }}
>
  <div>
    O ficheiro seguido contém A. Editas para B, fazes{' '}
    <code>git add regra.txt</code>, editas para C e fazes commit sem outro add.
    Que conteúdo fica no novo commit?
  </div>
  <div slot="hint">
    <div>Distingue a versão no ficheiro da versão no índice.</div>
  </div>
  <div slot="hint-more">
    <div>O add copiou B; a edição para C não repetiu essa cópia.</div>
  </div>
  <div slot="solution">
    <div>
      O commit guarda B. C continua como mudança local. Percorre os estados:
      após o add, índice tem B; após editar para C, ficheiro tem C e índice
      continua B. O diff normal compara C com B; o diff preparado compara B com
      A.
    </div>
  </div>
  <div slot="mistakes">
    <div>Não confundas guardar no editor com preparar no índice.</div>
  </div>
</Exercise>

<Exercise
  revision={2}
  id="git-merge-pais"
  title="Integrar dois históricos"
  explanation="/cadeiras/ldts/controlo-versoes/#branches-e-merges"
  answer={{ kind: 'self', checklist: [
    'Identifiquei E e D como pais diretos de M.',
    'Expliquei por que main não pode chegar a D por fast-forward.',
    'Distingui o caso em que main ainda apontava para B.',
  ] }}
>
  <div>

O histórico tem os commits seguintes. `main` aponta para E e `movimento` para D:

```text
A---B---E  main
     \
      C---D  movimento
```

Estás em `main` e executas `git merge movimento`, sem `--no-ff`.

1. É possível fazer fast-forward? Justifica pelo grafo.
2. Se a integração cria M, quais são os seus pais diretos e que commits ficam alcançáveis a partir de `main`?
3. O que mudaria se `main` ainda apontasse para B?

  </div>
  <div slot="hint">Um fast-forward exige que a ponta atual seja antepassada da ponta a integrar.</div>
  <div slot="solution">
    E não é antepassado de D: os ramos divergiram depois de B. M tem E e D como pais diretos, e permite alcançar A, B, C, D e E, além do próprio M. Os pais não são todos os antepassados. Se main estivesse em B, poderia avançar para D sem criar M. Nesse caso, main e movimento passariam a apontar para D.
  </div>
</Exercise>

<Exercise
  revision={1}
  id="gradle-teste-dependencia"
  title="Escolher o âmbito da dependência"
  explanation="/cadeiras/ldts/controlo-versoes/#dependências-com-gradle"
  answer={{
    kind: 'self',
    checklist: [
      'Indica testImplementation para compilar os testes.',
      'Distingue dependências dos testes das do programa.',
      'Refere o motor/plataforma necessário em runtime dos testes.',
    ],
  }}
>
  <div>
    JUnit só é usado pelos testes. Justifica em que configuração colocarias a
    dependência e por que o programa não deve precisar dela para arrancar.
  </div>
  <div slot="hint">
    <div>Pergunta em que conjunto de fontes aparecem os imports.</div>
  </div>
  <div slot="hint-more">
    <div>Os imports do JUnit estão em src/test/java, não em src/main/java.</div>
  </div>
  <div slot="solution">
    <div>
      JUnit Jupiter fica em testImplementation porque só `src/test/java` importa
      JUnit. A plataforma e o motor têm de estar disponíveis para executar os
      testes. O programa distribuído não precisa de carregar JUnit só porque tem
      testes.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Uma dependência de runtime dos testes não é necessariamente uma
      dependência de runtime do programa.
    </div>
  </div>
</Exercise>
