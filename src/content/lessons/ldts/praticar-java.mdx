<Exercise
  id="java-alias"
  title="Prever uma alteração através de um parâmetro"
  explanation="/cadeiras/ldts/java-orientado-objetos/#valores-e-referências"
  answer={{ kind: 'number', value: 2, tolerance: 0 }}
>
  <p>
    Uma lista L começa com um elemento. Um método recebe L, acrescenta outro
    elemento e depois atribui uma lista vazia ao parâmetro. Quantos elementos
    tem L depois da chamada?
  </p>
  <div slot="hint">
    <p>Desenha duas referências para o objeto inicial.</p>
  </div>
  <div slot="hint-more">
    <p>Acrescentar altera o objeto; a atribuição muda só a referência local.</p>
  </div>
  <div slot="solution">
    <p>
      L tem dois elementos. O método recebeu uma cópia da referência, que
      apontava para o mesmo objeto. Reatribuir o parâmetro não muda a referência
      do chamador.
    </p>
  </div>
  <div slot="mistakes">
    <p>Java não passa a variável do chamador por referência.</p>
  </div>
</Exercise>

<Exercise
  id="java-hash-contrato"
  title="Igualdade sem identidade"
  explanation="/cadeiras/ldts/java-orientado-objetos/#igualdade-e-hash"
  answer={{
    kind: 'self',
    checklist: [
      'Distingue identidade de igualdade por coordenadas.',
      'Afirma que objetos iguais têm de ter o mesmo hash.',
      'Deriva o hash de estado compatível com equals.',
    ],
  }}
>
  <p>
    Duas posições diferentes em memória têm as mesmas coordenadas. O tipo
    redefine equals corretamente, mas usa um hash dependente da identidade.
    Explica o problema num HashSet e a correção.
  </p>
  <div slot="hint">
    <p>O HashSet começa a procurar através do hash.</p>
  </div>
  <div slot="hint-more">
    <p>
      Se os objetos iguais forem colocados em grupos diferentes, a igualdade
      pode não ser consultada entre eles.
    </p>
  </div>
  <div slot="solution">
    <p>
      As posições são iguais pelo contrato, mas os hashes podem diferir,
      violando o contrato de hashCode. O conjunto pode aceitar duplicados
      lógicos ou falhar uma procura. Calcula o hash a partir das coordenadas e
      mantém esse estado estável enquanto está no conjunto.
    </p>
  </div>
  <div slot="mistakes">
    <p>
      Não é necessário que todos os objetos diferentes tenham hashes diferentes.
    </p>
  </div>
</Exercise>

<Exercise
  id="java-wildcard"
  title="Receber números de tipos diferentes"
  explanation="/cadeiras/ldts/java-orientado-objetos/#genéricos-e-wildcards"
  answer={{
    kind: 'choice',
    options: [
      {
        text: 'List<Number>',
        correct: false,
        explanation: 'A invariância impede passar diretamente List<Integer>.',
      },
      {
        text: 'List<? extends Number>',
        correct: true,
        explanation: 'Cada elemento pode ser lido como Number.',
      },
      {
        text: 'List<? super Number>',
        correct: false,
        explanation:
          'Ao ler, só podemos assumir Object, e listas de Integer não satisfazem esse limite.',
      },
    ],
  }}
>
  <p>
    Um método só lê números de uma lista e chama doubleValue em cada um. Deve
    aceitar List&lt;Integer&gt; e List&lt;Double&gt;. Qual é o parâmetro
    adequado?
  </p>
  <div slot="hint">
    <p>A lista fornece valores ao método.</p>
  </div>
  <div slot="hint-more">
    <p>Precisamos de ler como Number, sem acrescentar um tipo arbitrário.</p>
  </div>
  <div slot="solution">
    <p>
      Usa List&lt;? extends Number&gt;. Integer e Double são subtipos de Number,
      e ambos fornecem doubleValue. A lista continua a poder ser mutável; o
      wildcard não dá imutabilidade.
    </p>
  </div>
  <div slot="mistakes">
    <p>
      Não acrescentes um Double a uma lista cujo tipo concreto pode ser Integer.
    </p>
  </div>
</Exercise>
