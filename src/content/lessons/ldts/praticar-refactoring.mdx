<Exercise
  revision={1}
  id="refactoring-preco"
  title="Conservar o desconto marginal"
  explanation="/cadeiras/ldts/smells-refactoring/#exemplo-extrair-a-regra-do-preço"
  answer={{ kind: 'number', value: 1300, tolerance: 0, unit: 'cêntimos' }}
>
  <div>
    Cada uma das primeiras cinco unidades custa 200 cêntimos; cada unidade
    adicional custa 150. Quanto custam sete unidades, em cêntimos?
  </div>
  <div slot="hint">
    <div>Divide a quantidade em duas parcelas.</div>
  </div>
  <div slot="hint-more">
    <div>As cinco primeiras custam mil; só as duas seguintes usam 150.</div>
  </div>
  <div slot="solution">
    <div>
      O preço é 5 × 200 + 2 × 150 = 1000 + 300 = 1300 cêntimos. Divide em
      parcelas: as cinco primeiras a 200, as duas seguintes a 150. Aplicar 150 a
      todas as sete unidades daria 1050 e mudaria a regra de desconto marginal.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Um desconto marginal não é um preço retroativo sobre todas as unidades.
    </div>
  </div>
</Exercise>

<Exercise
  revision={1}
  id="refactoring-erros"
  title="A ordem pode fazer parte do comportamento"
  explanation="/cadeiras/ldts/smells-refactoring/#outras-transformações"
  answer={{
    kind: 'choice',
    options: [
      {
        text: 'Sim, porque continua a lançar uma exceção.',
        correct: false,
        explanation: 'O erro observado pode mudar, incluindo tipo e mensagem.',
      },
      {
        text: 'Não necessariamente, porque pode mudar o primeiro erro apresentado.',
        correct: true,
        explanation: 'A ordem de validação pode fazer parte do contrato.',
      },
      {
        text: 'Sim, porque guard clauses não mudam comportamento.',
        correct: false,
        explanation:
          'Uma transformação só é refatoração se preservar o comportamento relevante.',
      },
    ],
  }}
>
  <div>
    Um método verifica primeiro nome vazio e depois idade negativa, lançando
    erros diferentes. Uma refatoração troca a ordem. Quando a entrada viola
    ambos, o comportamento está preservado?
  </div>
  <div slot="hint">
    <div>Compara a exceção observada para a mesma entrada.</div>
  </div>
  <div slot="hint-more">
    <div>Na primeira versão o nome vence; na segunda pode vencer a idade.</div>
  </div>
  <div slot="solution">
    <div>
      Percorre a entrada que viola ambos: antes, o erro é de nome; depois da
      troca, o erro é de idade. Não necessariamente. A mesma entrada pode
      receber um erro diferente. Conserva a ordem se o contrato a exige ou trata
      a mudança de regra separadamente.
    </div>
  </div>
  <div slot="mistakes">
    <div>Ter testes verdes incompletos não demonstra equivalência.</div>
  </div>
</Exercise>

<Exercise
  revision={1}
  id="refactoring-envy"
  title="Contar chamadas chega?"
  explanation="/cadeiras/ldts/smells-refactoring/#os-cheiros-mais-comuns"
  answer={{
    kind: 'self',
    checklist: [
      'Não decide pela contagem de chamadas.',
      'Distingue regra do domínio de formato de serialização.',
      'Explica que mover o formato pode introduzir uma responsabilidade independente na entidade.',
    ],
  }}
>
  <div>
    Um serializador consulta dez atributos de uma entidade para construir texto.
    Um colega propõe movê-lo para a entidade porque tem mais chamadas à entidade
    do que a si próprio. Avalia a justificação.
  </div>
  <div slot="hint">
    <div>Pergunta quem deve conhecer o formato externo.</div>
  </div>
  <div slot="hint-more">
    <div>Ler dados é parte da função de um serializador.</div>
  </div>
  <div slot="solution">
    <div>
      A contagem é um sinal insuficiente. Se o método só traduz a entidade para
      um formato externo, o serializador pode ser o responsável certo. Mover o
      formato para a entidade pode juntar razões de mudança independentes. Se o
      método calcula uma regra do domínio, investiga essa parte separadamente.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Feature Envy não obriga a mover todo o código que consulta muitos getters.
    </div>
  </div>
</Exercise>
