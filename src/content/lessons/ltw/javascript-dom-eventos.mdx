Depois do servidor com PHP, esta página responde como o navegador altera a página já carregada com JavaScript.

JavaScript pode calcular valores e alterar a página já carregada. A linguagem e o DOM, ou seja a árvore de elementos que o navegador constrói a partir do HTML, são coisas diferentes: arrays, funções e objetos pertencem à linguagem; `document`, elementos e eventos são APIs do navegador, ou seja formas de o programa pedir coisas ao navegador, por isso um programa sem DOM pode correr noutro ambiente.

## Tipos e conversões

Usa `const` para uma ligação que não será reatribuída e `let` quando será. `const` não torna um objeto imutável. `var` tem âmbito de função e regras de declaração diferentes do âmbito de bloco de `let` e `const`.

```js
const livro = { titulo: 'Redes' };
livro.titulo = 'SQL'; // permitido
// livro = {};       // reatribuição proibida
```

Os tipos primitivos incluem string, number, boolean, null, undefined, bigint e symbol. `typeof null` devolve historicamente `'object'`, apesar de `null` não ser um objeto. `undefined` aparece, por exemplo, ao ler uma propriedade ausente.

```js
console.log('8' + 1); // 81, string
console.log('8' - 1); // 7, number
console.log('8' === 8); // false
console.log(Number('8') + 1); // 9
console.log(Number('8x')); // NaN
```

`+` pode concatenar; `-` exige operações numéricas. `===` evita conversões implícitas na igualdade. `NaN` significa que o resultado não é um número válido; usa `Number.isNaN` ou `Number.isFinite` conforme a condição. `Number('')` é 0, por isso confirma uma entrada obrigatória antes de converter.

`parseInt('8x', 10)` devolve 8, porque lê um prefixo numérico; `Number('8x')` dá `NaN`. Para exigir um inteiro completo, verifica primeiro a entrada vazia, converte e usa `Number.isInteger`, além dos limites pretendidos. Duas criações de objetos, como `[1] === [1]`, comparam referências e dão `false`, mesmo com valores iguais.

Num teste booleano, `0`, `''`, `null`, `undefined`, `NaN` e `false` são falsos; arrays e objetos vazios são verdadeiros. `x || alternativa` substitui todos os valores falsos; `x ?? alternativa` só substitui `null` e `undefined`. Uma quantidade válida igual a zero pode exigir `??`, não `||`.

## Arrays e funções como valores

`for...of` percorre valores de um iterável; `for...in` percorre nomes de propriedades e não é o percurso habitual para valores de um array. `map` transforma, `filter` seleciona e `reduce` acumula:

Os objetos dentro de uma cópia superficial continuam partilhados; alterar `baratos[0].preco` também altera esse objeto em `livros`.

Uma função é um valor que pode ser passado como callback. `livros.map((livro) => livro.titulo)` recebe uma função; escrever `map(obterTitulo())` chamaria `obterTitulo` imediatamente e passaria o resultado. Numa arrow function com corpo entre chavetas, usa `return` para devolver um valor.

A desestruturação extrai partes, como `const { titulo, preco } = livro`. Spread, como `[...livros]`, cria uma cópia superficial. Um `Set` guarda valores únicos; um `Map` associa chaves a valores sem limitar as chaves a nomes de propriedades de um objeto.

`slice` cria uma cópia de uma parte; `splice` altera o array ao remover ou inserir. `push` e `pop` alteram o fim. `sort` também altera o array e, sem comparador, compara representações textuais:

```js
const precos = [8, 25, 3];
console.log([...precos].sort()); // [25, 3, 8]
console.log([...precos].sort((a, b) => a - b)); // [3, 8, 25]
console.log(precos); // [8, 25, 3]
```

O comparador devolve um número negativo se `a` vem antes de `b`, zero se empatam e positivo se vem depois. A cópia com spread protege a ordem original. `forEach` percorre para produzir efeitos e devolve `undefined`; usa `map` quando precisas de construir um array com os resultados.

## Objetos, this e protótipos

Num método normal chamado como `objeto.metodo()`, `this` refere habitualmente esse objeto. Separar o método do objeto pode perder essa associação:

```js
'use strict';
const livro = {
  titulo: 'Redes',
  nome() {
    return this.titulo;
  },
};
const nome = livro.nome;
console.log(livro.nome()); // Redes
console.log(nome.call(livro)); // Redes
const nomeLigado = nome.bind(livro);
console.log(nomeLigado()); // Redes
```

Chamar apenas `nome()` neste exemplo estrito tenta aceder a `titulo` num `this` indefinido. `bind` cria uma função ligada; `call` faz a chamada com um `this` explícito. Uma arrow function herda `this` do ambiente em que foi criada, não o recebe do objeto pela mesma regra. Por isso não a uses como substituto automático de um método que depende de `this`.

Se uma propriedade não existe no objeto, a procura pode continuar no seu protótipo e depois nos protótipos seguintes. Classes usam esse mecanismo:

```js
class Livro {
  constructor(titulo) {
    this.titulo = titulo;
  }
  nome() {
    return this.titulo;
  }
}
const redes = new Livro('Redes');
console.log(redes.nome()); // Redes
console.log(redes.hasOwnProperty('titulo')); // true
console.log(redes.hasOwnProperty('nome')); // false
```

`titulo` pertence à instância; `nome` está em `Livro.prototype`. `extends` liga cadeias de protótipos, `super` permite chamar a implementação da classe base e membros `static` pertencem à classe. Campos privados com `#` têm uma restrição de acesso própria da linguagem.

## Ler e alterar o DOM

`querySelector` devolve o primeiro elemento ou `null`; `querySelectorAll` devolve uma NodeList estática. `children` contém elementos; `childNodes` inclui também texto e comentários. Por isso, espaços e mudanças de linha podem alterar `childNodes` sem acrescentar elementos.

Para percorrer elementos, usa `parentElement`, `firstElementChild` e `nextElementSibling`. `closest(seletor)` começa no próprio elemento e procura um antepassado correspondente. `classList` altera classes; `dataset.id` lê `data-id`. Uma propriedade como `input.value` representa o valor atual, que pode diferir do atributo inicial escrito no HTML. `children` é uma coleção viva: acompanha inserções e remoções. Uma NodeList de `querySelectorAll` conserva a seleção feita naquele momento. Para usar `map` numa NodeList, cria primeiro um array com `Array.from(nos)` ou `[...nos]`.

```js
const item = document.createElement('li');
item.textContent = '<b>Redes</b>';
lista.append(item);
```

O utilizador vê o texto literal `<b>Redes</b>`. `innerHTML` interpretaria marcação. Para dados do utilizador, `textContent` evita misturar dados com HTML. Inserir um nó que já está no documento move-o para o novo pai, sem o copiar. `cloneNode(true)` cria outra árvore, mas não copia listeners registados com `addEventListener`; evita também duplicar IDs.

`append` acrescenta nós; `replaceChildren` substitui todos os filhos; `remove` retira o nó. Mudar `style` aplica declarações em linha; mudar uma classe permite manter o aspeto no CSS.

## Eventos e delegação

O callback de `addEventListener` recebe um evento. `event.target` é o alvo onde o evento começou; `event.currentTarget` é o elemento cujo listener está a correr. Em captura, percorremos antepassados em direção ao alvo; em bubbling, o evento sobe do alvo pelos antepassados, quando o tipo de evento o permite.

`preventDefault()` impede uma ação por defeito, como submeter o formulário. Não pára a propagação. `stopPropagation()` interrompe a propagação, não a ação por defeito. Estas operações resolvem problemas diferentes.

## Carregamento e temporizadores

Um script clássico com `defer` executa depois da análise do documento e antes de `DOMContentLoaded`, conservando a ordem entre scripts deferidos. `async` executa quando o download termina, sem garantir essa ordem nem esperar pela análise completa. Módulos são deferidos por defeito.

`setTimeout(callback, atraso)` agenda um callback para não correr antes do atraso, mas não garante um instante exato. `setInterval` repete; usa `clearTimeout` ou `clearInterval` para cancelar. O JavaScript corrente termina antes dos callbacks agendados, tema que continuamos em [HTTP e Ajax](/cadeiras/ltw/http-ajax-json/#promessas-e-ordem-de-execução).

Um `<template>` guarda conteúdo inerte em `template.content`, que podes clonar com `cloneNode(true)` e inserir depois de preencher dados com destinos seguros. Shadow DOM cria uma árvore encapsulada para um componente, separando grande parte dos estilos e estrutura do documento exterior. Não é uma fronteira de segurança para guardar segredos.
