<Exercise
  id="ltw-total-precos"
  title="Filtrar e somar preços"
  revision={1}
  explanation="/cadeiras/ltw/javascript-dom-eventos/#arrays-e-funções-como-valores"
  answer={{
    kind: 'code',
    language: 'javascript',
    starter: 'function totalAte(precos, limite) {\n  return 0;\n}',
    tests: [
      {
        name: 'Selecionar sem alterar o array',
        code: 'const precos = [18, 12, 32];\nconsole.log(totalAte(precos, 20));\nconsole.log(JSON.stringify(precos));',
        output: '30\n[18,12,32]',
      },
      {
        name: 'Array vazio',
        code: 'console.log(totalAte([], 20));',
        output: '0',
      },
      {
        name: 'Incluir o limite',
        code: 'console.log(totalAte([20, 21], 20));',
        output: '20',
      },
      {
        name: 'Nenhum preço elegível',
        code: 'console.log(totalAte([25, 30], 20));',
        output: '0',
      },
      {
        name: 'Repetidos e limite zero',
        code: 'console.log(totalAte([12, 12, 25], 20));\nconsole.log(totalAte([0, 1], 0));',
        output: '24\n0',
      },
    ],
  }}
>
  <div>
    Define <code>{"totalAte(precos, limite)"}</code>: devolve a soma dos preços menores ou iguais
    ao limite, sem alterar o array nem imprimir. São inteiros não negativos em
    euros; a soma vazia é zero. Não uses o DOM.
  </div>
  <div slot="hint">Seleciona os preços com <code>{"filter"}</code> e acumula com <code>{"reduce"}</code>.</div>
  <div slot="hint-more">
    Inclui o limite com &lt;= e dá a <code>{"reduce"}</code> um total inicial igual a zero.
  </div>
  <div slot="solution">

```javascript
function totalAte(precos, limite) {
  return precos
    .filter((preco) => preco <= limite)
    .reduce((total, preco) => total + preco, 0);
}
```

    Para <code>{"[18, 12, 32]"}</code> e limite 20, entram 18 e 12, cuja soma é 30. Um ciclo
    for...of com um acumulador também resolve.

  </div>
  <div slot="mistakes">
    Excluir o preço igual ao limite, esquecer o valor inicial de <code>{"reduce"}</code>, alterar
    o array recebido ou imprimir em vez de devolver.
  </div>
</Exercise>

<Exercise
  id="ltw-array-partilhado"
  revision={1}
  title="Seguir uma cópia superficial"
  explanation="/cadeiras/ltw/javascript-dom-eventos/#arrays-e-funções-como-valores"
  answer={{"kind": "self", "checklist": ["Obtive 9, 2 e 1.", "Expliquei arrays diferentes e objeto partilhado."]}}
>

Prevê os três valores escritos e explica a diferença entre reatribuir e alterar o objeto.

```js
const a = [{ n: 2 }, { n: 5 }];
const b = a.filter((x) => x.n < 4);
b[0].n = 9;
console.log(a[0].n, a.length, b.length);
```

<div slot="hint">

<code>{'filter'}</code> cria outro array, mas não copia profundamente os
objetos.

</div>
<div slot="solution">

A saída é 9 2 1. `filter` cria um array novo com uma entrada, mas o objeto dentro dele é o mesmo objeto de `a`. Ao escrever `b[0].n = 9`, alteras esse objeto partilhado, por isso `a[0].n` passa a 9. Os arrays continuam distintos, com comprimentos 2 e 1. `const` impede reatribuir `a` ou `b`, não alterar objetos referidos.

</div>
<div slot="mistakes">

Não prever 2 para <code>{"a[0]"}</code>.n nem tratar const como congelamento profundo.

</div>
</Exercise>

<Exercise
  id="ltw-contador-closure"
  revision={1}
  title="Prever ambientes separados"
  explanation="/cadeiras/ltw/javascript-dom-eventos/#âmbito-e-closures"
  answer={{"kind": "self", "checklist": ["Obtive 3 12 5 14.", "Segui dois estados independentes."]}}
>

Prevê a saída e mostra o estado de n de cada closure após cada chamada.

```js
function contador(inicio) {
  let n = inicio;
  return () => (n += 2);
}
const a = contador(1);
const b = contador(10);
console.log(a(), b(), a(), b());
```

<div slot="hint">

Cada chamada a contador cria uma ligação de n diferente.

</div>
<div slot="solution">

A saída é 3 12 5 14. Cada chamada a `contador` cria um `n` independente. As chamadas correm da esquerda para a direita. Após `a()`: n de a passa de 1 para 3. Após `b()`: n de b passa de 10 para 12. O segundo `a()` leva a de 3 para 5. O segundo `b()` leva b de 12 para 14. As closures conservam o seu ambiente, mas não partilham `n`.

</div>
<div slot="mistakes">

Não usar um único contador global para as duas closures.

</div>
</Exercise>

<Exercise
  id="ltw-metodo-this"
  revision={1}
  title="Manter o recetor do método"
  explanation="/cadeiras/ltw/javascript-dom-eventos/#objetos-this-e-protótipos"
  answer={{"kind": "self", "checklist": ["Expliquei a falha de f().", "Distingui protótipo e propriedade própria."]}}
>

Em modo estrito, um objeto tem titulo: Redes e método normal <code>{"nome()"}</code> que devolve <code>{"this.titulo"}</code>. Guarda-se `const f = livro.nome`. Compara <code>{"livro.nome()"}</code>, <code>{"f()"}</code> e <code>{"f.bind(livro)"}</code>(). Onde fica um método definido por class Livro?

<div slot="hint">

Uma função normal não fica ligada ao objeto só por ser lida numa propriedade.

</div>
<div slot="hint-more">

bind fixa o recetor; métodos de classe são habitualmente partilhados no protótipo.

</div>
<div slot="solution">

<code>{'livro.nome()'}</code> devolve Redes. <code>{'f()'}</code> tem
<code>{'this'}</code>
indefinido neste exemplo e falha ao ler titulo. <code>{'f.bind(livro)'}</code>()
devolve Redes. Um método normal definido na classe fica em
<code>{'Livro.prototype'}</code>; uma propriedade criada no
<code>{'constructor'}</code> fica na instância.

</div>
<div slot="mistakes">

Não substituir indiscriminadamente o método por arrow function, porque ela herda outro <code>{"this"}</code>.

</div>
</Exercise>

<Exercise
  id="ltw-evento-lista"
  revision={1}
  title="Remover itens criados depois"
  explanation="/cadeiras/ltw/javascript-dom-eventos/#eventos-e-delegação"
  answer={{"kind": "self", "checklist": ["Usei closest e verificação de pertença.", "Expliquei alvo, listener e as duas operações."]}}
>

Descreve um listener único num <code>{"ul"}</code> que remove o <code>{"li"}</code> quando o utilizador clica no botão Remover, incluindo quando clica num <code>{"span"}</code> dentro do botão. Distingue target de <code>{"currentTarget"}</code> e as funções <code>{"preventDefault"}</code>/<code>{"stopPropagation"}</code>.

<div slot="hint">

Procura o botão a partir do alvo com closest.

</div>
<div slot="hint-more">

Depois procura o <code>{"li"}</code>; o listener está no <code>{"ul"}</code> e vê o clique que subiu.

</div>
<div slot="solution">

O listener recebe o evento no <code>{"ul"}</code>. Usa <code>{"evento.target.closest"}</code> com um seletor dos botões de remoção, confirma que o botão pertence à lista e remove o item com `botao.closest('li').remove()`. O alvo pode ser o <code>{"span"}</code>; <code>{"currentTarget"}</code> é o <code>{"ul"}</code>. <code>{"preventDefault"}</code> impediria uma ação nativa, como submissão, enquanto <code>{"stopPropagation"}</code> impediria continuar a subida. A delegação funciona nos novos itens sem lhes acrescentar listeners.

</div>
<div slot="mistakes">

Não testar target como se fosse sempre o botão, nem confundir cancelamento com propagação.

</div>
</Exercise>

<Exercise

  answer={{
    kind: 'code',
    language: 'javascript',
    starter: 'function ordenarPrecos(precos) {\n  return [];\n}',
    tests: [
      { name: 'Ordem numérica e entrada preservada', code: 'const precos = [8, 25, 3];\nconsole.log(JSON.stringify(ordenarPrecos(precos)));\nconsole.log(JSON.stringify(precos));', output: '[3,8,25]\n[8,25,3]' },
      { name: 'Lista vazia', code: 'console.log(JSON.stringify(ordenarPrecos([])));', output: '[]' },
      { name: 'Repetidos e zero', code: 'console.log(JSON.stringify(ordenarPrecos([12, 0, 12, 2])));', output: '[0,2,12,12]' },
      { name: 'Cópia independente', code: 'const precos = [4];\nconst copia = ordenarPrecos(precos);\ncopia.push(9);\nconsole.log(JSON.stringify(precos));\nconst vazio = [];\nordenarPrecos(vazio).push(9);\nconsole.log(JSON.stringify(vazio));', output: '[4]\n[]' },
    ],
  }}
>

Define `ordenarPrecos(precos)`: recebe um array de inteiros não negativos e devolve outro array com os mesmos preços por ordem crescente, conservando repetições e a entrada. Mesmo para a lista vazia ou com um preço, devolve um array independente. Não imprimas dentro da função.

<div slot="hint"><code>{"sort"}</code> altera o array e, sem comparador, compara texto.</div>
<div slot="hint-more">Cria uma cópia com spread ou slice antes de ordenar com um comparador numérico.</div>
<div slot="solution">

```js
function ordenarPrecos(precos) {
  return [...precos].sort((a, b) => a - b);
}
```

A cópia recebe a ordenação; `precos` conserva a ordem original. `precos.slice().sort((a, b) => a - b)` também resolve. Um algoritmo que insira os valores numa nova lista ordenada é igualmente válido.

</div>
<div slot="mistakes">Não ordenar a entrada diretamente, devolver a própria entrada quando tem poucos valores, remover repetições com Set ou comparar os números como strings.</div>
</Exercise>
