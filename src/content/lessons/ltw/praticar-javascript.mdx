<Exercise
  id="ltw-array-partilhado"
  title="Seguir uma cópia superficial"
  explanation="/cadeiras/ltw/javascript-dom-eventos/#arrays-e-funções-como-valores"
  answer={{"kind": "self", "checklist": ["Obtive 9, 2 e 1.", "Expliquei arrays diferentes e objeto partilhado."]}}
>

Prevê os três valores escritos e explica a diferença entre reatribuição e mutação.

```js
const a = [{ n: 2 }, { n: 5 }];
const b = a.filter((x) => x.n < 4);
b[0].n = 9;
console.log(a[0].n, a.length, b.length);
```

<div slot="hint">

filter cria outro array, mas não copia profundamente os objetos.

</div>
<div slot="hint-more">

O primeiro objeto pertence aos dois arrays por referência.

</div>
<div slot="solution">

A saída é 9 2 1. Os arrays são diferentes e conservam as suas quantidades de entradas. O objeto selecionado é partilhado e a mutação de n é observada a partir de a. const impede reatribuir a ou b, não alterar objetos referidos.

</div>
<div slot="mistakes">

Não prever 2 para a[0].n nem tratar const como congelamento profundo.

</div>
</Exercise>

<Exercise
  id="ltw-contador-closure"
  title="Prever ambientes separados"
  explanation="/cadeiras/ltw/javascript-dom-eventos/#âmbito-e-closures"
  answer={{"kind": "self", "checklist": ["Obtive 3 12 5 14.", "Segui dois estados independentes."]}}
>

Prevê a saída e mostra o estado de n de cada closure após cada chamada.

```js
function contador(inicio) {
  let n = inicio;
  return () => (n += 2);
}
const a = contador(1);
const b = contador(10);
console.log(a(), b(), a(), b());
```

<div slot="hint">

Cada chamada a contador cria uma ligação de n diferente.

</div>
<div slot="hint-more">

As chamadas seguem da esquerda para a direita.

</div>
<div slot="solution">

A saída é 3 12 5 14. Após a primeira chamada: n de a=3 e n de b=10. Depois b=12; depois a=5; por fim b=14. Ambas conservam a função e o ambiente em que foram criadas, mas não partilham n.

</div>
<div slot="mistakes">

Não usar um único contador global para as duas closures.

</div>
</Exercise>

<Exercise
  id="ltw-metodo-this"
  title="Manter o recetor do método"
  explanation="/cadeiras/ltw/javascript-dom-eventos/#objetos-this-e-protótipos"
  answer={{"kind": "self", "checklist": ["Expliquei a falha de f().", "Distingui protótipo e propriedade própria."]}}
>

Em modo estrito, um objeto tem titulo: Redes e método normal nome() que devolve this.titulo. Guarda-se `const f = livro.nome`. Compara livro.nome(), f() e f.bind(livro)(). Onde fica um método definido por class Livro?

<div slot="hint">

Uma função normal não fica ligada ao objeto só por ser lida numa propriedade.

</div>
<div slot="hint-more">

bind fixa o recetor; métodos de classe são habitualmente partilhados no protótipo.

</div>
<div slot="solution">

livro.nome() devolve Redes. f() tem this indefinido neste exemplo e falha ao ler titulo. f.bind(livro)() devolve Redes. Um método normal definido na classe fica em Livro.prototype; uma propriedade criada no constructor fica na instância.

</div>
<div slot="mistakes">

Não substituir indiscriminadamente o método por arrow function, porque ela herda outro this.

</div>
</Exercise>

<Exercise
  id="ltw-evento-lista"
  title="Remover itens criados depois"
  explanation="/cadeiras/ltw/javascript-dom-eventos/#eventos-e-delegação"
  answer={{"kind": "self", "checklist": ["Usei closest e verificação de pertença.", "Expliquei alvo, listener e as duas operações."]}}
>

Descreve um listener único num ul que remove o li quando o utilizador clica no botão Remover, incluindo quando clica num span dentro do botão. Distingue target de currentTarget e as funções preventDefault/stopPropagation.

<div slot="hint">

Procura o botão a partir do alvo com closest.

</div>
<div slot="hint-more">

Depois procura o li; o listener está no ul e vê o clique que subiu.

</div>
<div slot="solution">

O listener recebe o evento no ul. Usa evento.target.closest com um seletor dos botões de remoção, confirma que o botão pertence à lista e remove o item com `botao.closest('li').remove()`. O alvo pode ser o span; currentTarget é o ul. preventDefault impediria uma ação nativa, como submissão, enquanto stopPropagation impediria continuar a subida. A delegação funciona nos novos itens sem lhes acrescentar listeners.

</div>
<div slot="mistakes">

Não testar target como se fosse sempre o botão, nem confundir cancelamento com propagação.

</div>
</Exercise>
