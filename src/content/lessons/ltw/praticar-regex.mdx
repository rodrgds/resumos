<Exercise
  revision={1}
  id="ltw-codigo-padrao"
  title="Construir um código completo"
  explanation="/cadeiras/ltw/expressoes-regulares/#construir-e-testar-um-formato"
  answer={{"kind": "self", "checklist": ["Agrupei e ancorei as alternativas.", "Previ os quatro casos e a captura 0007."]}}
>

Um código tem prefixo A ou B, hífen e exatamente quatro dígitos. Constrói um padrão JavaScript para o valor completo, capturando os dígitos. Testa mentalmente <code>{"A-0007"}</code>, <code>{"B-42"}</code>, X<code>{"A-0007"}</code> e <code>{"C-0007"}</code>.

<div slot="hint">

Agrupa as alternativas antes de fixar início e fim.

</div>
<div slot="hint-more">

Usa grupo não capturante no prefixo e capturante nos quatro dígitos.

</div>
<div slot="solution">

Uma solução é `/^(?:A|B)-([0-9]{4})$/`, para entradas sem quebras de linha. <code>{"A-0007"}</code> passa e o grupo 1 vale 0007. <code>{"B-42"}</code> falha por comprimento, X<code>{"A-0007"}</code> falha pelo início e <code>{"C-0007"}</code> falha pelo prefixo. Não converter a captura para inteiro se precisas dos zeros iniciais.

</div>
<div slot="mistakes">

Não escrever <code>{"^A|B-...$"}</code> nem perder os zeros da captura.

</div>
</Exercise>

<Exercise
  revision={1}
  id="ltw-guloso-primeiro"
  title="Prever a primeira correspondência"
  explanation="/cadeiras/ltw/expressoes-regulares/#guloso-preguiçoso-e-primeiro-resultado"
  answer={{"kind": "self", "checklist": ["Obtive os dois resultados distintos.", "Defini a classe que exclui o fecho."]}}
>

No texto `preço [12] e [35]`, escreve a primeira correspondência de `/\[.*\]/` e `/\[.*?\]/`. Propõe uma classe negada que pare no primeiro fecho.

<div slot="hint">

O início é o primeiro [ onde o padrão pode casar.

</div>
<div slot="hint-more">

Guloso tenta o máximo; preguiçoso tenta o mínimo que permite acabar.

</div>
<div slot="solution">

O guloso escolhe <code>{"[12]"}</code> e <code>{"[35]"}</code>. O preguiçoso escolhe <code>{"[12]"}</code>. Uma alternativa é `/\[[^\]]*\]/`, que admite apenas caracteres diferentes de ] dentro dos colchetes. A escolha gulosa não começa automaticamente no segundo [ para obter outra correspondência.

</div>
<div slot="mistakes">

Não esquecer que \* admite zero caracteres nem confundir primeiro início com menor resultado.

</div>
</Exercise>

<Exercise
  revision={1}
  id="ltw-captura-repetida"
  title="Exigir a mesma palavra"
  explanation="/cadeiras/ltw/expressoes-regulares/#capturas-e-referências"
  answer={{"kind": "self", "checklist": ["Distingui identidade de formato de palavra.", "Indiquei o primeiro resultado de cada."]}}
>

Compara `/\b(\w+)\s+\1\b/` e `/\b\w+\s+\w+\b/` sobre `rede web rede rede`. Qual o primeiro resultado de cada?

<div slot="hint">

A referência exige o texto da primeira captura.

</div>
<div slot="hint-more">

O segundo padrão só exige duas palavras quaisquer.

</div>
<div slot="solution">

O padrão com referência escolhe rede rede no fim; a tentativa rede web falha porque web não é rede, e web rede também falha. O segundo escolhe rede web logo no início. A correspondência global não foi pedida, por isso paramos no primeiro resultado de cada padrão.

</div>
<div slot="mistakes">

Não tratar \1 como um novo grupo livre nem escolher a ocorrência repetida final em ambos.

</div>
</Exercise>

<Exercise
  revision={1}
  id="ltw-contexto-data"
  title="Validar formato e significado"
  explanation="/cadeiras/ltw/expressoes-regulares/#lookaround-e-backtracking"
  answer={{"kind": "self", "checklist": ["Usei (?!s) e identifiquei a ocorrência.", "Separei forma e calendário."]}}
>

Queremos encontrar livro que não é seguido de s, no texto `livros e livro`. Escreve um padrão com lookahead negativo. Depois explica por que `/^\d{4}-\d{2}-\d{2}$/` aceita <code>{"2026-02-31"}</code> e o que falta validar.

<div slot="hint">

A condição de contexto não deve consumir o caráter seguinte.

</div>
<div slot="hint-more">

O padrão da data só conta dígitos e separadores.

</div>
<div slot="solution">

`/livro(?!s)/` escolhe a segunda ocorrência, livro. O lookahead verifica a ausência de s sem consumir o que vem depois. O padrão da data aceita <code>{"2026-02-31"}</code> porque tem quatro, dois e dois dígitos nas posições certas. Falta verificar mês, dia e regras do calendário; uma regex de forma não prova a existência da data.

</div>
<div slot="mistakes">

Não usar uma classe que consome um caráter após livro quando se pede apenas uma asserção de contexto.

</div>
</Exercise>

<Exercise
  id="ltw-extrair-codigo"
  revision={1}
  title="Devolver a captura ou ausência"
  explanation="/cadeiras/ltw/expressoes-regulares/#construir-e-testar-um-formato"
  answer={{
    kind: 'code',
    language: 'javascript',
    starter: 'function numeroCodigo(texto) {\n  return null;\n}',
    tests: [
      { name: 'Zeros e ambos os prefixos', code: "console.log(JSON.stringify(numeroCodigo('LTW-042')));\nconsole.log(JSON.stringify(numeroCodigo('BD-007')));", output: '"042"\n"007"' },
      { name: 'Comprimento e prefixo inválidos', code: "console.log(numeroCodigo('LTW-42'));\nconsole.log(numeroCodigo('LTW-0042'));\nconsole.log(numeroCodigo('IA-042'));\nconsole.log(numeroCodigo('ltw-042'));", output: 'null\nnull\nnull\nnull' },
      { name: 'Entrada completa', code: "console.log(numeroCodigo('xLTW-042'));\nconsole.log(numeroCodigo('LTW-042x'));\nconsole.log(numeroCodigo(''));", output: 'null\nnull\nnull' },
      { name: 'Validação repetida', code: "console.log(JSON.stringify(numeroCodigo('BD-000')));\nconsole.log(JSON.stringify(numeroCodigo('BD-000')));", output: '"000"\n"000"' },
    ],
  }}
>

Define `numeroCodigo(texto)`: recebe uma string sem quebras de linha. Se toda a string tiver prefixo LTW ou BD, hífen e exatamente três dígitos de 0 a 9, devolve os dígitos como string. Caso contrário, devolve `null`. Chamadas repetidas devem dar o mesmo resultado.

<div slot="hint">Usa um grupo que capture os dígitos e fixa ambas as pontas do padrão.</div>
<div slot="hint-more">match devolve <code>{"null"}</code> quando não há correspondência. O índice 1 contém a primeira captura.</div>
<div slot="solution">

```js
function numeroCodigo(texto) {
  const resultado = texto.match(/^(?:LTW|BD)-([0-9]{3})$/);
  return resultado === null ? null : resultado[1];
}
```

`exec` sem flag global também resolve. Uma validação manual que cumpra o mesmo contrato passa os testes. Preserva os zeros, porque a captura é texto.

</div>
<div slot="mistakes">Não converter para número, devolver a correspondência inteira, aceitar apenas parte da entrada nem confundir <code>{"null"}</code> com a string '<code>{"null"}</code>'.</div>
</Exercise>
