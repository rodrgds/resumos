<Exercise
  revision={1}
  id="ltw-guloso-primeiro"
  title="Prever a primeira correspondência"
  explanation="/cadeiras/ltw/expressoes-regulares/#guloso-preguiçoso-e-primeiro-resultado"
  answer={{"kind": "self", "checklist": ["Obtive os dois resultados distintos.", "Defini a classe que exclui o fecho."]}}
>

No texto `preço [12] e [35]`, escreve a primeira correspondência de `/\[.*\]/` e `/\[.*?\]/`. Propõe uma classe negada que pare no primeiro fecho.

<div slot="hint">

O início é o primeiro [ onde o padrão pode casar.

</div>
<div slot="hint-more">

Guloso tenta o máximo; preguiçoso tenta o mínimo que permite acabar.

</div>
<div slot="solution">

O guloso produz uma única correspondência, <code>{"[12] e [35]"}</code>, do primeiro `[` ao último `]`. O preguiçoso produz <code>{"[12]"}</code>. Uma alternativa é `/\[[^\]]*\]/`, que admite apenas caracteres diferentes de ] dentro dos colchetes. A escolha gulosa não começa automaticamente no segundo [ para obter outra correspondência.

</div>
<div slot="mistakes">

Não esquecer que \* admite zero caracteres nem confundir primeiro início com menor resultado.

</div>
</Exercise>

<Exercise
  revision={1}
  id="ltw-captura-repetida"
  title="Exigir a mesma palavra"
  explanation="/cadeiras/ltw/expressoes-regulares/#capturas-e-referências"
  answer={{"kind": "self", "checklist": ["Distingui identidade de formato de palavra.", "Indiquei o primeiro resultado de cada."]}}
>

Compara `/\b(\w+)\s+\1\b/` e `/\b\w+\s+\w+\b/` sobre `rede web rede rede`. Qual o primeiro resultado de cada?

<div slot="hint">

A referência exige o texto da primeira captura.

</div>
<div slot="solution">

O padrão com referência tenta primeiro em cada posição inicial. Em `rede web`, a captura é `rede` mas o texto seguinte é `web`, por isso falha. Em `web rede`, a captura é `web` e o seguinte é `rede`, por isso falha. Em `rede rede` no fim, a repetição confirma-se. O segundo padrão só exige duas palavras e escolhe `rede web` logo no início. A correspondência global não foi pedida, por isso paramos no primeiro resultado de cada padrão.

</div>
<div slot="mistakes">

Não tratar \1 como um novo grupo livre nem escolher a ocorrência repetida final em ambos.

</div>
</Exercise>

<Exercise
  revision={2}
  id="ltw-contexto-data"
  title="Validar formato e significado"
  explanation="/cadeiras/ltw/expressoes-regulares/#lookaround-e-backtracking"
  answer={{"kind": "self", "checklist": ["Usei uma asserção que não consome o separador e obtive 2026-03-01.", "Distingui extração, contexto e validade da data."]}}
>

Uma aplicação extrai datas com `/\b\d{4}-\d{2}-\d{2}\b/` de `Entrega: 2026-02-31; próxima: 2026-03-01`. Usa depois `(?!;)` para recusar uma correspondência seguida imediatamente de ponto e vírgula. Escreve o novo padrão, prevê o resultado de cada versão e explica que validação ainda falta antes de aceitar uma data.

<div slot="hint">

Segue primeiro a correspondência completa; só depois verifica o caráter seguinte.

</div>
<div slot="hint-more">

Coloca `(?!;)` depois da fronteira final. O mês e o dia ainda são apenas pares de dígitos.

</div>
<div slot="solution">

O padrão original encontra primeiro `2026-02-31`. Com `/\b\d{4}-\d{2}-\d{2}\b(?!;)/`, essa ocorrência falha porque vem seguida de `;`; a primeira correspondência passa a ser `2026-03-01`. O lookahead não consome caracteres. A fronteira final impede aceitar apenas um prefixo dos dígitos para fugir ao teste do separador. Nenhuma versão valida o calendário: fevereiro não tem 31 dias. Depois de extrair, verifica mês, dia e ano, incluindo anos bissextos.

</div>
<div slot="mistakes">

Não substituir a asserção por uma classe que consome o separador, nem aceitar uma data só porque tem o formato certo.

</div>
</Exercise>

<Exercise

  revision={1}
  title="Devolver a captura ou ausência"
  explanation="/cadeiras/ltw/expressoes-regulares/#construir-e-testar-um-formato"
  answer={{
    kind: 'code',
    language: 'javascript',
    starter: 'function numeroCodigo(texto) {\n  return null;\n}',
    tests: [
      { name: 'Zeros e ambos os prefixos', code: "console.log(JSON.stringify(numeroCodigo('LTW-042')));\nconsole.log(JSON.stringify(numeroCodigo('BD-007')));", output: '"042"\n"007"' },

      { name: 'Entrada completa', code: "console.log(numeroCodigo('xLTW-042'));\nconsole.log(numeroCodigo('LTW-042x'));\nconsole.log(numeroCodigo(''));", output: 'null\nnull\nnull' },
      { name: 'Validação repetida', code: "console.log(JSON.stringify(numeroCodigo('BD-000')));\nconsole.log(JSON.stringify(numeroCodigo('BD-000')));", output: '"000"\n"000"' },
    ],
  }}
>

Define `numeroCodigo(texto)`: recebe uma string sem quebras de linha. Se toda a string tiver prefixo LTW ou BD, hífen e exatamente três dígitos de 0 a 9, devolve os dígitos como string. Caso contrário, devolve `null`. Chamadas repetidas devem dar o mesmo resultado.

<div slot="hint">Usa um grupo que capture os dígitos e fixa ambas as pontas do padrão.</div>
<div slot="hint-more">match devolve <code>{"null"}</code> quando não há correspondência. O índice 1 contém a primeira captura.</div>
<div slot="solution">

```js
function numeroCodigo(texto) {
  const resultado = texto.match(/^(?:LTW|BD)-([0-9]{3})$/);
  return resultado === null ? null : resultado[1];
}
```

`exec` sem flag global também resolve. Uma validação manual que cumpra o mesmo contrato passa os testes. Preserva os zeros, porque a captura é texto.

</div>
<div slot="mistakes">Não converter para número, devolver a correspondência inteira, aceitar apenas parte da entrada nem confundir <code>{"null"}</code> com a string '<code>{"null"}</code>'.</div>
</Exercise>
