Depois de trocar dados como JSON entre o navegador e o servidor, esta página responde como representar dados em XML e selecionar partes com XPath.

XML representa dados e documentos com elementos e atributos definidos pelo formato que escolhemos. Ao contrário do HTML, não tem um vocabulário fixo de etiquetas, ou seja nenhuma etiqueta traz significado para o navegador. XPath seleciona partes dessa organização em árvore, ou seja cada elemento, atributo ou texto como um nó, ou calcula valores a partir deles.

## Documento bem formado

```xml
<?xml version="1.0" encoding="UTF-8"?>
<catalogo>
  <livro id="r1">
    <titulo>Redes</titulo>
    <preco>18</preco>
  </livro>
  <livro id="a1">
    <titulo>Algoritmos</titulo>
    <preco>25</preco>
  </livro>
  <livro id="s1">
    <titulo>SQL</titulo>
    <preco>12</preco>
  </livro>
</catalogo>
```

Existe um único elemento raiz, `catalogo`. As etiquetas fecham pela ordem inversa à abertura, os nomes distinguem maiúsculas e os valores de atributos usam aspas. `<livro id=r1>` não é bem formado; `<Titulo>Redes</titulo>` também não. Elementos vazios podem usar `<aviso/>`.

O nó raiz do documento contém o elemento `catalogo`; não são o mesmo nó. Cada `livro` tem um atributo `id` e dois elementos filhos. Os valores como `Redes` são nós de texto. Mudanças de linha e indentação também podem criar nós de texto. Atributos não são filhos na árvore XPath.

`&amp;` representa `&`, e `&lt;` representa `<` em texto. Uma secção `<![CDATA[...]]>` permite texto que não é interpretado como marcação, mas não pode conter o seu próprio terminador `]]>`. Comentários não podem conter `--` no interior.

## Boa formação e validade

Boa formação verifica as regras sintáticas do XML. Validade exige também cumprir um contrato, como DTD, XML Schema ou Relax NG. Um documento com `<preco>caro</preco>` pode ser bem formado e falhar um esquema que exija número.

Uma DTD possível para o catálogo, sem repetir aqui o documento inteiro:

```xml
<!ELEMENT catalogo (livro*)>
<!ELEMENT livro (titulo, preco)>
<!ATTLIST livro id ID #REQUIRED>
<!ELEMENT titulo (#PCDATA)>
<!ELEMENT preco (#PCDATA)>
```

`livro*` permite zero ou mais livros. `(titulo, preco)` exige os dois nessa ordem. O atributo `id` é obrigatório, com unicidade e formato de ID. `#PCDATA` admite texto, mas esta DTD não exige que o preço seja numérico. Um XSD pode acrescentar tipos, como `xs:decimal`, e restrições. Uma DTD não é uma base de dados nem substitui a verificação de regras de negócio.

Ao processar XML não confiável, não atives resolução arbitrária de entidades externas nem carregamento de recursos do cliente. Esses mecanismos podem expor ficheiros ou fazer pedidos do servidor. O formato estar bem formado não o torna seguro.

## Caminhos XPath

Vamos usar XPath 1.0, como no DOMXPath de PHP. O contexto é o nó a partir do qual uma expressão é avaliada.

| Expressão                            | Resultado sobre o catálogo                                 |
| ------------------------------------ | ---------------------------------------------------------- |
| `/catalogo/livro`                    | Os três elementos `livro`                                  |
| `/catalogo/livro/titulo`             | Os três elementos `titulo`                                 |
| `/catalogo/livro/titulo/text()`      | Os seus nós de texto                                       |
| `//livro`                            | Livros descendentes do documento, em qualquer profundidade |
| `/catalogo/livro/@id`                | Atributos `id` dos livros                                  |
| `/catalogo/livro[@id='s1']/titulo`   | O elemento cujo texto é SQL                                |
| `/catalogo/livro[preco < 20]/titulo` | Títulos Redes e SQL                                        |
| `count(/catalogo/livro)`             | O número 3                                                 |
| `sum(/catalogo/livro/preco)`         | O número 55                                                |

`/` no início fixa o nó raiz do documento. Entre passos, `/` liga o eixo de filhos habitual. `//` abrevia um percurso por descendentes, não apenas filhos diretos. `.` representa o contexto e `..` o pai. `@` seleciona atributos; `*` seleciona elementos com qualquer nome nesse passo.

## Predicados e posição

Um predicado entre `[]` filtra os candidatos do passo em que aparece. `[preco < 20]` avalia o preço de cada livro candidato. `[2]` equivale a uma condição sobre a posição, que começa em 1.

```text
/catalogo/livro[2]/titulo
/catalogo/livro[preco < 20][1]/titulo
/catalogo/livro[1][preco < 20]/titulo
```

A primeira dá Algoritmos. A segunda primeiro filtra baratos e depois escolhe o primeiro, Redes. A terceira escolhe o primeiro livro e só depois verifica o preço. Neste catálogo também dá Redes, mas não daria o mesmo se o primeiro livro custasse 30. A ordem dos filtros faz parte da pergunta.

`//livro[1]` escolhe livros que são o primeiro `livro` entre os irmãos em cada grupo relevante. `(//livro)[1]` escolhe um único primeiro livro do conjunto global. Quando só há um `catalogo`, podem coincidir; com várias secções, a diferença torna-se visível.

Podemos combinar condições com `and`, `or` e `not`. `contains(titulo, 'Red')` procura texto contido; `starts-with` verifica prefixo; `normalize-space` remove espaços exteriores e reduz sequências de espaços. `last()` usa a última posição. `|` une conjuntos de nós. Eixos como `ancestor::`, `descendant::` e `following-sibling::` permitem explicitar relações da árvore.

Com vários nós, compara existência e ausência com cuidado. Sobre `<livro><categoria>redes</categoria><categoria>web</categoria></livro>`, `categoria = 'web'` é verdadeiro, mas `categoria != 'web'` também é, porque existe uma categoria diferente. `not(categoria = 'web')` é falso porque uma das categorias é web. Para pedir "nenhuma categoria é web", usa a negação da igualdade.

Uma igualdade como `ingredientes/ingrediente = 'arroz'` em XPath 1.0 é verdadeira se algum dos nós selecionados tiver esse valor de texto. Não exige que todos os ingredientes sejam arroz. Essa distinção é útil em consultas de receitas ou catálogos com várias categorias.

## Namespaces

Um namespace distingue vocabulários através de um URI. O prefixo é uma abreviatura local, não a identidade definitiva do nome:

```xml
<c:catalogo xmlns:c="urn:biblioteca">
  <c:livro id="r1"><c:titulo>Redes</c:titulo></c:livro>
</c:catalogo>
```

`c:livro` pertence ao namespace `urn:biblioteca`. Outro documento pode usar prefixo `b` para o mesmo URI, sem mudar esse nome expandido. Declarar `xmlns="urn:biblioteca"` coloca elementos sem prefixo nesse namespace. A declaração por defeito não coloca automaticamente atributos sem prefixo no namespace.

Em XPath 1.0, um nome sem prefixo procura elementos sem namespace. Para consultar um documento com namespace por defeito, regista um prefixo na consulta:

```php
$xpath->registerNamespace('b', 'urn:biblioteca');
$livros = $xpath->query('/b:catalogo/b:livro');
```

O prefixo `b` da consulta não precisa de ser o `c` do documento. Precisa de apontar para o mesmo URI. O URI identifica o namespace; não implica que o programa deva descarregar algo desse endereço.

## Tecnologias relacionadas

XPath seleciona. XSLT transforma XML, por exemplo em HTML ou noutro XML. XQuery consulta e constrói resultados. XSL-FO descreve formatação de documentos, frequentemente para PDF. SVG é um vocabulário XML para gráficos. Um documento XML não ganha validade, namespaces ou um esquema só por usar etiquetas; é o formato e o processamento escolhidos que dão essas propriedades. JSON também pode ter contratos de validação, por isso a escolha não se reduz a "XML validado, JSON sem regras".
