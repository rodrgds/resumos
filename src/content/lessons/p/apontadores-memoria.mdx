Um apontador guarda o endereço de um objeto. Saber o endereço permite aceder ao objeto, mas não garante que ele ainda existe, que o acesso é permitido ou que o apontador é responsável por o destruir. Estas perguntas têm de ser respondidas separadamente.

## Endereço de e dereferenciação

`&a` obtém o endereço de `a`. Numa declaração, `int* p` define um apontador para `int`. Numa expressão, `*p` **desreferencia** o apontador, ou seja, acede ao objeto apontado. `p = &b` muda o endereço guardado; `*p = 7` muda o objeto nesse endereço.


No início, `p` e `q` apontam para `a`. `*q += 2` altera `a` de `3` para `5`. Depois, `p = &b` muda apenas `p`; `q` continua a apontar para `a`. `*p -= 1` altera `b` para `7`. Os dois apontadores são objetos distintos, embora tenham começado com o mesmo valor.

Dois acessos ao mesmo objeto são **aliases**. Uma cópia de apontador copia um endereço, não duplica o objeto apontado. Imprimir um endereço pode ajudar a comparar identidades, mas o seu número depende da execução e não serve como saída fixa de um exercício.

## Apontadores nulos e const

`nullptr` representa ausência de objeto. Podes compará-lo e testá-lo; não podes desreferenciá-lo. `int* p;` deixa um apontador local sem inicialização. Em C++17, ler esse valor indeterminado ou tentar usá-lo não tem resultado válido em que possas confiar.

| Declaração           | Pode mudar o endereço? | Pode alterar o `int` por esse acesso? |
| -------------------- | ---------------------- | ------------------------------------- |
| `int* p`             | Sim                    | Sim                                   |
| `const int* p`       | Sim                    | Não                                   |
| `int* const p`       | Não                    | Sim                                   |
| `const int* const p` | Não                    | Não                                   |

`const int* p` não torna necessariamente constante o objeto. Se o original não é `const`, outro acesso modificável pode alterá-lo. Já retirar `const` para modificar um objeto originalmente constante tem comportamento indefinido.

## Apontadores e arrays

Um array converte-se, em muitas expressões, num apontador para o primeiro elemento. `p + i` avança `i` elementos do tipo apontado, não `i` bytes. `p[i]` equivale a `*(p + i)` quando essa operação é válida.

```cpp
// Excerto com um array vivo de quatro elementos.
int v[] = {10, 20, 30, 40};
int* inicio = v;
int* fim = v + 4;
```

`*(inicio + 2)` vale `30`. `fim` é a posição imediatamente depois do array, válida para marcar o fim de um intervalo. Não é um elemento e não se desreferencia. Avançar para além dessa posição também sai dos limites permitidos. Subtrair dois apontadores para elementos do mesmo array, ou para a posição depois do fim, dá a distância em elementos.

A aritmética de apontadores não serve para saltar entre objetos independentes. O intervalo habitual é `[inicio, fim)`: inclui o início e exclui o fim. A página [Templates e STL](/cadeiras/p/templates-stl/#iteradores) usa esta convenção nos algoritmos.

## Pilha, área livre e duração de vida

Uma variável local normal tem **duração automática** e é destruída ao sair do bloco. A implementação costuma guardar estes objetos na pilha, ou _stack_. Um objeto criado com `new` tem duração dinâmica e permanece até à destruição explícita. O seu armazenamento vem da área livre, habitualmente chamada _heap_. A norma descreve durações de armazenamento; não exige uma organização física específica com estes nomes.

Um apontador local e o objeto dinâmico para o qual aponta têm vidas diferentes. Ao sair da função, destruir o apontador não destrói um objeto criado com `new`. Retornar o endereço de uma variável local também não prolonga a vida dessa variável.

```cpp
// Código incorreto para análise. Não executar.
int* endereco_invalido() {
    int local = 5;
    return &local;
}
```

O objeto `local` morre ao sair da função. O endereço devolvido fica **pendente**, ou _dangling_. Não existe uma "saída esperada" para a leitura por esse endereço. Retorna o valor, ou usa um objeto com propriedade e duração adequadas.

## Alocação dinâmica com new e delete

`new T(...)` cria um objeto e devolve o seu endereço. `new T[n]` cria um array. Usa `delete` para o primeiro e `delete[]` para o segundo. A troca tem comportamento indefinido. `new` normal lança `std::bad_alloc` se não conseguir reservar memória.

<CodePlayground

  }
/>

Saída:

```text
Soma: 10
```

O tamanho é limitado para evitar uma reserva descontrolada e para manter a soma em `int`. `new int[n]{}` inicializa os elementos a zero. O ciclo substitui-os por `1`, `2`, `3` e `4`, somando `10`. Para `n = 0`, a soma é `0` e `delete[]` continua válido. O endereço de um array vazio não autoriza qualquer indexação.

## Fugas de memória e double-free

Há fuga quando um recurso reservado deixa de ter uma forma válida de ser libertado. Sobrescrever o único apontador dono perde essa possibilidade. Libertar duas vezes o mesmo objeto causa _double-free_; aceder depois da libertação é _use-after-free_. Ambos têm comportamento indefinido.

Depois de `delete p`, todos os aliases do objeto ficam pendentes. Fazer `p = nullptr` evita um uso posterior por esse nome e permite `delete p` sem efeito. Não corrige os outros aliases, não deteta automaticamente o erro e não torna a desreferenciação nula segura. `delete nullptr` é válido; `*nullptr` não é.

## O essencial de RAII e smart pointers

**RAII**, _Resource Acquisition Is Initialization_, liga um recurso à duração de vida de um objeto dono. O construtor adquire ou recebe o recurso; o destrutor liberta-o. Ao sair normalmente de um âmbito, ou quando uma exceção sai dele, os donos automáticos são destruídos. Assim, a libertação não depende de repetir `delete` em cada saída.

`std::vector` e `std::string` já gerem a sua memória. `std::unique_ptr<T>` representa propriedade exclusiva de um objeto dinâmico; não se copia, mas pode transferir a propriedade por movimento. `get()` fornece um apontador observador, sem transferir propriedade.

Saída:

```text

```

Depois do movimento, `primeiro` está vazio e `segundo` é o dono. O inteiro não mudou de endereço e `observador` ainda é válido. Ao destruir `segundo`, o inteiro desaparece; qualquer observador que sobreviva fica pendente. Nunca faças `delete observador`.

`std::shared_ptr` permite vários donos e destrói o objeto quando termina a última propriedade forte. Tem custo de gestão e não resolve ciclos de propriedade fortes. Usa-o quando o modelo realmente exige propriedade partilhada, não para evitar decidir quem é o dono. `std::weak_ptr` permite observar essa propriedade sem a prolongar.

## Ler a memória em palavras

Para seguir código com apontadores, desenha os objetos vivos, os seus valores e as setas separadamente. Em cada atribuição, identifica se o lado esquerdo é o apontador ou o objeto apontado. Em cada destruição, risca o objeto e marca todos os aliases como pendentes. Esta forma de raciocinar continua a ser necessária quando usas smart pointers: a gestão automática evita muitas fugas, mas um observador ainda pode durar mais que o dono.
