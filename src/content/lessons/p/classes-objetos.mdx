Dois inteiros soltos aceitam `70` minutos. Esta página constrói um relógio que recusa esse estado desde a criação e o conserva em cada operação.

Uma classe define o estado e as operações que o mantêm válido. Cada objeto conserva o seu próprio estado dentro do contrato: as promessas sobre que valores são válidos. Um relógio com dois inteiros permite estados sem sentido, como `70` minutos.

## Definir uma classe e criar objetos

A interface pública diz o que o chamador pode fazer. Os membros privados guardam a representação e só são acessíveis aos membros e amigos da classe. **Encapsular** é manter uma fronteira que preserva o significado dos dados, não apenas escrever getters e setters para cada campo.

Este relógio guarda minutos desde a meia-noite, numa única representação. O seu **invariante** é `0 <= minutos_ < 1440`. O chamador conhece horas e minutos; não precisa de saber a representação escolhida. Guardar `hora_`, `minuto_` e `minutos_` em simultâneo obrigaria a atualizar três representações da mesma informação.

Programa completo para compilar localmente:

`throw` abandona a operação atual e procura um tratador. Aqui serve apenas para recusar construção ou alteração inválida; a página [Exceções e testes](/cadeiras/p/excecoes-testes/#lançar-e-apanhar) explica a propagação completa. O destrutor de um objeto automático corre sempre na saída do âmbito, mesmo quando uma exceção atravessa esse âmbito.

```cpp
#include <iostream>
#include <stdexcept>

class Relogio {
public:
    Relogio(int hora, int minuto) {
        if (hora < 0 || hora >= 24 || minuto < 0 || minuto >= 60)
            throw std::invalid_argument("Hora invalida");
        minutos_ = 60 * hora + minuto;
    }
    int hora() const { return minutos_ / 60; }
    int minuto() const { return minutos_ % 60; }
    void avancar(int quantidade) {
        if (quantidade < 0 || quantidade > 1440)
            throw std::invalid_argument("Avanco invalido");
        minutos_ = (minutos_ + quantidade) % 1440;
    }
    bool operator==(const Relogio& outro) const {
        return minutos_ == outro.minutos_;
    }
private:
    int minutos_ = 0;
};

int main() {
    Relogio a(23, 50);
    Relogio b = a;
    a.avancar(25);
    const Relogio& leitura = a;
    std::cout << leitura.hora() << ":" << leitura.minuto() << "\n";
    std::cout << b.hora() << ":" << b.minuto() << "\n";
    std::cout << std::boolalpha << (a == Relogio(0, 15)) << "\n";
}
```

Saída:

```text
0:15
23:50
true
```

O construtor transforma `23:50` em `60 * 23 + 50 = 1430`. Avançar `25` produz `1455`, cujo resto por `1440` dá `15`, ou seja `0:15`. A cópia `b` conserva `1430` (`23:50`), porque cada objeto tem o seu próprio `minutos_`. Consulta por `const Relogio&` não copia o relógio nem o altera.

## Encapsulamento

O construtor rejeita horas fora de `0` a `23` e minutos fora de `0` a `59`. `avancar` aceita `0` a `1440`, por isso a soma continua representável. Nenhuma operação pública permite escrever `minutos_ = -1`.

A validação tem de acontecer antes de alterar o estado. Se `avancar(-5)` lança uma exceção, o relógio fica com o mesmo valor. Uma classe que permite um estado inválido e espera que cada chamador o corrija não está a proteger o seu invariante.

Não é necessário guardar simultaneamente `hora_`, `minuto_` e `minutos_`. Isso obrigaria a atualizar três representações da mesma informação. Aqui, `hora()` e `minuto()` calculam resultados a partir de um estado único.

## Construtores e destrutor

Um construtor tem o nome da classe e não tem tipo de retorno. Uma lista de inicialização, como `Marca(const std::string& nome) : nome_(nome)`, constrói os membros diretamente. Atribuir no corpo acontece depois da inicialização e não a substitui. Membros `const` e referências precisam de ser inicializados, não podem receber a primeira atribuição no corpo.

As bases são construídas primeiro; os membros são construídos pela ordem de declaração na classe, mesmo que a lista do construtor use outra ordem. Depois corre o corpo do construtor. O destrutor tem o nome `~Classe()` e não recebe parâmetros. Depois do seu corpo, os membros são destruídos na ordem inversa.

O bloco interior cria `B` antes de `C`, mas destrói `C` antes de `B`. `A` só morre no fim de `main`. Não chames o destrutor de um objeto automático; um objeto dinâmico é destruído pelo dono, por exemplo através de `unique_ptr`.

`explicit` num construtor evita certas conversões implícitas para o tipo. Neste caso, exige que a construção de uma `Marca` seja intencional. O exemplo escreve mensagens para tornar a ordem visível; em código habitual, o destrutor trata recursos e evita lançar exceções.

## Métodos const

O `const` depois dos parâmetros, como em `int hora() const`, permite chamar o método num objeto constante ou por uma referência constante. Dentro do método, `this` dá acesso constante ao objeto. `avancar` não é constante porque altera o estado.

Uma consulta que devolve um apontador modificável para um membro pode permitir alterar estado indiretamente. Por isso, const-correctness também depende dos tipos devolvidos, não apenas da palavra `const` no método. Usa resultados por valor ou acessos de leitura quando a interface promete só consultar.

## this, static e visibilidade

Numa chamada `a.avancar(25)`, `this` aponta para `a`. `this->minutos_` e `minutos_` acedem ao mesmo membro dentro do método. Usa `this` quando ajuda a distinguir nomes ou a devolver o próprio objeto.

Um membro `static` pertence à classe e não a um objeto específico. Conta objetos criados, por exemplo:

```cpp
// Excerto: cada objeto recebe um número sequencial.
struct Contador {
    static int criados;
    int id;
    Contador() : id(++criados) {}
};
int Contador::criados = 0;
```

Depois de `Contador a; Contador b;`, `criados` vale `2`, com `a.id == 1` e `b.id == 2`. Uma função estática não tem `this`; só pode aceder a membros de instância se receber um objeto. Uma variável estática local tem duração até ao fim do programa, embora o seu nome só seja visível na função.

Em `class`, os membros são privados por defeito. `public` expõe o contrato. `protected` dá acesso também a classes derivadas e aumenta a quantidade de código capaz de alterar a representação. Preferir estado privado facilita manter o invariante, inclusive quando existe herança.

## Sobrecarga de operadores

`operator==` define a comparação entre dois relógios e devolve `bool`. Como ambos usam a mesma representação normalizada, basta comparar `minutos_`. Um operador deve conservar o significado habitual. Não uses `+` para uma operação surpreendente que destrói ou altera o operando esquerdo. Quando o operador precisa de simetria entre tipos diferentes, prefere uma função livre que recebe os dois operandos; um operador membro recebe o operando esquerdo através de `this`.

A sobrecarga não permite criar operadores novos, mudar a precedência ou modificar operações entre dois tipos fundamentais. Pelo menos um dos operandos deve ter tipo de classe ou enumeração. Um operador membro recebe o operando esquerdo através de `this`; um operador livre recebe os dois. `friend` concede acesso privado a uma função específica, não torna todos os campos públicos.

## Copiar objetos com memória própria

:::tip[Ideia-chave]

O construtor estabelece o **invariante** e cada operação pública conserva-o. Valida antes de alterar o estado, para uma falha deixar o objeto intacto.
:::

Quando todos os membros gerem os seus recursos, a cópia gerada costuma servir. Se um membro é um apontador dono, copiar só o endereço não duplica o recurso. A página [Cópia, movimento e propriedade](/cadeiras/p/copia-propriedade/) constrói essa cópia independente.
