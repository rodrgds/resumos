Um ficheiro de texto precisa de um formato. Vamos usar uma linha por registo, com um nome sem espaços e uma nota de `0` a `20`. A biblioteca lê caracteres; o teu programa verifica se eles cumprem o formato.

## Abrir, escrever e fechar

`std::ifstream` abre para leitura e `std::ofstream` para escrita. Por defeito, `ofstream` substitui o conteúdo de um ficheiro existente. Usa `std::ios::app` quando o contrato é acrescentar ao fim. O caminho relativo é resolvido a partir da pasta de trabalho do processo, não da pasta onde está o código.

Programa completo para compilar localmente:

```cpp
#include <fstream>
#include <iostream>
#include <string>

int main() {
    {
        std::ofstream saida("notas.txt");
        if (!saida) { std::cout << "Erro de abertura\n"; return 0; }
        saida << "Ana 15\nRui 12\n";
        saida.close();
        if (!saida) { std::cout << "Erro de escrita\n"; return 0; }
    }
    std::ifstream entrada("notas.txt");
    if (!entrada) { std::cout << "Erro de leitura\n"; return 0; }
    std::string nome;
    int nota = 0;
    int total = 0;
    while (entrada >> nome >> nota) {
        std::cout << nome << ": " << nota << "\n";
        total += nota;
    }
    if (entrada.bad()) { std::cout << "Erro de I/O\n"; return 0; }
    std::cout << "Total: " << total << "\n";
}
```

Saída:

```text
Ana: 15
Rui: 12
Total: 27
```

O programa cria `notas.txt` na pasta de trabalho e corre localmente, porque o executor do navegador não cria ficheiros. Fecha a escrita antes de leres e verifica `close()`, pois o destrutor fecha mas não trata um erro final de escrita.

O leitor acima demonstra leitura por tokens num ficheiro conhecido. Para dados externos, a leitura por linhas seguinte distingue um registo incompleto do fim normal.

## Ler sem antecipar o fim

O ciclo `while (entrada >> nome >> nota)` só entra no corpo depois de ler os dois campos. `eof()` indica que uma operação anterior encontrou o fim; não prevê se a próxima leitura vai resultar. Por isso, `while (!entrada.eof())` pode repetir o último registo ou usar dados incompletos.

Os fluxos conservam estado. `fail()` sinaliza falha de uma operação ou conversão; `bad()` sinaliza uma falha grave de I/O; `eof()` indica encontro do fim. Estes estados podem coexistir. Depois de uma falha, novas leituras não prosseguem normalmente até limpar o estado com `clear()` e tratar a entrada problemática. Limpar o estado sem consumir ou corrigir a causa pode criar um ciclo sem progresso.

## Separar linhas e registos

A leitura por tokens ignora espaços e fins de linha. Se o formato exige exatamente um registo por linha, lê primeiro a linha e interpreta-a num `istringstream`. Esta classe permite tratar uma string como um fluxo, sem abrir outro ficheiro.

:::tip[Ideia-chave]

Usa a própria leitura como condição: `while (entrada >> nome >> nota)` só entra com um par válido. `eof()` descreve o passado e não prevê a próxima leitura.
:::

A linha de Eva traz um inteiro fora do intervalo e a de Leo traz campos extra, que `(registo >> extra)` deteta. Uma linha vazia ou `12abc` também é rejeitada.

Cada iteração cria um fluxo novo para a linha. Uma falha de conversão não contamina a seguinte. Se o formato permitisse nomes com espaços, teria de usar outra separação, por exemplo um delimitador, e definir como esse delimitador pode aparecer nos campos.

## Binário não é memória bruta portátil

`std::ios::binary` evita transformações de texto próprias da plataforma. Não define por si só um formato de dados. Escrever os bytes de uma struct depende do padding, da ordem dos bytes e da representação dos tipos. Um formato portátil especifica tamanhos, ordem dos bytes e codificação, ou usa uma biblioteca que trate essas decisões.

## Caso resolvido: fim depois de um nome

Imagina a linha `Ana`, sem nota. `getline` resulta porque leu uma linha. A extração do nome resulta, mas a da nota falha. O programa rejeita o registo e não usa o valor anterior de `nota`. Agora imagina um ficheiro vazio: `getline` falha antes do corpo do ciclo e não existe registo a validar. Os dois casos chegam ao fim dos dados, mas têm significados diferentes.
