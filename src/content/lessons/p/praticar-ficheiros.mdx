<Exercise
  id="eof-ciclo"
  revision={1}
  title="O fim não prevê a leitura"
  explanation="/cadeiras/p/ficheiros/#ler-sem-antecipar-o-fim"
  answer={{
    kind: 'self',
    checklist: [
      'Distingui encontro do fim de previsão da próxima leitura.',
      'Expliquei o risco de usar valores antigos.',
      'Usei a própria leitura como condição.',
    ],
  }}
>
  <div>
    Um ficheiro contém <code>Ana 15</code> e termina com um fim de linha. Um
    ciclo testa <code>!entrada.eof()</code> antes de tentar ler nome e nota.
    Explica por que pode executar o corpo mais uma vez e como corrigir.
  </div>
  <div slot="hint">
    <p>Lembra-te de que eof descreve uma tentativa anterior.</p>
  </div>
  <div slot="hint-more">
    <div>
      A leitura do último registo pode acabar antes de tentar ler para além
      dele.
    </div>
  </div>
  <div slot="solution">
    <div>
      Depois do registo válido, ainda pode faltar a tentativa que deteta o fim.
      O ciclo entra outra vez, a extração falha e o corpo pode usar valores
      antigos. A condição deve ser{' '}
      <code>while (entrada &gt;&gt; nome &gt;&gt; nota)</code>, para só usar um
      par lido com sucesso. Para um formato de uma linha por registo, lê e
      valida cada linha.
    </div>
  </div>
  <div slot="mistakes">
    <p>Verificar eof não substitui confirmar se todos os campos foram lidos.</p>
  </div>
</Exercise>

<Exercise
  id="registo-extra"
  revision={1}
  title="Validar o formato completo"
  explanation="/cadeiras/p/ficheiros/#separar-linhas-e-registos"
  answer={{
    kind: 'choice',
    options: [
      {
        text: 'Não, há conteúdo adicional depois do inteiro.',
        correct: true,
        explanation: 'abc fica por consumir e forma um token extra.',
      },
      {
        text: 'Sim, a nota 12 está no intervalo.',
        correct: false,
        explanation: 'O intervalo é só uma das condições do formato.',
      },
      {
        text: 'Sim, qualquer texto depois do número é comentário.',
        correct: false,
        explanation: 'O formato não definiu comentários.',
      },
    ],
  }}
>
  <div>
    O leitor por linhas recebe <code>Eva 12abc</code>. A leitura de nome e
    inteiro pode obter Eva e 12. A linha deve ser aceite?
  </div>
  <div slot="hint">
    <p>O contrato permite só nome, inteiro e espaços finais.</p>
  </div>
  <div slot="hint-more">
    <p>Depois de ler 12, ficam os caracteres abc.</p>
  </div>
  <div slot="solution">
    <div>
      Não. O token extra <code>abc</code> viola o formato. O teste de conteúdo
      adicional rejeita a linha. Uma conversão parcial de um campo não significa
      que o registo inteiro é válido.
    </div>
  </div>
  <div slot="mistakes">
    <p>Não confundas um prefixo numérico válido com uma linha válida.</p>
  </div>
</Exercise>
