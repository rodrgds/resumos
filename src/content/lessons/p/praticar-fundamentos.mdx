<Exercise
  id="divisao-conversao"
  revision={2}
  title="Conversão e divisão inteira"
  explanation="/cadeiras/p/cpp-fundamentos/#operadores-e-divisão"
  answer={{
    kind: 'self',
    checklist: [
      'Obtive 2, 2.75 e -2 nos três resultados.',
      'Expliquei em que expressão a conversão antecede a divisão.',
      'Corrigi o cálculo da média sem alterar os valores de entrada.',
    ],
  }}
>
  Com <code>int soma = 11, n = 4;</code>, prevê os valores de
  <code>double a = soma / n;</code>,
  <code>double b = static_cast&lt;double&gt;(soma) / n;</code> e
  <code>int c = -soma / n;</code>. Uma média deve conservar a parte fracionária.
  Qual expressão serve e porquê? Não executes antes de prever.
  <div slot="hint">
    Determina primeiro o tipo de cada operando de <code>/</code>.
  </div>
  <div slot="solution">
    <code>a</code> vale <code>2.0</code>: a divisão inteira produz 2 antes da
    conversão para o destino. <code>b</code> vale <code>2.75</code>, pois um
    operando já é <code>double</code> quando a divisão é calculada.
    <code>c</code> vale <code>-2</code>, porque a divisão inteira trunca em
    direção a zero, em vez de arredondar para -3. Para a média, usa a expressão
    de <code>b</code>, verificando antes que <code>n</code> não é zero.
  </div>
</Exercise>

<Exercise
  id="ciclo-fronteira"
  revision={1}
  title="Justificar o limite de um ciclo"
  explanation="/cadeiras/p/cpp-fundamentos/#escolha-iteração-e-âmbito"
  answer={{
    kind: 'self',
    checklist: [
      'Enumerei 0, 1, 2 e 3.',
      'Obtive total 6 e distingui o total 10 da alternativa.',
      'Expliquei o risco de usar <= com índices de um array.',
    ],
  }}
>
  <div>
    <p>
      O programa abaixo começa com <code>total = 0</code> e executa{' '}
      <code>total += i</code> enquanto <code>i &lt; 4</code>.
    </p>
    <pre>
      <code>for (int i = 0; i &lt; 4; ++i) total += i;</code>
    </pre>
    <p>
      Indica os valores visitados, o total final e o que mudaria com{' '}
      <code>i &lt;= 4</code>. Num array de quatro elementos, os índices válidos
      são 0 a 3.
    </p>
  </div>
  <div slot="hint">
    <p>Escreve cada valor de i que satisfaz a condição, por ordem.</p>
  </div>
  <div slot="solution">
    <div>
      Com <code>i &lt; 4</code>, o corpo usa <code>0, 1, 2, 3</code>, dando{' '}
      <code>0 + 1 + 2 + 3 = 6</code>. Com <code>i &lt;= 4</code>, inclui também{' '}
      <code>4</code>, dando <code>10</code>. Num array de quatro elementos, o
      segundo limite permitiria o índice inválido <code>4</code>.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Não contes o valor que termina o ciclo como se tivesse passado pelo corpo.
    </div>
  </div>
</Exercise>

<Exercise
  id="curto-circuito-protege"
  revision={2}
  title="Ordem da proteção de uma divisão"
  explanation="/cadeiras/p/cpp-fundamentos/#operadores-e-divisão"
  answer={{ kind: 'self', checklist: [
    'Identifiquei a primeira condição como a única segura para n igual a zero.',
    'Localizei a divisão indevida nas outras duas expressões.',
    'Obtive verdadeiro para a primeira com soma 60 e n 5.',
  ] }}
>
  <code>soma</code> e <code>n</code> são inteiros não negativos.
  Compara as condições abaixo para <code>n = 0</code>. Qual evita a divisão
  por zero? Justifica a ordem de avaliação e prevê o resultado dessa condição
  para <code>soma = 60</code> e <code>n = 5</code>.

```cpp
n != 0 && soma / n > 10
soma / n > 10 && n != 0
n == 0 && soma / n > 10
```

  <div slot="hint">Em <code>&amp;&amp;</code>, uma condição esquerda falsa impede avaliar a direita.</div>
  <div slot="solution">
    A primeira condição é segura para zero: <code>n != 0</code> é falso e a
    divisão não é avaliada. Na segunda, a divisão vem antes da proteção. Na
    terceira, <code>n == 0</code> é verdadeiro e obriga a avaliar a divisão.
    Estas duas versões têm comportamento indefinido para zero, não uma resposta
    booleana que possas prever. Com 60 e 5, a primeira avalia
    <code>12 &gt; 10</code> e dá verdadeiro.
  </div>
</Exercise>
