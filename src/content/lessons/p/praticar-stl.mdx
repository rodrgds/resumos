  <code>auto fim = std::unique(v.begin(), v.end());</code>. Indica o tamanho de{' '}

<Exercise
  id="substituir-intervalo-generico"
  title="Um percurso para vector e list"
  explanation="/cadeiras/p/templates-stl/#iteradores"
  answer={{
    kind: 'self',
    checklist: [
      'Percorri [inicio, fim) com !=, * e ++, sem ler fim.',
      'Obtive 2 substituições e a sequência 2, 9, 9, 4 no caso dado.',
      'Tratei o intervalo vazio e não usei aritmética indisponível numa list.',
    ],
  }}
>
  Escreve uma função template que substitua por <code>novo</code> cada valor
  igual a <code>antigo</code> no intervalo válido <code>[inicio, fim)</code> e
  devolva o número de substituições. Deve servir tanto os iteradores de um
  <code>vector&lt;int&gt;</code> como os de uma <code>list&lt;int&gt;</code>.
  Os elementos admitem comparação e atribuição; <code>antigo</code> e
  <code>novo</code> são recebidos por valor para não dependerem de elementos
  que a função possa alterar.

```cpp
template <typename It, typename T>
std::size_t substituir(It inicio, It fim, T antigo, T novo);
```

Testa a sequência <code>2, 3, 3, 4</code>, substituindo 3 por 9, e um
intervalo vazio. Justifica por que <code>it + 1</code> limitaria o conjunto
de iteradores aceites. O enunciado adapta o problema de iteradores P11 do
suplemento FEUP_PROG.

  <div slot="hint">O algoritmo só precisa de comparar posições, ler o elemento e avançar.</div>
  <div slot="solution">

```cpp
// Inclui <cstddef> para std::size_t.
template <typename It, typename T>
std::size_t substituir(It inicio, It fim, T antigo, T novo) {
    std::size_t total = 0;
    for (auto it = inicio; it != fim; ++it) {
        if (*it == antigo) {
            *it = novo;
            ++total;
        }
    }
    return total;
}
```

    Com <code>2, 3, 3, 4</code>, as duas posições com 3 passam a 9, dando
    <code>2, 9, 9, 4</code> e resultado 2. No vazio, a condição é logo falsa e
    o resultado é zero. Uma <code>list</code> permite <code>++it</code>, mas
    não <code>it + 1</code>. Não há inserção nem remoção, por isso este percurso
    não invalida os iteradores de nenhuma das duas coleções.

  </div>
</Exercise>

<Exercise
  id="remover-negativos"
  revision={1}
  title="Remover sem saltar o elemento seguinte"
  explanation="/cadeiras/p/templates-stl/#invalidação-de-iteradores"
  answer={{
    kind: 'self',
    checklist: [
      'Removi todos os negativos, incluindo negativos consecutivos.',
      'Conservei zero, positivos, repetições e a ordem relativa.',
      'Usei o iterador devolvido por erase sem o avançar novamente.',
    ],
  }}
>
  <div>
    Define <code>void remover_negativos(std::vector&lt;int&gt;&amp; valores)</code>.
    Altera o vetor recebido, conservando os restantes valores pela mesma ordem.
    Nesta versão, usa um iterador e <code>erase</code> para seguir a
    invalidação. Esta resposta é de autoavaliação.
  </div>
  <div slot="work">
    <CodePlayground
      autoRun={false}
      language="cpp"
      title="Escrever a remoção por iterador"
      code={
        '#include <iostream>\n#include <vector>\n\nvoid remover_negativos(std::vector<int>& valores) {\n    // Escreve o percurso e a remoção.\n}\n\nvoid mostrar(std::vector<int> valores) {\n    remover_negativos(valores);\n    std::cout << "[";\n    for (int x : valores) std::cout << " " << x;\n    std::cout << " ]\\n";\n}\n\nint main() {\n    mostrar({}); // [ ]\n    mostrar({-1, -2}); // [ ]\n    mostrar({1, -1, -2, 0, 3, 3, -4}); // [ 1 0 3 3 ]\n}\n'
      }
    />
  </div>
  <div slot="hint">O elemento seguinte ocupa a posição que acabaste de remover.</div>
  <div slot="hint-more">
    Se removes, usa <code>it = valores.erase(it)</code>. Se conservas, usa
    <code>++it</code>. Os dois casos não devem fazer o mesmo avanço.
  </div>
  <div slot="solution">

```cpp
void remover_negativos(std::vector<int>& valores) {
    auto it = valores.begin();
    while (it != valores.end()) {
        if (*it < 0) it = valores.erase(it);
        else ++it;
    }
}
```

    Em <code>&#123;-1, -2&#125;</code>, remover -1 devolve um iterador para -2.
    Esse valor ainda precisa de ser analisado. Ao remover o último elemento,
    <code>erase</code> devolve <code>end()</code> e o ciclo termina sem o ler.
    Cada remoção pode deslocar o resto do vetor; no pior caso, esta versão tem
    custo quadrático no número de elementos. A combinação
    <code>remove_if</code> e <code>erase</code> da lição permite uma passagem
    linear.

  </div>
  <div slot="mistakes">
    Não uses um <code>for</code> com avanço incondicional depois de
    <code>erase</code>. Não conserves o antigo <code>end()</code> nem uses um
    iterador invalidado. Passar o vetor por valor alteraria apenas uma cópia.
  </div>
</Exercise>
