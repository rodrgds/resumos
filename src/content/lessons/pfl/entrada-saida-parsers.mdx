Uma função pura não pode ler do teclado: o mesmo argumento deve determinar o mesmo resultado, mas a linha lida depende de uma interação. Haskell separa o cálculo puro do contacto com o mundo no tipo **`IO`**. Um valor `IO ()` é uma **ação**, uma receita que, quando executada, interage e devolve `()`. O `main` do programa é uma ação composta.

## I/O com do

```haskell
main :: IO ()
main = do
  putStrLn "Como te chamas?"
  nome <- getLine
  putStrLn ("Ola, " ++ nome ++ "!")
```

Neste exemplo, cada linha do `do` executa uma ação por ordem. Um bloco `do` também pode conter definições puras com `let`. A seta `<-` corre a ação e dá nome ao resultado: `nome` fica com a string lida. Sem seta, como em `putStrLn`, o resultado é ignorado. `"Ola, " ++ nome ++ "!"` calcula uma string pura, e `putStrLn` cria a ação que a imprime. A seta liga o resultado de uma ação; não marca todos os efeitos do bloco. Separa os cálculos em funções puras e usa o bloco `do` para ligar as ações aos seus resultados.

## Parsers como funções

Um **parser** para valores do tipo `a` é uma função que come carateres da entrada e devolve o valor com o resto:

```haskell
newtype Parser a = P (String -> [(a, String)])

parse :: Parser a -> String -> [(a, String)]
parse (P p) = p

item :: Parser Char
item = P (\inp -> case inp of
                   []     -> []
                   (c:cs) -> [(c, cs)])
```

Resultado vazio significa falha. Sobre esta base definem-se os **combinadores**, parsers feitos de parsers: sequência com o `do` (definimos uma instância de `Monad` para `Parser`), alternativa com `+++` (tenta o segundo se o primeiro falhar) e repetição com `many`:

```haskell
import Data.Char (isDigit, isSpace)

instance Functor Parser where
  fmap f p = P (\inp -> case parse p inp of
                         []        -> []
                         [(v,out)] -> [(f v, out)])

instance Applicative Parser where
  pure v = P (\inp -> [(v, inp)])
  pf <*> px = P (\inp -> case parse pf inp of
                            []        -> []
                            [(f,out)] -> parse (fmap f px) out)

instance Monad Parser where
  p >>= f = P (\inp -> case parse p inp of
                         []        -> []
                         [(v,out)] -> parse (f v) out)

(+++) :: Parser a -> Parser a -> Parser a
p +++ q = P (\inp -> case parse p inp of
                       []        -> parse q inp
                       [(v,out)] -> [(v,out)])

sat :: (Char -> Bool) -> Parser Char
sat pr = do c <- item
            if pr c then return c else P (const [])

digit :: Parser Char
digit = sat isDigit

many :: Parser a -> Parser [a]
many p = many1 p +++ return []

many1 :: Parser a -> Parser [a]
many1 p = do v  <- p
             vs <- many p
             return (v:vs)

nat :: Parser Int
nat = do xs <- many1 digit
         return (read xs)

space :: Parser ()
space = do many (sat isSpace)
           return ()

token :: Parser a -> Parser a
token p = do space
             v <- p
             space
             return v

symbol :: Char -> Parser Char
symbol c = token (sat (== c))
```

`Functor` aplica uma função ao resultado com `fmap`. `Applicative` fornece `pure`, sucesso sem consumir entrada, e `<*>`, sequência de um parser de funções com um parser de argumentos. `Monad` fornece `>>=`, que escolhe o parser seguinte a partir do valor acabado de ler. Aqui `return` tem o mesmo papel que `pure`, e o `do` usa `>>=`. Cada combinador faz uma coisa pequena: `sat` testa um caráter, `many` repete zero ou mais vezes, `token` ignora espaços à volta.

`parse nat "42x"` dá `[(42,"x")]`: lê o número e deixa o resto. A gramática seguinte compõe estes combinadores para ler expressões:

```haskell
expr :: Parser Int
expr = do t <- term
          (do symbol '+'
              e <- expr
              return (t + e)) +++ return t

term :: Parser Int
term = do f <- factor
          (do symbol '*'
              t <- term
              return (f * t)) +++ return f

factor :: Parser Int
factor = (do symbol '('
             e <- expr
             symbol ')'
             return e) +++ token nat
```

A precedência vive na estrutura: `expr` soma `term`s e `term` multiplica `factor`s, por isso `*` liga mais que `+`. As duas árvores mostram a diferença: sem parênteses o `*` fica por baixo do `+`; com parênteses a soma desce primeiro.

## Alternativa, falha e entrada restante

O `+++` definido nesta página tenta `q` na entrada original quando `p` devolve `[]`. Por isso há retrocesso mesmo que `p` tenha consumido caracteres antes de falhar. Este contrato difere de parsers que guardam explicitamente se a falha aconteceu depois de consumir entrada.

No parser determinístico, o resultado tem zero ou uma solução. Se quiseres um parser não determinístico com várias soluções, os casos `[(v,out)]` deixam de chegar: tens de combinar cada resultado possível. Não mistures os dois contratos.

`parse expr "2+3x"` dá `[(5,"x")]`. A alternativa também permite que `parse expr "2+"` recue para o prefixo `2` e deixe `"+"`. Uma aplicação que exige uma expressão inteira deve aceitar apenas `[(v,"")]`, depois de consumir espaços:

```haskell
completa :: Parser a -> String -> Maybe a
completa p texto = case parse (token p) texto of
  [(valor, "")] -> Just valor
  _ -> Nothing
```

`completa expr " 2 + 3*4 "` dá `Just 14`; `"2+"`, `"2+3x"` e `"(2+3"` dão `Nothing`. Sucesso do prefixo não valida todo o ficheiro.

`many p` exige que `p` consuma entrada em cada sucesso. Se `p` for `pure 1`, o parser pode repetir para sempre sem avançar. É a condição de progresso correspondente ao caso recursivo de uma lista.

## Precedência e associatividade

A gramática `expr = term '+' expr | term` dá prioridade à multiplicação, mas associa a soma à direita. Como a adição de inteiros é associativa, os resultados não revelam essa escolha. Se trocares `+` por `-`, `8-3-1` passa a `8-(3-1)=6`. A associatividade usual à esquerda daria `(8-3)-1=4`. Uma solução é ler um primeiro termo, ler pares operador-termo e acumular pela esquerda.

Recursão à esquerda, como `expr = expr '+' term | term`, não serve diretamente num parser recursivo descendente: chama `expr` de novo sem consumir nada. Reformula a gramática com um acumulador ou um combinador de cadeias.

## Sequenciar ações sem confundir valores

`getLine :: IO String`, enquanto `length :: [a] -> Int`. Não podes escrever `length getLine`: uma ação não é a string que vai produzir. Em `do`, `linha <- getLine` liga o valor produzido; `let n = length linha` dá nome a um cálculo puro e não usa `<-`. `return n` cria uma ação que devolve `n`; não interrompe as ações seguintes como um `return` imperativo.

Um modelo da sequência é `acao >>= continuacao`, com `continuacao :: a -> IO b` se `acao :: IO a`. O resultado de `IO` fica dentro do programa de efeitos; uma função pura pode receber o valor lido, mas não extrair sozinha um valor de uma ação arbitrária.
