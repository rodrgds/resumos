Toda a função em Haskell recebe na verdade um só argumento. Uma função "de dois argumentos" é uma função que recebe o primeiro e devolve outra função à espera do segundo. Esta convenção chama-se **currying** e transforma a aplicação parcial, passar só alguns argumentos, na ferramenta mais usada da linguagem.

## Aplicação parcial

```haskell
soma :: Int -> Int -> Int
soma x y = x + y

soma5 :: Int -> Int
soma5 = soma 5
```

`soma 5` é uma função à espera do segundo argumento, por isso `soma5 3` dá `8`. O mesmo vale para operadores por meio de **secções**: `(>= 9.5)` é a função que testa se o seu argumento é maior ou igual a `9.5`, e `(* 2)` é a função que dobra. Quando precisares de uma função pequena só uma vez, escreve-a anónima com **lambda**: `(\x -> x * 2)` lê-se "a função que a `x` associa `x * 2`".

Isto generaliza o que viste em [FP](/cadeiras/fp/programacao-funcional/): o `lambda` do Python e o `\` do Haskell são o mesmo gesto, mas em Haskell a aplicação parcial dispensa a maioria dos lambdas.

## map, filter e foldr

O prelúdio traz as três de ordem superior que já conheces, com tipos honestos:

```haskell
map    :: (a -> b) -> [a] -> [b]
filter :: (a -> Bool) -> [a] -> [a]
foldr  :: (a -> b -> b) -> b -> [a] -> b
```

`map` transforma, `filter` seleciona, `foldr` combina tudo num valor partindo da direita com um acumulador inicial. `sum` é `foldr (+) 0` e `length` é `foldr (\_ n -> n + 1) 0`. Quando o problema for "transformar cada um", "ficar só com alguns" ou "resumir tudo", começa por estas antes de escreveres recursão à mão.

## Exemplo completo: média das aprovações

Dada uma pauta, queremos calcular a média das notas de aprovação. As notas podem ter parte decimal, por isso usamos `[Double]`. O resultado é `Maybe Double`, porque uma pauta sem aprovações não tem essa média.

```haskell
mediaAprovados :: [Double] -> Maybe Double
mediaAprovados notas = case filter (>= 9.5) notas of
  [] -> Nothing
  xs -> Just (sum xs / fromIntegral (length xs))
```

Em `[8,12,6,15,10]`, `filter` conserva `[12,15,10]`. A soma é `37` e o comprimento é `3`, dando `Just 12.333333333333334`. A soma já é `Double`; só precisamos de converter o comprimento, que é `Int`. Com `[2,7]`, o filtro produz `[]` e o resultado é `Nothing`.

Podes usar `where` para dar nome a etapas intermédias. Nesta versão usamos `case` para tratar as duas formas do resultado do filtro.

## foldr contra foldl

O `foldr` combina da direita e o `foldl` da esquerda, e a diferença aparece quando a operação não é associativa. Compara a subtração:

```haskell
somaD :: [Int] -> Int
somaD = foldr (+) 0

somaE :: [Int] -> Int
somaE = foldl (+) 0
```

`foldr (-) 0 [1,2,3]` calcula `1 - (2 - (3 - 0))`, que dá `2`. Já `foldl (-) 0 [1,2,3]` calcula `((0 - 1) - 2) - 3`, que dá `-6`. Com inteiros sem overflow e `(+)`, os dois concordam, e é por isso que o exemplo da média não distingue; com `(-)` ou com `(:)`, a direção decide o resultado. A versão com acumulador explícito é o `foldl` escrito à mão:

## Listas infinitas e preguiça

Haskell só calcula o que é preciso para responder, por isso uma lista infinita é um valor legítimo enquanto só consumires um prefixo finito:

```text
ghci> take 5 (iterate (+1) 0)
[0,1,2,3,4]
ghci> take 3 (repeat "ola")
["ola","ola","ola"]
```

`iterate` aplica a função ao resultado anterior para sempre; o `take` puxa só os cinco primeiros e o resto nunca chega a existir. O caso limite mostra a regra: `length` numa lista infinita nunca termina, porque precisa de ver o fim que não existe. Quando uma função de consumo parcial, como `take`, encontra um produtor infinito, como `iterate`, a preguiça é o que torna a combinação possível.

## Escolher a função de ordem superior

`takeWhile p` conserva apenas o prefixo que satisfaz `p`; `filter p` examina a lista inteira. Em `[2,4,1,6]`, `takeWhile even` dá `[2,4]`, enquanto `filter even` dá `[2,4,6]`. `dropWhile even` dá `[1,6]`. O `6` já não é testado para terminar o prefixo: a fronteira foi o primeiro `1`.

`all p xs` é verdadeiro se todos os elementos satisfazem `p`; `any p xs` basta-se com um. Na lista vazia, `all` dá `True` e `any` dá `False`. Estas identidades permitem escrever `and = foldr (&&) True` e `or = foldr (||) False`.

Uma composição lê-se da direita para a esquerda. `sum . map (^2) . filter even` seleciona pares, calcula quadrados e soma. Para `[1,2,3,4]`, as etapas são `[2,4]`, `[4,16]`, `20`. Se precisas de ver a entrada de cada etapa, escreve primeiro a versão com argumento e nomes locais; só depois retira o argumento.

## Derivar um fold

Para substituir a recursão de `append xs ys`, queremos trocar cada `(:)` de `xs` por `(:)` e o `[]` final por `ys`. Logo `append xs ys = foldr (:) ys xs`. Para `concat`, cada elemento já é uma lista: `concat = foldr (++) []`.

Inverter com `foldl (flip (:)) []` coloca cada novo elemento na cabeça do acumulador. Os estados para `[1,2,3]` são `[]`, `[1]`, `[2,1]`, `[3,2,1]`. Inverter com `foldr (\x acc -> acc ++ [x]) []` também funciona numa lista finita, mas as concatenações repetidas tornam o tempo quadrático. A primeira versão percorre a lista em tempo linear.

## O que a preguiça permite

Haskell só exige um resultado intermédio quando precisa dele. `take 3 [1..]` pede três células e termina; `sum [1..]` exige o fim de uma lista que não o tem. `False && undefined` é `False`, mas `True && undefined` falha ao pedir o segundo argumento. A ordem dos argumentos importa para este curto-circuito.

`foldr (&&) True (False:repeat True)` termina com `False`, porque `&&` pode ignorar a cauda. `foldl (&&) True` nessa lista precisa de chegar ao fim e não termina. `foldr` não é uma promessa geral de terminação em listas infinitas: `foldr (+) 0 [1..]` também exige a cauda inteira.

`foldl` pode acumular uma cadeia de expressões por avaliar. `foldl'` de `Data.List` força o acumulador a cada passo até à forma normal fraca. É útil para somas grandes, mas não força necessariamente o interior de uma árvore ou de um tuplo. Distingue associatividade da operação, ordem de avaliação e custo em memória.
