Uma lista tem duas formas: `[]` ou `x:xs`, ou seja esta definição dá-nos os casos que uma função precisa de tratar. Para somar, a lista vazia contribui com zero; para uma lista não vazia, somamos a cabeça ao resultado da cauda. Para construir outra lista, usamos `:` para colocar um elemento antes do resultado recursivo.

## Construir e percorrer

`3:[5,7]` constrói `[3,5,7]`. O lado direito de `:` tem de ser uma lista, por isso `3:5` não tem um tipo válido. `++` junta duas listas: `[3] ++ [5,7]` também dá `[3,5,7]`, mas percorre o operando esquerdo. Construir com `:` custa tempo constante; juntar `xs ++ ys` custa tempo proporcional ao comprimento de `xs`.

| Operação                  | Condição ou resultado                                   |
| ------------------------- | ------------------------------------------------------- |
| `head xs`, `tail xs`      | Exigem lista não vazia.                                 |
| `take n xs`, `drop n xs`  | Aceitam lista vazia; para `n <= 0`, dão `[]` e `xs`.    |
| `xs !! i`                 | Exige `0 <= i < length xs`; os índices começam em zero. |
| `zip xs ys`               | Para quando termina a lista mais curta.                 |
| `length xs`, `reverse xs` | Precisam de percorrer uma lista finita.                 |

Se queres saber se há menos de três elementos, não precisas de contar a lista toda:

```haskell
curta :: [a] -> Bool
curta (_:_:_:_) = False
curta _ = True
```

O primeiro padrão precisa de três elementos. A variável `_` na cauda pode corresponder a qualquer lista, incluindo uma infinita. Esta função termina depois de observar no máximo três células; `length xs < 3` não termina para uma lista infinita.

## Geradores e condições

Uma compreensão `[expressao | gerador, condicao]` produz valores na ordem dos geradores. Com `[(x,y) | x <- [1,2], y <- [4,5]]`, fixamos primeiro `x=1` e percorremos os dois `y`; depois fazemos o mesmo para `x=2`. O resultado é `[(1,4),(1,5),(2,4),(2,5)]`. Trocar os geradores muda a ordem.

Um problema de divisores pede candidatos inteiros e um teste de divisibilidade:

```haskell
divisoresProprios :: Integer -> [Integer]
divisoresProprios n = [d | d <- [1..n-1], n `mod` d == 0]

perfeito :: Integer -> Bool
perfeito n = n > 0 && sum (divisoresProprios n) == n
```

Para `n=12`, os candidatos aceites são `[1,2,3,4,6]`, cuja soma é `16`; por isso `perfeito 12` é `False`, porque a condição `n > 0` evita chamar perfeito a zero, já que a soma da lista vazia também é zero.

Para testar primalidade não precisamos de chegar a `n-1`. Se `n=d*k` e os dois fatores fossem maiores que a raiz quadrada de `n`, o produto seria maior que `n`. Um composto tem portanto um divisor até essa raiz. Podemos evitar erros de arredondamento usando `d*d <= n` com `Integer`:

```haskell
primo :: Integer -> Bool
primo n = n > 1 && testar 2
  where
    testar d
      | d*d > n = True
      | n `mod` d == 0 = False
      | otherwise = testar (d+1)
```

`primo 49` chega a `d=7`, testa o divisor e dá `False`, porque o teste de paragem tem de usar `>`: com `>=`, saltaríamos precisamente o divisor de um quadrado perfeito. O custo deste método é de ordem raiz quadrada de `n`, contando candidatos, não o custo de multiplicar inteiros grandes.

## Relacionar posições com zip

`zip` junta posições correspondentes. Uma compreensão pode depois selecionar os pares que interessam:

```haskell
indices :: Eq a => a -> [a] -> [Int]
indices valor xs = [i | (x,i) <- zip xs [0..], x == valor]
```

Para `indices 'a' "casa"`, `zip` forma `[('c',0),('a',1),('s',2),('a',3)]` e o teste conserva `[1,3]`, porque a enumeração `[0..]` não precisa de um limite explícito: `zip` para quando acaba a lista finita `xs`. O padrão `(x,i)` separa cada par.

Num gerador dependente, os nomes têm de ser definidos antes de usados. `[(x,y) | x <- [1..3], y <- [x..3]]` dá `[(1,1),(1,2),(1,3),(2,2),(2,3),(3,3)]`. Se trocarmos os geradores, `x` ainda não existe ao avaliar `[x..3]`.

## Recursão que termina

Identifica o caso base e uma medida que diminui. Em funções sobre listas finitas, a medida costuma ser o comprimento da lista restante. Em `replicar n x`, pode ser `max 0 n`:

```haskell
replicar :: Int -> a -> [a]
replicar n x
  | n <= 0 = []
  | otherwise = x : replicar (n-1) x
```

Usar apenas o caso `n == 0` faria a função divergir para `n` negativo, porque o tipo `Int -> a -> [a]` permite argumentos negativos; se queres excluí-los, precisas de o declarar como pré-condição ou de os tratar.

Para eliminar repetidos conservando a primeira ocorrência, guardamos a cabeça e retiramos todas as cópias dela na cauda. Para `"abacaba"`, conservamos `a`, resta `"bcb"`, conservamos `b` e resta `"c"`. O resultado é `"abc"`. É diferente de agrupar iguais consecutivos: `"AABBBAA"` dá `["AA","BBB","AA"]`, sem fundir os dois grupos de `A`.

## Ordenação por inserção

A função `inserir x ys` pressupõe que `ys` já está ordenada. Se `x <= head ys`, põe `x` antes da cabeça; caso contrário, conserva a cabeça e continua na cauda. Para inserir `3` em `[1,2,4]`, conservamos `1`, conservamos `2` e paramos antes de `4`: `[1,2,3,4]`.

Ordenar uma lista não vazia é ordenar a cauda e inserir a cabeça nesse resultado. A correção tem dois passos: o caso vazio está ordenado; se a cauda recursiva está ordenada e tem os mesmos elementos, inserir a cabeça mantém a ordenação e restitui todos os elementos. Num caso desfavorável, cada inserção percorre quase toda a lista anterior, por isso o total cresce como `1+2+...+(n-1)`, ou seja ordem `n²`.

## Dividir e juntar

Merge sort divide a lista em duas metades, ordena cada metade e junta-as comparando as duas cabeças. Só retiramos a cabeça escolhida: a outra tem de voltar à chamada recursiva. Esquecer essa cabeça perde dados.

## Acumular uma representação binária

Ler um bit depois do prefixo equivale a multiplicar o valor anterior por dois e somar o bit. Para `[1,0,1,1]`, os acumuladores são `0`, `1`, `2`, `5`, `11`. Isto dá `foldl (\n b -> 2*n+b) 0`.

A função pressupõe que cada elemento é `0` ou `1`. O tipo `[Integer]` não impõe essa regra; verifica `all (\b -> b==0 || b==1) bits` se a entrada não for controlada. Para converter no sentido inverso, divide por dois, recolhe os restos e inverte a lista. Define ainda que representação queres para zero, normalmente `[0]`, e exclui números negativos ou especifica outra codificação.

## Intercalar sem acrescentar nas pontas

Queremos pôr um separador **entre** elementos. Para `intercalar '-' "rt"`, o resultado é `"r-t"`. A lista vazia continua vazia; um elemento fica sozinho. Estes dois casos impedem um separador no fim:

```haskell
intercalar :: a -> [a] -> [a]
intercalar _ [] = []
intercalar _ [x] = [x]
intercalar s (x:xs) = x:s:intercalar s xs
```

A última equação só é usada quando há pelo menos dois elementos, porque os casos anteriores já trataram zero e um. Conservamos a cabeça e pomos o separador antes do resto.

## Inserir em todas as posições e permutar

Inserir `x` em todas as posições de `"ab"` dá `["xab","axb","abx"]`. Há uma possibilidade antes da cabeça; nas restantes, conservamos a cabeça e inserimos mais adiante:

```haskell
posicoes :: a -> [a] -> [[a]]
posicoes x [] = [[x]]
posicoes x (y:ys) = (x:y:ys) : map (y:) (posicoes x ys)

permutar :: [a] -> [[a]]
permutar [] = [[]]
permutar (x:xs) = concatMap (posicoes x) (permutar xs)
```

`posicoes x []` dá uma lista com uma possibilidade, `[[x]]`. Já `permutar []` dá `[[]]`, porque existe uma ordenação da lista vazia. Se devolvesse `[]`, não haveria uma possibilidade onde inserir o elemento na chamada anterior.

Para permutar `"ab"`, começamos pela cauda `"b"`, cuja única permutação é `"b"`. Inserir `a` nas duas posições produz `"ab"` e `"ba"`, ou seja para `"abc"` a cauda tem duas permutações e cada uma dá três posições para `a`, portanto seis resultados.

O tipo não exige `Eq`: trata ocorrências, mesmo quando os valores são iguais. `permutar "aa"` produz `"aa"` duas vezes. Com `n` elementos há `n!` resultados nesta enumeração; visitar ou imprimir os `n` elementos de cada resultado já exige ordem `n*n!` operações. Não uses este método como procura eficiente para entradas grandes. A construção termina para listas finitas, mas o número de possibilidades cresce depressa.

## Converter inteiro para bits

O primeiro resto de dividir por dois é o bit menos significativo. Para `10`, as divisões sucessivas são `10/2`, `5/2` e `2/2`, seguidas de `1/2`. Os restos surgem como `[0,1,0,1]`; inverter dá `[1,0,1,0]`.

A folha 3 pede `toBits :: Int -> [Int]`. Para esse tipo, esta definição assume binário sem sinal, com `n >= 0`. Escolhemos `[0]` para zero; a folha não fixa essa convenção:

```haskell
toBits :: Int -> [Int]
toBits n
  | n < 0 = error "Esperado um inteiro nao negativo"
  | n == 0 = [0]
  | otherwise = reverse (restos n)
  where
    restos 0 = []
    restos k = k `mod` 2 : restos (k `div` 2)
```

O guarda negativo assinala uma violação da pré-condição; não fornece uma representação de números negativos. O programa completo chama esta versão `toBitsFicha` para a distinguir da seguinte. Numa resposta à ficha, conserva o tipo pedido.

:::details[Contrato alternativo com `Maybe`]

Podemos definir um contrato alternativo que devolve a falha como valor. Aqui mudamos também para `Integer`, evitando o limite de tamanho de `Int`:

```haskell
toBits :: Integer -> Maybe [Integer]
toBits n
  | n < 0 = Nothing
  | n == 0 = Just [0]
  | otherwise = Just (reverse (restos n))
  where
    restos 0 = []
    restos k = k `mod` 2 : restos (k `div` 2)
```

O contrato deste exemplo é binário sem sinal: um argumento negativo dá `Nothing`, e zero tem representação `[0]`. Para um positivo, o quociente é estritamente menor, por isso acaba em zero. Não uses a mesma recursão para um negativo: em Haskell, `(-1) div 2` continua a dar `-1`.

:::
