<Exercise
  id="associatividade"
  revision={1}
  title="Uma gramática que associa à direita"
  explanation="/cadeiras/pfl/entrada-saida-parsers/#precedência-e-associatividade"
  answer={{ kind: 'number', value: 7, tolerance: 0 }}
>
  <div>
    Uma gramática de subtração usa <code>{'expr = term - expr | term'}</code>.
    Quanto dá 9-4-2?
  </div>
  <div slot="hint">
    <p>A chamada recursiva está do lado direito.</p>
  </div>
  <div slot="hint-more">
    <p>Calcula 9-(4-2).</p>
  </div>
  <div slot="solution">
    <p>4-2=2 e 9-2=7. A associatividade usual à esquerda daria 3.</p>
  </div>
  <div slot="mistakes">
    <div>
      A prioridade entre operadores e a associatividade do mesmo operador são
      decisões diferentes.
    </div>
  </div>
</Exercise>

<Exercise
  id="progresso"
  revision={1}
  title="Repetir um parser vazio"
  explanation="/cadeiras/pfl/entrada-saida-parsers/#alternativa-falha-e-entrada-restante"
  answer={{
    kind: 'self',
    checklist: [
      'Identifico que pure tem sucesso sem consumir.',
      'Mostro que a entrada da recursão fica igual.',
      'Distingo sucesso de progresso.',
    ],
  }}
>
  <p>Por que many (pure 1) pode divergir nesta definição recursiva?</p>
  <div slot="hint">
    <p>O parser pure devolve um valor e a entrada intacta.</p>
  </div>
  <div slot="hint-more">
    <p>many1 volta a chamar many na mesma entrada.</p>
  </div>
  <div slot="solution">
    <div>
      Cada sucesso de pure 1 mantém a entrada; a repetição não se aproxima de
      uma falha nem do fim. O combinador precisa de um parser que avance em cada
      sucesso.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Não assumas que uma recursão sobre texto avança só porque produziu um
      valor.
    </div>
  </div>
</Exercise>

<Exercise
  id="io-return"
  revision={1}
  title="Criar uma ação sem terminar a sequência"
  explanation="/cadeiras/pfl/entrada-saida-parsers/#sequenciar-ações-sem-confundir-valores"
  answer={{ kind: 'choice', options: [
    { text: 'Imprime 3 e depois fim.', correct: true, explanation: "`return` cria a ação que produz 3; o bloco continua." },
    { text: 'Não imprime nada.', correct: false, explanation: "`return` não sai do bloco do." },
    { text: 'Imprime só 3.', correct: false, explanation: 'A ação putStrLn seguinte também é executada.' },
  ] }}
>
  <div>
    Que efeito tem este programa?
  </div>

```haskell
main :: IO ()
main = do
  n <- return (3 :: Int)
  print n
  putStrLn "fim"
```

  <div slot="hint">
    Compara `return` com a criação de uma ação que devolve um valor.
  </div>
  <div slot="hint-more">
    A ligação dá `n=3`. Ainda restam duas ações.
  </div>
  <div slot="solution">
    Imprime `3` e `fim`, em linhas separadas. `return (3 :: Int)` tem tipo `IO Int`. A seta liga o resultado e a execução segue para `print` e `putStrLn`.
  </div>
  <div slot="mistakes">
    Não importes o significado de <code>{"return"}</code> em C ou Python para Haskell.
  </div>
</Exercise>
