        correct: false,
        explanation: 'A restrição numérica não é usada pelo corpo.',
      },
    ],
  }}
>
  <p>
    Qual é o tipo mais geral de <code>{'duas f x = f (f x)'}</code>?
  </p>
  <div slot="hint">
    <p>Usa o mesmo tipo de f nas duas chamadas.</p>
  </div>
  <div slot="solution">
    <div>
      Se x é a e f é a -&gt; b, a chamada exterior exige b=a. A função não usa
      operações de classe.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Uma função que funciona com números pode ainda ter um tipo mais geral.
    </div>
  </div>
</Exercise>

<Exercise
  id="tipo-composicao"
  revision={1}
  title="Restrições que vêm de funções diferentes"
  explanation="/cadeiras/pfl/polimorfismo-classes/#operações-acrescentam-restrições"
  answer={{ kind: 'self', checklist: [
    'Obtenho (Eq a, Num a) => [a] -> a.',
    "Relaciono Eq com semRepetidos e Num com `sum`.",
    'Não deduzo Eq a apenas de Num a.',
  ] }}
>
  <div>
    Deduz o tipo mais geral de `somaSem xs = sum (semRepetidos xs)`.
    Assume `semRepetidos :: Eq a => [a] -> [a]`. Que restrições vêm de cada função?
  </div>
  <div slot="hint">
    O filtro conserva o tipo dos elementos.
  </div>
  <div slot="hint-more">
    `semRepetidos` pede igualdade; `sum` pede aritmética.
  </div>
  <div slot="solution">
    O tipo é `(Eq a, Num a) => [a] -> a`. `semRepetidos` usa `Eq a` e conserva `[a]`; `sum` recebe essa lista e usa `Num a`. Ambas as restrições incidem no mesmo tipo de elemento.
  </div>
  <div slot="mistakes">
    A hierarquia atual não permite retirar `Eq a` por haver `Num a`.
  </div>
</Exercise>

<Exercise
  id="mediana-restricao"
  revision={2}
  title="Comparar os tipos das medianas"
  explanation="/cadeiras/pfl/polimorfismo-classes/#deduzir-um-tipo-passo-a-passo"
  answer={{ kind: 'self', checklist: ['Deduzo Ord a para a versão por comparações.', 'Deduzo (Ord a, Num a) para a versão aritmética.', 'Dou uma aplicação permitida só pela primeira versão.'] }}
>
  <div>
Para três valores, considera `medianaOrd`, que ordena usando apenas `(<=)` e seleciona o valor central, e `medianaSoma x y z = x+y+z - minimum [x,y,z] - maximum [x,y,z]`.

Deduz os tipos mais gerais. Qual versão permite obter a mediana de `'c'`, `'a'` e `'b'`? Justifica sem restringir os tipos a números.

  </div>
  <div slot="hint">Relaciona cada operação com a classe que a fornece.</div>
  <div slot="solution">
Na primeira versão, a comparação impõe `Ord a`; selecionar um elemento conserva `a`. O tipo é `Ord a => a -> a -> a -> a`.

Na segunda, os extremos pedem `Ord a` e `+` e `-` pedem `Num a`. As três entradas e a saída partilham `a`: `(Ord a, Num a) => a -> a -> a -> a`.

`Char` tem ordenação, mas não tem a instância numérica pedida. A primeira versão dá `'b'`; a segunda não aceita esta aplicação.

  </div>
  <div slot="mistakes">O facto de uma aplicação usar inteiros não torna Int o tipo mais geral.</div>
</Exercise>
