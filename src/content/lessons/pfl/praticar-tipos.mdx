<Exercise
  id="tipo-duas"
  revision={1}
  title="Tipo de uma aplicação repetida"
  explanation="/cadeiras/pfl/polimorfismo-classes/#deduzir-um-tipo-passo-a-passo"
  answer={{
    kind: 'choice',
    options: [
      {
        text: '(a -> a) -> a -> a',
        correct: true,
        explanation:
          'A saída da chamada interior volta a entrar na mesma função.',
      },
      {
        text: '(a -> b) -> a -> b',
        correct: false,
        explanation: 'Não obriga b a poder entrar em f.',
      },
      {
        text: 'Num a => (a -> a) -> a -> a',
        correct: false,
        explanation: 'A restrição numérica não é usada pelo corpo.',
      },
    ],
  }}
>
  <p>Qual é o tipo mais geral de duas f x = f (f x)?</p>
  <div slot="hint">
    <p>Usa o mesmo tipo de f nas duas chamadas.</p>
  </div>
  <div slot="hint-more">
    <p>O resultado interior tem de ter o tipo do argumento de f.</p>
  </div>
  <div slot="solution">
    <div>
      Se x é a e f é a -&gt; b, a chamada exterior exige b=a. A função não usa
      operações de classe.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Uma função que funciona com números pode ainda ter um tipo mais geral.
    </div>
  </div>
</Exercise>

<Exercise
  id="tipo-media"
  revision={1}
  title="Que restrição pede a divisão?"
  explanation="/cadeiras/pfl/polimorfismo-classes/#operações-acrescentam-restrições"
  answer={{
    kind: 'self',
    checklist: [
      'Obtenho Fractional a => a -> a.',
      'Relaciono entrada e resultado pelo mesmo a.',
      'Distingo literal inteiro de divisão fracionária.',
    ],
  }}
>
  <div>
    Deduz o tipo mais geral de meio x = x/2 e explica por que Int não serve.
  </div>
  <div slot="hint">
    <p>Começa pelo tipo de (/).</p>
  </div>
  <div slot="hint-more">
    <p>(/) :: Fractional a =&gt; a -&gt; a -&gt; a.</p>
  </div>
  <div slot="solution">
    <div>
      meio :: Fractional a =&gt; a -&gt; a. O literal 2 pode entrar nesse a; Int
      não tem a instância Fractional necessária.
    </div>
  </div>
  <div slot="mistakes">
    <div>
      Não acrescentes Num redundante nem escolhas Double só porque é um exemplo
      possível.
    </div>
  </div>
</Exercise>

>
  <p>Quanto vale (-11) mod 4?</p>
  <div slot="hint">
    <p>
      <code>{'div'}</code> arredonda o quociente para baixo.
    </p>
  </div>
  <div slot="hint-more">
    <p>O quociente é -3; procura r tal que -11 = (-3)*4+r.</p>
  </div>
  <div slot="solution">
    <p>O resto é 1. Com quot, o quociente seria -2 e rem seria -3.</p>
  </div>
  <div slot="mistakes">
    <p>Não uses o quociente de quot com o resto de mod.</p>
  </div>
</Exercise>

<Exercise
  id="tipo-composicao"
  revision={1}
  title="Restrições que vêm de funções diferentes"
  explanation="/cadeiras/pfl/polimorfismo-classes/#operações-acrescentam-restrições"
  answer={{ kind: 'self', checklist: [
    'Obtenho (Eq a, Num a) => [a] -> a.',
    "Relaciono Eq com semRepetidos e Num com `sum`.",
    'Não deduzo Eq a apenas de Num a.',
  ] }}
>
  <div>
    Deduz o tipo mais geral de `somaSem xs = sum (semRepetidos xs)`.
    Assume `semRepetidos :: Eq a => [a] -> [a]`. Que restrições vêm de cada função?
  </div>
  <div slot="hint">
    O filtro conserva o tipo dos elementos.
  </div>
  <div slot="hint-more">
    `semRepetidos` pede igualdade; `sum` pede aritmética.
  </div>
  <div slot="solution">
    O tipo é `(Eq a, Num a) => [a] -> a`. `semRepetidos` usa `Eq a` e conserva `[a]`; `sum` recebe essa lista e usa `Num a`. Ambas as restrições incidem no mesmo tipo de elemento.
  </div>
  <div slot="mistakes">
    A hierarquia atual não permite retirar `Eq a` por haver `Num a`.
  </div>
</Exercise>
