Para somar `[1,2,3]`, primeiro resolvemos a soma da cauda e só depois avaliamos a adição. Isto distingue o cálculo aritmético com `is` da unificação de termos com `=`. Mais adiante, os mesmos mecanismos de procura permitem enumerar caminhos num labirinto.

## Listas e aritmética

Listas usam `[Cabeça|Cauda]`, como o `(x:xs)` do Haskell. Somar uma lista é caso base mais passo recursivo:

```prolog
soma([], 0).
soma([H|T], S) :- soma(T, R), S is H + R.
```

Cada chamada usa variáveis frescas. A consulta `soma([1,2,3],S)` espera o resultado `R1` de `soma([2,3],R1)`; esta espera `R2` de `soma([3],R2)`, que espera `R3` de `soma([],R3)`. O caso base liga `R3=0`. No regresso calculamos `R2 is 3+0`, `R1 is 2+3` e `S is 1+5`, obtendo `S=6`. O **`is`** avalia o lado direito como expressão aritmética e unifica com a esquerda, ou seja sem ele, `S = H + R` ligaria `S` à expressão por avaliar, não ao número. Todas as variáveis do lado direito têm de estar ligadas quando ele corre; para comparar resultados numéricos, usa `=:=`.

## Corte e findall

Por omissão, o Prolog explora todas as alternativas ao pedir mais soluções. O **corte**, `!`, poda: descarta escolhas criadas desde a entrada no predicado até ao corte e as cláusulas alternativas desse predicado. Objetivos à direita ainda podem ter várias soluções.

```prolog
max(X, Y, X) :- X >= Y, !.
max(X, Y, Y) :- X < Y.
```

Com o corte, `max(3, 5, M)` usa a primeira cláusula, falha no teste, e o corte nunca chega a correr; a segunda dá `M = 5`. Com `max(7, 5, M)`, o teste passa, o corte elimina a segunda cláusula, e `M = 7` sem deixar alternativa pendente. Este corte é verde nesse contrato, ou seja retirá-lo não acrescenta uma resposta lógica. Um corte que mude respostas é vermelho.

Contrasta com um corte vermelho, que decide antes de testar:

```prolog
mau_max(X, Y, X) :- !.
mau_max(X, Y, Y) :- X < Y.
```

A query `?- mau_max(3, 5, M).` responde `M = 3`, que está errado. Compara os conjuntos de respostas no modo `(+,+,-)`:

| Programa  | Respostas para `(3,5,M)` |
| --------- | ------------------------ |
| Com corte | `M = 3`                  |
| Sem corte | `M = 3` e `M = 5`        |

O corte é vermelho porque altera o conjunto de respostas. Mas a resposta errada `3` já existe sem corte, pela primeira cláusula. Não há teste depois desse corte para discutir posição: a primeira cláusula decide sem comparar. No `max` verde, retirar o corte não acrescenta respostas lógicas nesse contrato. A posição do teste, por si só, não define a cor do corte.

Para juntar **todas** as respostas numa lista em vez de as pedir uma a uma, usa `findall`:

```prolog
?- findall(C, pai(ana, C), Cs).
Cs = [leo].
```

O segundo argumento é o objetivo, o primeiro diz o que colecionar de cada solução. Com os factos da [página anterior](/cadeiras/pfl/logica-unificacao-prolog/), só `leo` é filho da Ana.

## Caminhos e visitados

Modela o labirinto como ligações e procura um caminho acumulando visitados para não andar em círculos:

```prolog
ligado(a, b). ligado(b, c). ligado(b, d). ligado(c, e). ligado(d, e).

caminho(X, X, _, [X]).
caminho(X, Z, Visitados, [X|Resto]) :-
  ligado(X, Y),
  \+ member(Y, Visitados),
  caminho(Y, Z, [Y|Visitados], Resto).
```

A query `?- caminho(a, e, [a], C).` faz **procura em profundidade**: de `a` vai a `b` (única saída); de `b` tenta `c` primeiro (ordem das cláusulas); de `c` chega a `e`, que unifica com o caso base. Responde `C = [a, b, c, e]`; ao pedir mais soluções retrocede até `b`, tenta `d`, e encontra `[a, b, d, e]`.

## Uma relação pode funcionar em vários sentidos

```prolog
juntar([], Ys, Ys).
juntar([X|Xs], Ys, [X|Zs]) :- juntar(Xs, Ys, Zs).
```

`juntar([a,b],[c],Z)` constrói `[a,b,c]`; `juntar(X,Y,[a,b])` procura divisões: `X=[],Y=[a,b]`; `X=[a],Y=[b]`; `X=[a,b],Y=[]`, ou seja a mesma relação serve para construir e decompor. Uma função com `is` pode perder essa reversibilidade, porque o lado direito exige números conhecidos.

Definir membro por `membro(X,[X|_]).` e `membro(X,[_|T]) :- membro(X,T).` produz uma resposta por ocorrência. Com `[a,b,a]`, há duas provas de `membro(a,...)`, mesmo que a substituição seja a mesma. A base de conhecimento não é automaticamente um conjunto de respostas sem repetições.

## Aritmética e identidade

As operações respondem a perguntas diferentes:

| Consulta    | Resultado | Motivo                                     |
| ----------- | --------- | ------------------------------------------ |
| `X = 2+3`   | `X = 2+3` | Unifica com o termo `+(2,3)`.              |
| `X is 2+3`  | `X = 5`   | Avalia a expressão e unifica o resultado.  |
| `5 =:= 2+3` | Sucesso   | Avalia ambos os lados e compara números.   |
| `5 == 5.0`  | Falha     | Inteiro e flutuante são termos diferentes. |

`X = Y` pode criar uma ligação entre variáveis. `X == Y` apenas testa se já são o mesmo termo.

Uma desigualdade por não unificação, `X \= Y`, falha se os termos puderem ser unificados agora. Com as duas variáveis livres, falha, embora depois pudéssemos dar-lhes valores diferentes. `dif(X,Y)` em SWI-Prolog adia a restrição de diferença. Para escrever código portátil para a cadeira, distingue estes contratos e confirma os predicados disponíveis no SICStus.

### Modos de chamada e `is`

Documenta cada predicado com o modo, por exemplo `soma(+ListaDeNumeros, -Total)`. Com saída livre, `soma([1,2,3],S)` calcula `S=6`. Com saída instanciada, `soma([1,2,3],6)` confirma e `soma([1,2,3],5)` falha. `soma([1,X],6)` não resolve uma equação para `X`: chega a `is` com um operando desconhecido e produz um erro de instanciação. Os modos indicam como usar o predicado, mas não são declarações de tipo verificadas pelo motor.

## Acumuladores e terminação

A soma recursiva desta página faz primeiro a soma da cauda e depois a adição. Uma versão com acumulador transporta o total parcial:

```prolog
soma_acc(Xs,S) :- soma_acc(Xs,0,S).
soma_acc([],A,A).
soma_acc([X|Xs],A,S) :- B is A+X, soma_acc(Xs,B,S).
```

Com uma lista finita de números, o comprimento da lista diminui até zero. Com uma lista livre, este programa pode tentar gerar listas e acabar numa expressão aritmética com uma variável desconhecida. Documenta o modo esperado, por exemplo `soma_acc(+ListaDeNumeros,-Total)`.

## Reconhecer um corte vermelho

Se a segunda cláusula de `max` fosse apenas `max(_,Y,Y)`, retirar o corte permitiria também devolver `Y` quando `X` fosse maior. O corte corrigiria a escolha naquele modo, mas alteraria as respostas lógicas: seria vermelho. Há ainda um contraexemplo com resultado já preenchido: `max(7,5,5)` pode saltar a primeira cabeça e ter sucesso na segunda. A versão desta página conserva a guarda `X < Y` e recusa essa resposta errada.

Usa cortes depois de conhecer o conjunto de respostas sem eles. Desenha que escolhas cada corte elimina, verifica objetivos à direita e testa resultados já instanciados. A aparência de determinismo numa só consulta não prova correção nos restantes modos.
