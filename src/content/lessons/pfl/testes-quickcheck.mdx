Um teste de exemplo verifica `reverse [1,2,3] == [3,2,1]`. Uma propriedade afirma algo sobre uma família de entradas: `reverse (reverse xs) == xs` para listas finitas. O QuickCheck gera casos e procura um que viole a afirmação. Os testes observam esses casos; a afirmação universal continua a exigir uma demonstração.

## A primeira propriedade

Propriedades são funções que devolvem `Bool`, com tipos concretos para a ferramenta saber o que gerar:

```haskell
import Test.QuickCheck

prop_revRev :: [Int] -> Bool
prop_revRev xs = reverse (reverse xs) == xs
```

No GHCi, com o pacote QuickCheck instalado:

```text
ghci> quickCheck prop_revRev
+++ OK, passed 100 tests.
```

A ferramenta gerou 100 listas aleatórias[^cem], que podem incluir listas vazias, comprimentos distintos, negativos e repetidos e a igualdade valeu em todas. Um teste de exemplo verifica a entrada escolhida. A propriedade permite testar outras entradas automaticamente, mas só os casos gerados foram observados.

### Contrato da ordenação

Uma função de ordenação deve produzir uma lista ordenada com os mesmos elementos e multiplicidades. Em `[2,1,2]`, devolver `[1,2]` conserva os valores distintos, mas perde uma ocorrência. Devolver `[2,1,2]` conserva tudo, mas não ordena.

A idempotência `f (f xs) == f xs` verifica outra lei. A função `f xs = []` satisfaz essa igualdade para qualquer lista finita, embora perca os dados. Precisamos de propriedades que distingam estes erros, não apenas de mais tentativas da mesma lei.

## Quando falha: o contraexemplo

Uma propriedade falsa dá um contraexemplo reduzido. Afirma que ordenar é a identidade:

```haskell
import Data.List (sort)

prop_sortId :: [Int] -> Bool
prop_sortId xs = sort xs == xs
```

```text
ghci> quickCheck prop_sortId
*** Failed! Falsifiable (after 3 tests):
[1,0]
```

O QuickCheck responde que a propriedade é falsificável e mostra a testemunha: `[1,0]`. O **shrinking** tenta reduzir a entrada encontrada, conservando a falha. O número de testes varia de corrida para corrida; a lista curta fora de ordem é o essencial. Perante uma falha, compara o contraexemplo com o contrato antes de mudar a implementação. Neste caso, a ordenação está certa e a propriedade é que está errada. O ciclo da figura mostra esse regresso à afirmação:

A propriedade idempotente da ordenação passa:

```haskell
prop_sortSort :: [Int] -> Bool
prop_sortSort xs = sort (sort xs) == sort xs
```

```text
ghci> quickCheck prop_sortSort
+++ OK, passed 100 tests.
```

## Geradores e condições

Por omissão, o QuickCheck gera valores **arbitrários** do tipo pedido: a distribuição e os limites dependem da instância Arbitrary e do parâmetro de tamanho. Quando a propriedade só faz sentido sob uma condição, impõe-na com `==>`:

```haskell
prop_divMod :: Integer -> Integer -> Property
prop_divMod x y = y /= 0 ==> (x `div` y) * y + (x `mod` y) == x
```

Os casos com `y == 0` são descartados e não contam como testes bem-sucedidos. Se a pré-condição for rara, a ferramenta pode desistir sem obter a amostra pedida. Um gerador que constrói entradas válidas evita gastar a maior parte das tentativas em descartes.

Um gerador à medida é uma ação que produz valores com a forma que queres. Para testar que o máximo de um par ordenado é o segundo elemento, gera pares já ordenados:

```haskell
parOrdenado :: Gen (Int, Int)
parOrdenado = do
  x <- arbitrary
  y <- arbitrary
  return (min x y, max x y)

prop_maxDireita :: Property
prop_maxDireita = forAll parOrdenado $ \(x, y) -> max x y == y
```

Geramos dois inteiros e colocamos o menor primeiro. Todas as tentativas produzem um par válido. O `forAll` usa esses pares para testar a propriedade. `suchThat` é outra possibilidade, mas repete tentativas até satisfazer a condição; uma condição impossível ou muito rara pode impedir a geração de terminar. `forAll` não reduz automaticamente entradas de um gerador próprio. Usa `forAllShrink` e um redutor que preserve a condição quando precisares desse comportamento.

:::tip[De onde vêm as propriedades]
Boas fontes: leis algébricas (`x + 0 == x`), idempotência (`sort (sort xs) == sort xs`), inversas (`reverse (reverse xs) == xs`) e modelos de referência (a tua função dá o mesmo que a versão lenta e óbvia). Começa por escrever o que a função deve conservar ou produzir, incluindo os casos limite.
:::

[^cem]: Os 100 casos são a omissão da ferramenta; podes pedir mais com argumentos de configuração.

## Testar as partes que caracterizam o resultado

A idempotência `sort (sort xs) == sort xs` não caracteriza uma ordenação correta. Uma função que devolve sempre `[]` também satisfaz essa lei. Para conferir um algoritmo de ordenação, testa a ordem, a conservação dos elementos com multiplicidades e, quando tens uma referência independente, a igualdade com o resultado dessa referência.

Uma propriedade de `insert x xs` que pressupõe `xs` ordenada deve gerar listas ordenadas ou formular essa pré-condição, ou seja não escondas uma condição rara atrás de muitas implicações descartadas. Um gerador construtivo, como ordenar a lista antes de testar a inserção, produz entradas válidas mais vezes.

O shrinking procura um contraexemplo menor segundo as reduções disponíveis. Não promete o mínimo global entre todas as entradas possíveis. A ausência de falhas em 100 casos também não é uma demonstração para todas as listas.

## Um contraexemplo que cabe no papel

A lei `reverse (xs ++ ys) == reverse xs ++ reverse ys` é falsa. Com `xs=[1]` e `ys=[2]`, o lado esquerdo é `[2,1]` e o direito `[1,2]`. A lei correta troca a ordem das partes: `reverse (xs ++ ys) == reverse ys ++ reverse xs`. Este exemplo distingue a ordem de concatenação sem depender de acaso ou de um grande conjunto de dados.

Para justificar uma propriedade, identifica ainda o domínio. A igualdade envolvendo `length` pressupõe listas finitas; leis aritméticas em `Int` podem ser afetadas por overflow. Usar `Integer` numa propriedade de aritmética exata evita confundir uma falha matemática com o limite da representação.
