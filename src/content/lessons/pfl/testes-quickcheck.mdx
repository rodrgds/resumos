Um teste de exemplo verifica um caso: `reverse [1,2,3]` dá `[3,2,1]`. Uma **propriedade** afirma uma lei para todos os casos: inverter duas vezes devolve a lista original. O **QuickCheck** testa a propriedade em centenas de casos aleatórios por ti. Em vez de inventares exemplos, inventas leis, e a ferramenta trata de as tentar partir.

## A primeira propriedade

Propriedades são funções que devolvem `Bool`, com tipos concretos para a ferramenta saber o que gerar:

```haskell
import Test.QuickCheck

prop_revRev :: [Int] -> Bool
prop_revRev xs = reverse (reverse xs) == xs
```

No GHCi, com o pacote QuickCheck instalado:

```text
ghci> quickCheck prop_revRev
+++ OK, passed 100 tests.
```

A ferramenta gerou 100 listas aleatórias[^cem], que podem incluir listas vazias, comprimentos distintos, negativos e repetidos e a igualdade valeu em todas. Um teste de exemplo verifica a entrada escolhida. A propriedade permite testar outras entradas automaticamente, mas só os casos gerados foram observados.

## Quando falha: o contraexemplo

Uma propriedade falsa dá um contraexemplo reduzido. Afirma que ordenar é a identidade:

```haskell
import Data.List (sort)

prop_sortId :: [Int] -> Bool
prop_sortId xs = sort xs == xs
```

```text
ghci> quickCheck prop_sortId
*** Failed! Falsifiable (after 3 tests):
[1,0]
```

O QuickCheck responde que a propriedade é falsificável e mostra a testemunha: `[1,0]`, já **reduzida** (shrinking) de um caso aleatório maior para um caso mais pequeno que ainda falha. O número de testes varia de corrida para corrida; a lista curta fora de ordem é o essencial. O fluxo de trabalho é este: escreve a propriedade, vê-a falhar, lê o contraexemplo, corrige a ideia. ## Geradores e condições

Por omissão, o QuickCheck gera valores **arbitrários** do tipo pedido: a distribuição e os limites dependem da instância Arbitrary e do parâmetro de tamanho. Quando a propriedade só faz sentido sob uma condição, impõe-na com `==>`:

```haskell
prop_divMod :: Integer -> Integer -> Property
prop_divMod x y = y /= 0 ==> (x `div` y) * y + (x `mod` y) == x
```

Os casos com `y == 0` são descartados antes de contar. Se a condição for demasiado rara, a ferramenta avisa que não conseguiu casos suficientes, e aí o remédio é um gerador à medida com `forAll`. Um gerador próprio permite construir entradas válidas em vez de descartar uma grande parte das tentativas.

Um gerador à medida é uma ação que produz valores com a forma que queres. Para testar que o máximo de um par ordenado é o segundo elemento, gera pares já ordenados:

```haskell
parOrdenado :: Gen (Int, Int)
parOrdenado = do
  x <- arbitrary
  y <- arbitrary `suchThat` (>= x)
  return (x, y)

prop_maxDireita :: Property
prop_maxDireita = forAll parOrdenado $ \(x, y) -> max x y == y
```

O `suchThat` filtra os valores gerados até um `y` maior ou igual a `x`; o `forAll` corre a propriedade só nesses pares. Como `x <= y` por construção, `max x y` vale sempre `y` e a propriedade passa.

:::tip[De onde vêm as propriedades]
Boas fontes: leis algébricas (`x + 0 == x`), idempotência (`sort (sort xs) == sort xs`), inversas (`reverse (reverse xs) == xs`) e modelos de referência (a tua função dá o mesmo que a versão lenta e óbvia). Se não consegues enunciar nenhuma lei sobre a função, é sinal de que ainda não percebeste o que ela promete.
:::

[^cem]: Os 100 casos são a omissão da ferramenta; podes pedir mais com argumentos de configuração. Detalhes na [documentação do QuickCheck no Hackage](https://hackage.haskell.org/package/QuickCheck).

## Testar as partes que caracterizam o resultado

A idempotência `sort (sort xs) == sort xs` não caracteriza uma ordenação correta. Uma função que devolve sempre `[]` também satisfaz essa lei. Para conferir um algoritmo de ordenação, testa a ordem, a conservação dos elementos com multiplicidades e, quando tens uma referência independente, a igualdade com o resultado dessa referência.

Uma propriedade de `insert x xs` que pressupõe `xs` ordenada deve gerar listas ordenadas ou formular essa pré-condição. Não escondas uma condição rara atrás de muitas implicações descartadas. Um gerador construtivo, como ordenar a lista antes de testar uma propriedade que só compara a inserção, produz entradas válidas mais vezes.

O shrinking procura um contraexemplo menor segundo as reduções disponíveis. Não promete o mínimo global entre todas as entradas possíveis. A ausência de falhas em 100 casos também não é uma demonstração para todas as listas.

## Um contraexemplo que cabe no papel

A lei `reverse (xs ++ ys) == reverse xs ++ reverse ys` é falsa. Com `xs=[1]` e `ys=[2]`, o lado esquerdo é `[2,1]` e o direito `[1,2]`. A lei correta troca a ordem das partes: `reverse (xs ++ ys) == reverse ys ++ reverse xs`. Este exemplo distingue a ordem de concatenação sem depender de acaso ou de um grande conjunto de dados.

Para justificar uma propriedade, identifica ainda o domínio. A igualdade envolvendo `length` pressupõe listas finitas; leis aritméticas em `Int` podem ser afetadas por overflow. Usar `Integer` numa propriedade de aritmética exata evita confundir uma falha matemática com o limite da representação.
