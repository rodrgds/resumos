Os tipos predefinidos chegam para exercícios pequenos. Para modelar os teus próprios dados, defines **tipos algébricos** com `data`: enumeras os construtores e o que cada um guarda, ou seja depois as funções escolhem a equação pelo **padrão** do construtor, e a recursão segue a forma dos dados.

## data e padrões

Uma árvore binária ou está vazia ou é um nó com um valor e duas subárvores. A definição é quase essa frase:

```haskell
data Arvore a = Vazia | No a (Arvore a) (Arvore a)
```

`Vazia` é um construtor sem argumentos e `No` guarda um valor e duas árvores. Funções sobre a árvore têm uma equação por construtor:

```haskell
emOrdem :: Arvore a -> [a]
emOrdem Vazia = []
emOrdem (No x esq dir) = emOrdem esq ++ [x] ++ emOrdem dir
```

O padrão `(No x esq dir)` desmonta o nó e dá nome às peças. A travessia em ordem lista a esquerda, depois o valor, depois a direita. O caso base `Vazia` devolve a lista vazia, e é ele que termina a recursão, como o `[]` nas listas da [primeira página](/cadeiras/pfl/haskell-expressoes-tipos/).

## Exemplo completo: pesquisa binária

Inserir mantém a invariância: valores menores à esquerda, maiores ou iguais à direita. Procurar desce só para o lado certo:

```haskell
inserir :: Ord a => a -> Arvore a -> Arvore a
inserir x Vazia = No x Vazia Vazia
inserir x (No y esq dir)
  | x < y     = No y (inserir x esq) dir
  | otherwise = No y esq (inserir x dir)

procura :: Ord a => a -> Arvore a -> Bool
procura _ Vazia = False
procura x (No y esq dir)
  | x == y    = True
  | x < y     = procura x esq
  | otherwise = procura x dir
```

Constrói a árvore inserindo `3, 1, 4, 1, 5` por ordem em `Vazia`. O `3` abre a raiz. O `1` vai para a esquerda. O `4` vai para a direita. O segundo `1` é igual, por isso cai no `otherwise` e vai para a direita do primeiro `1`. O `5` vai para a direita do `4`.

A travessia em ordem devolve `[1,1,3,4,5]`: a invariância garante que a travessia sai ordenada, incluindo o duplicado.

Agora `procura 4`: compara com `3`, desce à direita, compara com `4`, encontra, `True`. E `procura 2`: compara com `3`, desce à esquerda, compara com o primeiro `1`, desce à direita, compara com o segundo `1`, volta a descer à direita e encontra `Vazia`: `False`. Cada comparação escolhe uma subárvore, por isso o número de comparações depende da altura da árvore[^metade].

## Quando a resposta pode faltar

A média das aprovações falhava na lista vazia por dividir por zero. O tipo que declara "valor ou ausência" é o `Maybe`:

```haskell
mediaSegura :: [Double] -> Maybe Double
mediaSegura [] = Nothing
mediaSegura xs = Just (sum xs / fromIntegral (length xs))
```

`Nothing` é a ausência e `Just` embrulha o valor presente, ou seja `mediaSegura []` dá `Nothing` e `mediaSegura [8.0,12.0]` dá `Just 10.0`. O tipo declara os dois casos, que quem chama a função deve tratar com padrões. O compilador pode avisar se falta um caso, mas ainda permite funções parciais; usar `Maybe` não obriga, por si só, a escrever esse tratamento.

[^metade]: A promessa vale quando a árvore está equilibrada: a altura cresce com o logaritmo do número de nós. Uma árvore equilibrada não precisa de ter metades exatamente iguais. Numa árvore degenerada em lista, a procura degrada-se para linear. Estruturas como `Data.Set` mantêm o equilíbrio; a função `inserir` desta página não o faz.

:::tip[Desenha antes de codificar]
Perante um tipo novo, escreve primeiro um valor concreto à mão, como o `No 3 ...` acima, e só depois as equações. Identifica em cada nó o construtor, o valor e as subárvores. Cada equação desmonta uma dessas formas.
:::

## Construtores, sinónimos e recursão estrutural

`type Ponto = (Double,Double)` dá outro nome a um tipo existente. `data Forma = Circulo Double | Retangulo Double Double` cria um tipo novo com duas alternativas. Uma função `area :: Forma -> Double` precisa de considerar cada construtor: `area (Circulo r) = pi*r*r` e `area (Retangulo a b) = a*b`. A validade de dimensões positivas continua a ser uma condição separada.

O nome do tipo aparece nas assinaturas; o nome do construtor aparece nos valores e padrões. Em `data Arvore a = Vazia | No a (Arvore a) (Arvore a)`, `No` tem tipo `a -> Arvore a -> Arvore a -> Arvore a`. A função construtora também pode ser parcialmente aplicada.

O esquema de recursão segue os componentes recursivos. Para contar nós, o caso vazio dá zero e o nó dá `1 + tamanho esq + tamanho dir`. Para altura, com vazio de altura zero, o nó dá `1 + max (altura esq) (altura dir)`. Numa folha, as duas subárvores vazias têm altura zero, dando altura um. Indica a convenção: outra definição pode dar altura menos um à árvore vazia.

## Uma árvore de expressões

```haskell
data Expr = Valor Integer | Soma Expr Expr | Produto Expr Expr
  deriving (Eq, Show)

avaliar :: Expr -> Integer
avaliar (Valor n) = n
avaliar (Soma a b) = avaliar a + avaliar b
avaliar (Produto a b) = avaliar a * avaliar b
```

`Soma (Valor 2) (Produto (Valor 3) (Valor 4))` representa `2+3*4`. Avaliamos as folhas para `2`, `3`, `4`, o produto para `12` e a soma para `14`, porque a precedência já está na estrutura; `avaliar` não decide que operador tem prioridade.

`deriving (Eq,Show)` pede ao compilador implementações baseadas nos construtores e campos. Num tipo parametrizado, comparar duas `Arvore a` requer também `Eq a`. `Maybe` e `Either` são outros tipos algébricos: o primeiro distingue ausência de valor; `Either erro valor` permite ainda explicar por que o cálculo falhou.

## Justificar uma lei por indução

:::details[Demonstração completa]

Para provar `length (map f xs) = length xs` em listas finitas, começa no caso `[]`: os dois comprimentos são zero. No passo `x:xs`, `map` produz `f x : map f xs`, cujo comprimento é `1 + length (map f xs)`. Pela hipótese de indução sobre a cauda, isso é `1 + length xs`, igual ao comprimento original. A hipótese aplica-se à estrutura menor, não à expressão que queremos provar.

:::

Uma propriedade testada em exemplos reforça a confiança, mas não substitui esta prova para todas as listas finitas. A afirmação sobre `length` não pode ser avaliada numa lista infinita.
