  <p>
    {
      'Uma ligação HTTP/1.1 persistente começa com TCP novo, RTT de 50 ms. Pede dois objetos pequenos, um de cada vez, sem pipelining. Ignora DNS, TLS, transmissão e processamento. Quanto demora desde a abertura até receber o segundo objeto, em ms?'
    }
  </p>
  <p slot="hint">{'Conta a abertura de TCP e cada pedido/resposta.'}</p>
  <p slot="hint-more">
    {'A ligação é reutilizada. Há uma abertura e duas trocas pedido/resposta.'}
  </p>
  <p slot="solution">
    {
      '50+50+50=150 ms. Com uma ligação nova para cada objeto seriam 200 ms. A persistência poupa a segunda abertura; não elimina o segundo pedido/resposta.'
    }
  </p>
  <p slot="mistakes">
    {
      'Aplicar 2 RTT a qualquer versão e situação de HTTP sem verificar hipóteses.'
    }
  </p>
</Exercise>

<Exercise
  id="rc-p2p-limite"
  title={'Distribuição ideal entre peers'}
  explanation="/cadeiras/rc/aplicacoes/#cliente-servidor-e-p2p"
  answer={{ kind: 'number', value: 50, tolerance: 0, unit: 's' }}
>
  <p>
    {
      'F=100 Mbit, N=10, us=10 Mbit/s; cada peer upload 1 Mbit/s, download 5 Mbit/s. Qual o limite inferior ideal P2P em segundos?'
    }
  </p>
  <p slot="hint">{'Calcula os três limites e escolhe o máximo.'}</p>
  <p slot="hint-more">{'F/us=10; F/dmin=20; NF/(us+Σui)=1000/20=50.'}</p>
  <p slot="solution">
    {
      'Pelo menos 50 s. Não é garantia de execução: nem toda a capacidade pode ser utilizável instantaneamente.'
    }
  </p>
  <p slot="mistakes">
    {'Somar os três limites ou tratá-los como tempo garantido.'}
  </p>
</Exercise>
