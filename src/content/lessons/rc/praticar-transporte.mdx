<Exercise
  id="rc-tcp-ack"
  title={'Contar bytes após SYN'}
  explanation="/cadeiras/rc/transporte-e-aplicacoes/#sequência-ack-e-abertura"
  answer={{ kind: 'number', value: 801, tolerance: 0 }}
>
  <p>
    {
      'Cliente envia SYN com sequência 500. A abertura termina; cliente envia 300 bytes contíguos. Qual ACK cumulativo do servidor após recebê-los?'
    }
  </p>
  <p slot="hint">{'SYN consome um número.'}</p>
  <p slot="hint-more">{'Primeiro byte 501; os 300 bytes ocupam 501 a 800.'}</p>
  <p slot="solution">
    {
      'ACK 801, próximo byte esperado. O ACK da abertura não consome outro número.'
    }
  </p>
  <p slot="mistakes">
    {'Responder 800 ou acrescentar um número por segmento.'}
  </p>
</Exercise>

<Exercise
  id="rc-tcp-lacuna"
  title={'Confirmar apesar de uma lacuna'}
  explanation="/cadeiras/rc/transporte-e-aplicacoes/#sequência-ack-e-abertura"
  answer={{ kind: 'number', value: 1200, tolerance: 0 }}
>
  <p>
    {
      'Recetor recebeu 1000–1199 e 1400–1599, mas espera 1200–1399. Qual ACK cumulativo?'
    }
  </p>
  <p slot="hint">{'O ACK não ultrapassa a primeira lacuna.'}</p>
  <p slot="hint-more">{'O próximo byte esperado é 1200.'}</p>
  <p slot="solution">
    {
      'ACK1200. SACK pode informar o bloco posterior se negociado, mas o ACK cumulativo continua 1200.'
    }
  </p>
  <p slot="mistakes">{'Responder 1600 porque esse é o maior byte recebido.'}</p>
</Exercise>

<Exercise
  id="rc-tcp-limite"
  title={'Converter janela em débito'}
  explanation="/cadeiras/rc/transporte-e-aplicacoes/#fluxo-e-congestionamento"
  answer={{ kind: 'number', value: 8, tolerance: 0 }}
>
  <p>
    {
      'Janela efetiva 100000 bytes, RTT 0,1 s, ligação 40 Mbit/s. Qual o menor limite ideal em Mbit/s?'
    }
  </p>
  <p slot="hint">{'A janela está em bytes.'}</p>
  <p slot="hint-more">{'8 ×100000/0,1=8000000 bit/s.'}</p>
  <p slot="solution">
    {'8 Mbit/s. A ligação permite 40, mas a janela limita antes.'}
  </p>
  <p slot="mistakes">{'Dar 1 Mbit/spor esquecer multiplicarbytespor 8.'}</p>
</Exercise>

  </p>
