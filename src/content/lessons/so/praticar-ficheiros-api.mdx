<Exercise
  id="so-write-parcial"
  revision={1}
  title="Uma escrita incompleta"
  explanation="/cadeiras/so/ficheiros-api/#ler-e-escrever-todos-os-bytes"
  answer={{
    kind: 'self',
    checklist: [
      'Retomei no endereço buf + 3.',
      'Pedi os cinco bytes restantes.',
      'Conservei a interpretação de erro com sinal.',
    ],
  }}
>
  <div>
    Tens oito bytes em buf. A primeira write devolve 3. Indica o endereço e a
    quantidade da próxima tentativa e explica por que não repetes os oito.
  </div>
  <div slot="hint">A quantidade devolvida conta o prefixo já enviado.</div>
  <div slot="hint-more">
    Não podes reenviar esse prefixo sem duplicar dados.
  </div>
  <div slot="solution">
    A próxima tentativa usa buf + 3 e quantidade 5. Reenviar oito repetiria os
    três primeiros bytes. O retorno usa <code>{'ssize_t'}</code> e deve ser
    testado antes de converter para <code>{'size_t'}</code>, porque -1 significa
    erro.
  </div>
  <div slot="mistakes">
    Assumir que um retorno positivo sempre iguala o pedido, ou converter -1 para
    uma quantidade enorme.
  </div>
</Exercise>

<Exercise
  id="so-caminho-stat"
  revision={1}
  title="Consultar uma entrada de outra pasta"
  explanation="/cadeiras/so/ficheiros-api/#metadados-e-diretórios"
  answer={{
    kind: 'self',
    checklist: [
      'Expliquei que d_name não é o caminho completo.',
      'Resolvi relativamente ao diretório aberto ou juntei o caminho.',
      'Só usei struct stat após sucesso.',
    ],
  }}
>
  <div>
    O diretório de trabalho é /tmp e abriste /home/ana/notas com{' '}
    <code>{'opendir'}</code>.<code>{'readdir'}</code> devolve{' '}
    <code>{'aula.txt'}</code>. Porque pode{' '}
    <code>{'stat("aula.txt", &info)'}</code> falhar apesar de a entrada existir?
  </div>
  <div slot="hint">
    Os dois pedidos podem usar pontos de partida diferentes.
  </div>
  <div slot="hint-more">
    stat com caminho relativo usa o diretório de trabalho.
  </div>
  <div slot="solution">
    stat procuraria /tmp/<code>{'aula.txt'}</code>. Usa o caminho
    /home/ana/notas/<code>{'aula.txt'}</code>, construído com espaço suficiente,
    ou fstatat relativamente ao descritor do diretório aberto. Só lê os campos
    de info se a consulta teve sucesso.
  </div>
  <div slot="mistakes">
    Achar que <code>{'opendir'}</code> muda o diretório de trabalho ou que a
    estrutura já contém dados antes de stat.
  </div>
</Exercise>

<Exercise
  id="so-tail-curto"
  revision={1}
  title="Últimas linhas de um ficheiro curto"
  explanation="/cadeiras/so/ficheiros-api/#linhas-com-getline"
  answer={{ kind: 'number', value: 0, tolerance: 0 }}
>
  <div>
    Um ficheiro tem L=3 linhas e queres as últimas k=5. Contando índices desde
    zero, em que índice começa a impressão no algoritmo de duas passagens?
  </div>
  <div slot="hint">Não pode começar antes da primeira linha.</div>
  <div slot="hint-more">Usa max(0, L-k).</div>
  <div slot="solution">
    Começa em 0: max(0, 3-5)=0. Imprime todas as três linhas e não inventa cinco
    leituras bem-sucedidas.
  </div>
  <div slot="mistakes">
    Usar um índice negativo ou voltar a imprimir o ficheiro inteiro em cada
    iteração.
  </div>
</Exercise>
