  </div>

    As duas tarefas usam os mesmos recursos em ordens opostas.
  </div>

    por outra thread.
  </div>

  <div>
    Há três unidades de um recurso. A e B têm uma cada e declaram máximo de três
    cada. A unidade livre basta para provar segurança?
  </div>
  <div slot="hint">Calcula Max menos Allocation para ambos.</div>
  <div slot="hint-more">

  </div>
  <div slot="solution">

    possibilidade de libertação.
  </div>

<Exercise
  id="so-banqueiro-vetores"
  revision={1}
  title="Uma disponibilidade que não basta"
  explanation="/cadeiras/so/impasses/#seguro-não-significa-livre-de-espera"
  answer={{kind: 'self', checklist: [
    'Calculei Need como Max menos Allocation em cada componente.',
    'Encontrei a sequência segura P0, P2, P1 no estado inicial.',
    'Rejeitei o pedido de P2 por deixar todos sem conclusão garantida.',
  ]}}
>
  <div>

Existem três unidades de X e três de Y. A disponibilidade atual é `(1,1)`. As linhas seguintes indicam os recursos já atribuídos e o máximo total de cada processo.

| Processo | Allocation (X,Y) | Max (X,Y) |
| -------- | ---------------- | --------- |
| P0       | (1,0)            | (2,1)     |
| P1       | (1,1)            | (1,3)     |
| P2       | (0,1)            | (2,2)     |

Mostra uma sequência segura. Depois P2 pede `(1,0)`: o pedido respeita a sua necessidade e a disponibilidade. O banqueiro deve concedê-lo?

  </div>
  <div slot="hint">Não compares apenas a soma dos recursos: cada tipo precisa de unidades próprias.</div>
  <div slot="hint-more">Antes do pedido, P0 precisa de `(1,1)`. Se concederes a unidade de X a P2, Work começa em `(0,1)`.</div>
  <div slot="solution">

As necessidades iniciais são P0 `(1,1)`, P1 `(0,2)` e P2 `(2,1)`. Começamos com Work `(1,1)`. P0 conclui e devolve Allocation `(1,0)`, deixando Work `(2,1)`. P2 pode concluir e devolver `(0,1)`, deixando `(2,2)`. P1 conclui e devolve `(1,1)`, deixando `(3,3)`.

Se concedermos o pedido, Work fica `(0,1)` e Need de P2 fica `(1,1)`. Nenhuma necessidade cabe em Work: P0 e P2 precisam de X e P1 precisa de duas unidades de Y. O estado seria inseguro, por isso o banqueiro adia o pedido. Isto não prova que os três já estejam em impasse.

  </div>
  <div slot="mistakes">Somar Max a Work quando um processo conclui, ou admitir um pedido apenas porque cabe na disponibilidade atual.</div>
</Exercise>

<Exercise

  title="Um ciclo que não prova impasse"

    options: [

        correct: true,
        explanation:
          'Com múltiplas instâncias, um ciclo pode coexistir com uma conclusão possível.',
      },
      {
        text: 'Há sempre impasse quando o grafo tem um ciclo',
        correct: false,
        explanation: 'Essa prova só vale com uma instância por recurso.',
      },
      {

        correct: false,
        explanation:
          'Inseguro significa ausência de garantia, não bloqueio atual.',
      },
    ],
  }}
>
  <div>
    Dois discos iguais formam um ciclo de espera entre A e B, mas existe uma
    segunda unidade livre que permite a um deles concluir. Há impasse provado?
    Este aprofundamento é um complemento: responde apenas quando o enunciado
    pedir análise com múltiplas instâncias.
  </div>
  <div slot="hint">Conta as instâncias livres de cada recurso.</div>
  <div slot="hint-more">
    Uma conclusão liberta recursos e pode desfazer o ciclo.
  </div>
  <div slot="solution">
    Não há prova de impasse: um dos processos pode obter a unidade livre,
    concluir e libertar os seus recursos. Com uma instância por recurso, o mesmo
    ciclo provaria impasse.
  </div>
  <div slot="mistakes">
    Concluir impasse a partir de qualquer ciclo, sem verificar as instâncias.
  </div>
</Exercise>
