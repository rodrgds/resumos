## Forma e prioridade

Uma **max-heap binária** representa uma fila de prioridade com dois invariantes:

- Árvore completa, guardada por níveis num vetor sem buracos.
- Cada pai tem valor `>=` aos filhos. A raiz é máxima; o vetor não precisa de estar ordenado nem respeita a ordem de uma BST.

Com índices a partir de zero, filhos de `i` são `2*i+1` e `2*i+2`, se existirem; pai de `i>0` é `(i-1)/2`. Altura $\lfloor\log_2 n\rfloor$ para `n>0`.

## Inserção, retirada e construção

1. **Inserir:** acrescenta no fim; sobe trocando com o pai enquanto for maior.
2. **Retirar máximo:** guarda a raiz, substitui-a pelo último, reduz tamanho e desce trocando com o **maior filho** enquanto este for maior. Só o nó atual pode violar a ordem.

Consultar custa $O(1)$; inserir/retirar custam $O(\log(n+1))$. Empates não exigem troca; o vazio não tem raiz.

Para construir, desce em cada pai, do último até à raiz. Os filhos já são heaps quando o pai é tratado.

Construir custa $\Theta(n)$: $O(n\sum_{h\ge1}h/2^h)=O(n)$. Inserir um a um pode custar $O(n\log n)$.

## Heapsort e biblioteca

- Constrói max-heap, troca raiz com o fim ativo, reduz a heap e desce. O prefixo é heap e o sufixo contém os maiores elementos já ordenados.
- Heapsort iterativo custa $O(n\log n)$ no pior caso, com auxiliar $O(1)$ sobre o vetor; não é estável.
- `pop_heap` move o extremo para o fim, **sem reduzir o container**. Retira o último depois, quando esse for o objetivo.
- `priority_queue<int>` é max-heap; `priority_queue<int,vector<int>,greater<int>>` é min-heap, usando os nomes com `std::`.
- `top()` exige não vazio e `pop()` não devolve o valor. Define desempate se precisares de ordem previsível; prioridade igual não garante FIFO.

## Top-k e cordas

Para conservar os `k` maiores de um fluxo, mantém **min-heap de tamanho no máximo `k`**. Quando cheia, a raiz é o menor conservado: descarta valores que não a excedam; os restantes substituem-na. Tempo $O(n\log(k+1))$, espaço $O(k)$. Com `k=0`, a resposta é vazia, sem consulta à raiz.

Para juntar cordas, retira as duas menores, paga a soma e reinsere-a. Em `[4,3,2,6]`, paga `2+3=5`, depois `4+5=9`, depois `6+9=15`: custo total **29**, diferente do comprimento final 15.

Pesquisar chave arbitrária pode custar $O(n)$. Alterar prioridade exige subir ou descer.
