## Cliente, servidor e DOM

HTML dá estrutura e significado ao conteúdo. CSS define a apresentação; JavaScript lê e altera o **DOM**, a árvore de nós construída pelo navegador.

<Mermaid
  source={fluxo}
  alt="O navegador envia um pedido. PHP consulta SQLite no servidor e devolve HTML ao navegador."
/>

PHP executa no servidor e só envia a saída. Alterar o DOM não guarda alterações na base de dados. HTTPS protege o transporte com TLS; DNS permite resolver nomes em endereços IP.

## Documento e semântica

- `<!doctype html>` pede o modo normal; `html lang="pt-PT"` declara a língua.
- `head` contém metadados, `title`, ligações a CSS e scripts. `body` contém o conteúdo.
- `id` deve ser único; `class` pode repetir-se e reunir várias classes. Atributos booleanos valem pela presença: `disabled="false"` também desativa.
- `img`, `input` e `meta` são elementos vazios, sem etiqueta de fecho.

| Elemento             | Função                                                       |
| -------------------- | ------------------------------------------------------------ |
| `main`, `nav`        | Conteúdo principal e navegação                               |
| `article`, `section` | Conteúdo autónomo e secção temática, normalmente com título  |
| `a`, `button`        | Navegar e executar uma ação                                  |
| `ul`, `ol`, `dl`     | Lista sem ordem relevante, sequência e termos com descrições |
| `strong`, `em`       | Importância e ênfase                                         |
| `div`, `span`        | Agrupamento sem significado adicional                        |

Respeita a hierarquia dos títulos. Uma imagem informativa precisa de `alt` significativo; uma decorativa usa `alt=""`. Uma `label` identifica o campo, enquanto `placeholder` apenas sugere texto.

O HTML inválido pode produzir outro DOM: um `div` dentro de `p` fecha implicitamente o parágrafo. Usa o inspetor para observar a árvore real.

## Caminhos e tabelas

- `/livros/` começa na raiz do sítio; `capa.png` resolve relativamente ao documento; `../` sobe um nível.
- A partir de `https://catalogo.example/ano/lista.html`, `../livros/item.html?id=8#reserva` resolve para `/livros/item.html?id=8#reserva`. O pedido envia caminho e query, sem o fragmento `#reserva`.
- `table` representa dados; `caption` descreve o conjunto, `tr` cria linhas, `th` cabeçalhos e `td` células. `scope="col"` ou `scope="row"` identifica a associação.
- `rowspan="2"` ocupa a mesma coluna em duas linhas; `colspan="2"` ocupa duas colunas na mesma linha. Não acrescentes outra célula numa posição já ocupada.

## Formulários

`action` define o destino e `method` o método. **GET** coloca parâmetros na query e serve pesquisas; **POST** envia-os habitualmente no corpo. POST não cifra dados.

```html
<label for="nome">Nome</label> <input id="nome" name="pessoa" value="Ana" />
```

O `id` associa a etiqueta; o `name` identifica o parâmetro enviado, aqui `pessoa=Ana`.

| Controlo                    | Envio                                                   |
| --------------------------- | ------------------------------------------------------- |
| Sem `name` ou `disabled`    | Não envia                                               |
| `readonly`                  | Continua a enviar                                       |
| Checkbox não marcada        | Não envia, nem sequer `false`                           |
| Checkbox marcada            | Envia `value`, ou normalmente `on` se o atributo faltar |
| Radios com o mesmo nome     | Envia apenas o selecionado                              |
| Botão de submissão acionado | Pode enviar o próprio par `name`/`value`                |
| `select multiple`           | Pode enviar vários valores com o mesmo nome             |

`textarea` tem o valor inicial entre etiquetas. `datalist` sugere, mas admite outro valor; `select` limita às opções. Num formulário, usa `type="button"` quando o botão não deve submeter. Uploads exigem POST e `enctype="multipart/form-data"`.

`required`, limites e `pattern` ajudam antes do envio. O servidor volta a validar tipos, limites e permissões: `hidden`, `password` e validação do navegador não tornam a entrada fiável.
