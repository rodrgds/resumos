## O essencial

- HTML descreve estrutura e significado; CSS trata da apresentação.
- O navegador constrói o **DOM**, uma árvore de nós em memória. JavaScript lê e altera essa árvore, não o ficheiro original.
- PHP corre no servidor e envia só a saída. Mudar o DOM não guarda nada na base de dados.

## Documento

- `<!doctype html>` pede o modo normal; `lang="pt-PT"` declara a língua.
- `head` guarda metadados e título do separador; `body` guarda o conteúdo.
- `id` é único no documento; `class` pode repetir-se e acumular. `disabled="false"` continua a desativar: booleanos valem pela presença.
- `img`, `input`, `meta`: elementos vazios, sem fecho.

| Para isto                      | Usa isto             |
| ------------------------------ | -------------------- |
| Conteúdo principal, navegação  | `main`, `nav`        |
| Peça autónoma, secção temática | `article`, `section` |
| Navegar, agir                  | `a`, `button`        |
| Lista solta, passos, termos    | `ul`, `ol`, `dl`     |
| Importância, ênfase            | `strong`, `em`       |
| Agrupar sem significado        | `div`, `span`        |

- Títulos seguem a hierarquia do conteúdo, não o tamanho da letra.
- Imagem informativa: `alt` com a informação. Decorativa: `alt=""`.
- `placeholder` sugere; não substitui `label`. `div` dentro de `p` fecha o parágrafo implicitamente: confirma no inspetor.

## Caminhos e tabelas

- `../` sobe um nível do caminho; o fragmento `#id` nunca viaja no pedido HTTP.
- Tabela de dados: `caption`, `th` com `scope`, `rowspan`/`colspan` ocupam posições que não se voltam a preencher. Grelha de página faz-se com CSS.

## Formulários: o que viaja

`action` dá o destino, `method` o método. GET põe parâmetros na query (pesquisas); POST põe-nos habitualmente no corpo. POST não cifra.

| Controlo                     | Viaja?                     |
| ---------------------------- | -------------------------- |
| Com `name`, ativo            | Sim, como `name=valor`     |
| Sem `name`, ou `disabled`    | Não                        |
| `readonly`                   | Sim, nos tipos compatíveis |
| Checkbox por marcar          | Não, nem `false`           |
| Checkbox marcada sem `value` | Sim, normalmente `on`      |
| Radios com o mesmo `name`    | Só o selecionado           |
| Botão de submissão usado     | Pode enviar o seu par      |
| `select multiple`            | Vários valores, mesmo nome |

- `id` serve a `label` (`for`); `name` serve o pedido. São funções distintas.
- `datalist` sugere e admite outro valor; `select` limita às opções.
- `type="password"` só oculta caracteres; `type="hidden"` continua editável pelo cliente. Upload exige POST com `multipart/form-data`.
- Validação do navegador ajuda o utilizador; o servidor valida tudo de novo: presença, tipo, limites e permissões.
